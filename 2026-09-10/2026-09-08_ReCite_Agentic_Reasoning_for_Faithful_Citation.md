## 2. 论文要解决的核心问题

- **要解决什么问题**：学术写作中的自动引用推荐（ACR）。场景是"通用 Agent / 学术写作"，不属于 GUI 落地，而是 Agent 方法论域。
- **为什么重要**：文献体量爆炸使人工定位引用越来越难，LLM 大量代写学术文本后，引用幻觉成为"质量守门员"级隐患。作者把引用幻觉切成两类——**捏造**（引不存在的论文，RAG 已基本解决）与**错配/张冠李戴**（引的是真论文，但逻辑上不支持作者主张）。错配是当前真正开放的核心难题。
- **现有方法有什么不足**：现有系统把引用当**相似度检索**，但"主题相关"不等于"逻辑支撑"——语义检索器（如 SPECTER）会给"Transformer 在 NLP 成功"的主张推一篇视觉 Transformer 论文（文本重叠高，逻辑错配），而正确支柱应是《Attention Is All You Need》；且现有系统是**单向流水线**，一次检索失误即成不可逆错误，无自我纠正机会。NLI / 定理证明式的后置过滤只能"打标签"，无法纠正在生成流程里已传播的错误。现有多数引用数据集只做"上下文→目标论文"的静态映射，缺推理轨迹。
- **Research Gap**：作者 claim 自己补上的是——把引用从"检索任务"重定义为"推理任务"，并首个给出**闭环主张—证据校验框架**：意图感知检索 + 主张级证据校验 + 可纠错的反思式再检索，三者同时到位。

## 3. 方法核心思想（三层拆解）

### 3.1 一句话概括方法

用一个 observe-think-act 的解耦 Agent，把引用流程拆成"定位→规划→校验→反思"的迭代闭环，底座 Qwen3-4B，关键模块用 GRPO 强化。

### 3.2 方法总览（Pipeline）

- **输入**：一段被剥掉全部引用标记的未引用草稿段落；**输出**：带忠实引用及文献映射的完整段落。
- **三个解耦模块**：① **CiteLocator**（逻辑断点感知）——把"哪里该引"形式化为序列恢复任务，在每个合法位置预测统一 `[#CITE#]` 标记并标注必要性（Mandatory/Optional）；② **QueryPlanner**（意图感知查询规划）——为每个引用位置生成"推理链 + 关键词组"，弥合模糊局部语境与目标文献精确元数据间的词汇鸿沟；③ **Master Brain**（任务编排与反思校验）——中央调度器，调用前两者、查询 Semantic Scholar API 取候选元数据，校验证据是否支持局部主张。
- **连接（控制流）**：Master Brain 先调 CiteLocator 找所有位置 → 对每个位置调 QueryPlanner 生成关键词 → 检索 → 校验；**若无候选提供一致证据**，进入反思式再检索循环（产出失败归因 `<think>`，把关键词从宽泛领域细化为具体实体，发起二次检索）。因查询只打真实数据库，捏造被构造性消除。

### 3.3 真正的创新点（去伪存真）

- **真·方法创新**：① 引用定位的非对称交叉熵——因引用标记极稀疏、标准 CE 会塌缩到多数类，对标记 token 加大损失权重；② 闭环反思式再检索（首次把"纠错"放进流程内部，而非后置过滤）；③ CAP-8 八类引用意图分类体系（BG/MG/CMP/BS/MTD/VLD/EV/CRT）。
- **工程组合**：observe-think-act、GRPO、Semantic Scholar 检索、SFT 都是已有组件，本文的贡献在于把它们**按任务语义解耦**并各自配齐监督信号。
- **对性能提升最关键的设计**：ablation 显示 CiteLocator 是根基（去掉后 Strict F1 从 37.47 崩到 2.75），QueryPlanner 次之（降到 15.77）；Master Brain 的反思校验主要作用于 Lenient 指标。
- **证据不足 / 仅声称有效**：CAP-8 的"细粒度意图监督提升候选校验"仅有端到端增益佐证，未见对 CAP-8 本身的独立消融；"大模型基线受益于数据泄漏"是作者的单向推断，未做定量剥离。

## 4. 具体技术细节

### 4.1 模型结构

- **Base model**：Qwen3-4B-Instruct（纯文本 LLM，**非 MLLM、无视觉编码器**），三个模块同源同参（4B），均需微调。
- **CiteLocator**：把 `[#CITE#]` 注册为新 tokenizer 条目避免切分，SFT 训练，用非对称交叉熵加重标记 token 损失。
- **QueryPlanner**：先 SFT，再用 **GRPO** 激发更深推理——每个查询采样 G=4 个候选，用组内相对优势更新（无需价值网络），复合奖励 = 格式合规 + 实体召回 + 意图对齐。
- **Master Brain**：SFT 训练，遵循 observe-think-act 状态机。

### 4.2 训练流程

| 阶段 | 目标 | 训练什么能力 | 数据来源 | 数据形态 | 训练目标 / Loss |
|---|---|---|---|---|---|
| Stage 1 (CiteLocator) | 引用位置感知 | 定位断点 + 必要性标注 | arXiv 10,893 个 LaTeX 源码（2024–2025 ACL/EMNLP/CVPR/ICCV/NeurIPS） | 31,118 条（28,006/3,112），剥标记段落→`[#CITE#]`+Mandatory/Optional | SFT + 非对称交叉熵 |
| Stage 2 (QueryPlanner) | 意图推理 + 关键词生成 | 弥合词汇鸿沟 | 7,079 条高密度段落（6,779/300），DeepSeek-V3 后验反推推理链与最优关键词 | `<reasoning>`+`<keywords>` | SFT → GRPO（G=4，复合奖励） |
| Stage 3 (Master Brain) | 编排 + 反思纠错 | 多轮闭环轨迹 | 2,000 条轨迹（500 gold + 1,500 反思增强，DeepSeek-V3 补 `<think>`） | observe-think-act 多轮 | SFT |

> SFT 统一用 8-bit Paged AdamW（lr=2×10⁻⁵，3 epochs，cosine decay，5% warmup）；序列长度 CiteLocator 1024 / QueryPlanner 4096 / Master Brain 9216；GRPO lr=5×10⁻⁷。

### 4.3 推理流程

**多步推理**（循环机制为"规划-执行-反思"）：Master Brain 先定位全部引用位，逐位"生成关键词→检索 Semantic Scholar→校验证据是否支撑局部主张"，失败则进入反思再检索循环，直至找到一致证据或穷尽重试。无显式价值网络，靠 GRPO 的组内相对优势。

## 5. Benchmark 与实验设置

### 5.1 Benchmark 一览表

| Benchmark/数据集 | 场景 | 任务类型 | 数据规模 | 输入格式 | 输出格式 | 评测指标 |
|---|---|---|---|---|---|---|
| CiteLocator 定位集（自建） | 学术写作（CS） | 引用位置预测 | 31,118（28,006 训练/3,112 测试） | 剥引用标记的段落 | `[#CITE#]`+必要性标签 | P/R/F1（Mandatory/Optional） |
| QueryPlanner 规划集（自建） | 学术写作 | 意图推理+关键词生成 | 7,079（6,779/300） | 段落+引用位置 | `<reasoning>`+`<keywords>` | R-F1/K-F1/K-TR/K-PR/K-Jac/LLM-judge |
| 反思轨迹集（自建） | 学术写作 | 多轮编排纠错 | 2,000（500 gold+1,500 反思） | observe 状态 | think/act | 端到端 F1 |
| 端到端测试集（自建） | 学术写作 | 端到端引用预测 | 200 段/1,023 篇文献（50×4，严格不重叠训练池） | 未引用段落 | 完整引用+文献映射 | Strict/Lenient/Position-Only F1 |
| BUSCALDI（域外） | 学术写作 | 定位（粗/细粒度） | 133 句（3 名资深研究者标注） | 句子 | 引用位置 | P/R/F1 |

### 5.2 实验结果分析

- **主结果**（端到端，200 段）：ReCite-SFT(CAP-8) **Strict F1=39.15%**（P 39.22/R 39.07）、**Lenient F1=55.14%**、Position-Only F1=89.71%，超过全部基线（含 DeepSeek-V4-Pro 1.6T 的 31.77、DeepSeek-V4-Flash 284B 的 33.10、Qwen3.6-Plus 的 31.34）。ReCite-SFT 为 37.47%，ReCite-Base 为 36.33%。通用 Agent（Claude Code 21.49、Hermes Agent 21.80、OpenClaw 10.12）明显落后，说明黑箱端到端 Agent 无法从检索漂移中恢复。
- **模块级**：CiteLocator Overall F1=**66.37%**（P 74.16/R 60.06），远超次优 Qwen3.5-27B 的 48.04%；域外 BUSCALDI 细粒度定位 F1=52.8，优于带启发式的 GM-s2orc-H（50.0）。QueryPlanner 仅 SFT 即 R-F1=56.12%，逼近 DeepSeek-V3(671B) 的 58.63%；加 GRPO 后 R-F1=57.81，多数关键词指标继续提升。
- **Ablation 说明**：替换 CiteLocator → Strict F1 崩至 **2.75%（−34.72）**，证明定位是根基；去掉 QueryPlanner → 15.77%（−21.70），证明意图感知查询不可或缺；去掉 Master Brain 反思校验 → Strict 仅 −1.14（36.33），但 **Lenient 从 47.10 降到 42.76（−4.34）**，说明其价值主要在"过滤噪声/发现替代文献"。**其它分析**：检索候选数 k 从 4 增至 12 时在 k=8 达拐点，之后受上下文噪声限制，故固定 k=8；跨会议（CVPR/ICCV/EMNLP/NeurIPS）表现均衡，提示学到的是领域通用的修辞信号而非表层词汇重叠。

## 6. 亮点与贡献（Why it matters）

- **问题重构有价值**：把引用幻觉清晰切分为捏造/错配两类，论证 RAG 时代错配才是真瓶颈，推动子领域问题定义。
- **闭环校验是真正差异点**：NLI/定理证明式后置过滤无法纠正已传播的错误，ReCite 把"纠错"放进流程内部，是首个闭环主张—证据校验框架。
- **4B 小模型打败 1.6T 超大模型**：任务专用的解耦设计比通用大模型更可靠，对成本敏感、需离线部署的场景很有说服力（作者明确以量化/剪枝、本地离线、规避未发表数据外泄为动机）。
- **数据集与方法体系可复用**：位置感知、意图推理、反思轨迹三类监督 + CAP-8 分类，是可迁移的方法论资产。

## 7. 局限与可改进点（个人点评）

- **绝对精度仍偏低**：Strict F1=39.15% 意味着严格匹配下约六成错误。作者辩称严格匹配要求跨阶段完美联合正确、且受作者主观偏好影响——但这恰说明引用任务里"唯一正确答案"假设本身不稳，Lenient 与 Strict 之间 15.99 个百分点的巨大落差即证据。
- **评测窄且单模态**：仅覆盖 CS 论文，人文/生物医学等跨学科泛化未验证，数据时效窗口窄（2024–2025）；只处理文本，无法利用图表、伪代码等常被引用的证据形态（作者也承认需引入 VLM）。
- **模块级与端到端存在落差**：CiteLocator 定位 F1 66%、QueryPlanner 关键词 K-F1≈39%（推理 R-F1 才 56%），端到端串联会累积放大误差，论文对级联误差的定量归因不足；反思轮数分布与额外 token 开销报告不充分。
- **对比公平性存疑**：一边说大模型可能数据泄漏、一边用这些数字宣称超越，论证方向是双向的；同样无法排除 ReCite 受益于同分布训练语料。GRPO 增益本身较小（R-F1 仅 +1.69），"深层实体接地"的定性主张缺少更硬指标。

## 8. 对我们的启示 / 可借鉴点

- **"检索到≠用得上"是通用规律**：任何依赖外部知识的 Agent 都应区分"找到相关内容"与"内容真正支撑当前决策"，把校验做成显式模块而非隐式期望。
- **闭环 > 单向**：给流程加"失败归因→改写查询→重试"的反思环能显著提升鲁棒性；本文进一步证明在专用任务上做**解耦、可分别训练**的反思模块更有效。
- **细粒度监督信号关键**：位置必要性（Mandatory/Optional）与意图类别（CAP-8）这类额外标签明显提升下游判断质量，提示构造数据时应主动标注结构性信号。
- **非对称损失 + 专用小模型**：引用标记极稀疏、标准 CE 塌缩，该技巧可迁移到任何"长文本中定位稀疏关键元素"的任务；把简单子任务交给小模型、复杂决策交给被训练的核心模块，是可复制的工程范式。

**对 GUI Agent 的可借鉴点**（本篇为 Agent 方法论域，非 GUI 落地，故单列）：最值得迁移的是**"证据链 + 反思校验"闭环用于 GUI 操作的可解释性与自我纠错**。① CiteLocator 的"逻辑断点感知"可类比为在 GUI 轨迹中识别"哪一步操作需要外部依据"（某按钮语义、某字段合法取值），把关键决策点显式标出；② Master Brain 的"主张—证据一致性校验"可直接用于 GUI 操作证据链：每次点击/输入前校验当前观察（截图元素、DOM、历史状态）是否真的支持该动作意图，抑制"看起来像但其实不对"的误点——这与"相似度 92% 但逻辑错配"是同一类错误；③ 反思式再检索可类比为 GUI 的反思校验：动作后状态不符预期时产出失败归因、细化观察目标并重试；④ 用小的专用模块做定位与校验、只训练核心编排器，也能降低 GUI Agent 推理成本。边界：GUI 的"证据"是像素与控件树而非论文元数据，实时性要求更高，反思轮数须严格预算。

## 9. 延伸阅读

- **ALCE**（Gao et al., 2023）：标准化引用可靠性评测基准，量化引用质量的开端。
- **ReAct / Reflexion**（Yao et al., 2023; Shinn et al., 2023）：Agent 推理—行动循环与自我反思的经典框架，ReCite 的 observe-think-act 与反思环受其启发。
- **基于 NLI / 定理证明器的引用校验**（Xu et al., 2025; Pei et al., 2025）：静态后置过滤路线，与本文闭环路线形成对照。
- **Step-GRPO**（Li et al., 2026b）：步骤级强化，可作为 QueryPlanner GRPO 组内相对优势思路的延伸。
