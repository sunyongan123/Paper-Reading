# SciFigure2Code: An AI-Reconstructed Benchmark for Scientific Figure-to-Code

## 2. 论文要解决的核心问题

- **要解决什么问题**：给定一张最终发表的科研图板（panel，已后期处理、不暴露原始数据与作者脚本），评测模型能否生成一份可编辑、可执行、视觉保真的 Python 呈现程序（presentation program）。
- **为什么重要**：科研图是研究结论被检验、被复用的"界面"。若能恢复出可编辑绘图程序，研究者 / Agent 就能把同一套设计套到新数据上自动重绘；这卡住了"科研 Agent 读图→改图→重绘"的下游能力。
- **现有方法有什么不足**：ChartMimic（人工精选科学风格/web 图例）、Plot2Code、RealChart2Code（Kaggle 真实数据）要么用精选样本、要么假设能拿到原始数据，都没解决"原始代码不可得时，如何评测从最终图板重建可审计呈现程序"这一缺口。
- **Research Gap**：作者把目标从"恢复源码/数据"（欠定逆问题）改写为**呈现复现（presentation recovery）**——只要求生成的程序保留图板"如何被排布、如何被阅读"的可观测属性（几何、视觉层级、编码、注释、排版），并明确不宣称恢复作者测量值或脚本。

## 3. 方法核心思想（三层拆解）

### 3.1 一句话概括方法

用角色化 Codex 智能体把最终图板"逆向重建"为经执行、视觉精修、审计的银标准 Python 程序，构成可审计参考池，再用"执行门控 + 盲评"评测任意模型做呈现复现的能力。

### 3.2 方法总览（Pipeline）

- **输入**：开放获取 Nature 系论文的全图 + DOI/图注元数据；**输出**：干净参考包（可编辑 Python + PNG/PDF + provenance/审计元数据）+ 337 图测试集 SciFigureBench。
- 中间**四阶段**：
  1. **采集与切分**：抓取生物/环境/地理/材料/物理五领域全图；提案智能体产切图逻辑，审查智能体核验图板字母、坐标轴、刻度、图例、色条、注释是否完整，不合格重切。
  2. **质量过滤**：本地 Qwen 系 VLM 给每图板打清晰度、数据纯度、可复现代码性、美观度、总体分（构建期筛选，非最终评测分）。
  3. **重建与审查**：代码智能体写可执行 Python（必须同出 PNG+PDF），审查智能体逐项比对（图表类型/数据形态/轴/标签/图例/配色/布局/边缘），失败退回重写。
  4. **精修与审计**：精修智能体只在已通过审查的程序上编辑（禁图像操作替换），审计智能体查排版、重叠、科学符号、边缘裁切，筛出干净样本。
- **连接方式**：严格"下游只消费已审查的上游产物"，每步落机器可校验 artifact；合法性约束禁止直接加载/描摹目标图。

### 3.3 真正的创新点（去伪存真）

- **真·方法创新**：提出"呈现复现"新评测目标 + 执行门控（跑不起来/无 PNG 则视觉分全零）+ 盲评裁判信息隔离；用"AI 重建 + 审计的银标准"替代不可得的作者真值。
- **工程组合**：四角色智能体流水线、Qwen 本地 VLM 打分、Codex CLI 编排均为已有组件拼装，本身非新机制。
- **对性能提升最关键的设计**：执行门控把评测单元锚定为"可执行呈现程序"，盲评把布局/组件/图例/清晰度变一等指标——两者共同决定失败原因是否可见。
- **证据不足 / 仅声称有效**：裁判一致性、银标准与受评模型的同源偏差未量化；plan-then-code 与 caption 收益只测少量模型，未做统计检验。

## 4. 具体技术细节

### 4.1 模型结构

无训练模型，三组"模型"角色：① **构建期智能体** = 配置 GPT-5.4 的角色化 Codex CLI（切分/代码/精修/审计）；② **构建期打分器** = 本地 Qwen 系 VLM（只分类与打分，不产参考代码）；③ **盲评裁判** = 本地 Qwen3.6-27B。**受评对象** = 14 个模型（11 个开源 VLM 本地跑 + 3 个 Claude VLM API），全部零样本。

### 4.2 训练流程

—（本工作为基准构建与零样本评测，无模型训练/微调。）

### 4.3 推理流程（评测协议）

- **输入/输出**：输入 = 目标图板（仅图像）或图板 + 图注/内容摘要（合计 ≤1000 字符）；输出 = 自包含 Python 脚本，须从 `import os` 开头、以固定四行 `savefig` 结尾，同产 PNG(200dpi) 与 PDF。
- **单步 vs 多步**：默认单步零样本；额外测两阶段 **plan-then-code**（先出受限重建规划 768 token，再出最终代码 4096 token，规划以 `PLAN_COMPLETE` 标记）。
- **硬门控**：执行失败或无 PNG → 四维视觉分直接置零。
- **盲评**：裁判只收"目标图在前、候选图在后"两张图，不接触模型身份/提示/图注/源码，在 layout / component / legend_colorbar / clarity 四维打 0~100。
- **总分**：`Overall = 1/7(Valid + Visual + Type + Layout + Component + Legend + Clarity)`，三项确定性 + 四项盲评无权重平均。

## 5. Benchmark 与实验设置

### 5.1 Benchmark 一览表

| Benchmark | GUI 场景 | 任务类型 | 数据规模 | 输入格式 | 输出格式 | 评测指标 |
|---|---|---|---|---|---|---|
| SciFigureBench（本文） | General（科研图，非 GUI） | 图→可编辑代码（呈现复现，端到端） | 参考池 6,740；测试 337（31 子类/5 领域/3 复杂度，每领域 67–68、每复杂度 112–113） | 图板 PNG/PDF；仅图像 或 +图注摘要(≤1000 字符) | 可执行 Python（必出 PNG+PDF） | Valid/Visual/Type + 盲评 Layout/Component/Legend/Clarity → Overall(7 项均值) |

领域分配（clean/bench）：环境 3,187/68、地理 2,066/67、生物 651/68、物理 484/67、材料 352/67；复杂度占比 低 27.7% / 中 61.8% / 高 10.5%。

### 5.2 实验结果分析

**主结果**（337 图，零样本）：

- **仅图像**：Claude Opus 4.7 Overall 最高 **83.50**；Opus 4.6 领 Valid **95.25**、Type **67.17**。开源最高 GLM-4.5V **64.76**，Qwen3.5-122B-A10B **64.05** 紧随，仅 8B 的图表专用 CharTide-8B **63.02**，最低 Pixtral-12B **20.15**。
- **图注辅助**：Opus 4.6 最高 **83.57** 且包揽四维盲评；GLM-4.5V **65.77**、CharTide-8B **64.93**；Pixtral-12B 跌至 **7.25**。

**Ablation / 对照**：

- **图注 vs 仅图像**：14 中 8 个 Overall 升、10 个盲评均值升；最大增益 Gemma-4-31B-IT **+7.02**、Ovis2.6-80B-A3B **+5.50**；Molmo-72B **−7.06**、Pixtral-12B **−12.90** 明显倒退 → 图注收益高度依赖后端。
- **plan-then-code**：四模型全涨，Gemma-4-31B-IT **+6.37** 最大、Phi-4 Vision 15B **+1.78** 最小 → 显式规划是通用低成本提升项。
- **复杂度分层**（仅图像，开源 11 模型）：9/11 在高复杂度更低，池化均值 **47.29 → 45.36 → 42.67** 单调下滑；而执行通过率几乎不变（**70.0% vs 70.7%**）→ 高复杂度暴露的是"科学视觉语法复现失败"，而非代码跑不起来。图注辅助下通过率反而 **70.2% → 63.0%**。
- **认类 vs 复现细节**：可执行样本 Type 均值 **70.07** vs 盲评 Component 仅 **45.93**；最弱子类桑基/冲积 28.19、地理图 30.22、森林图 32.39、堆叠柱 32.89、点图 34.63；最强折线 61.78、火山 59.87、ROC 59.51。

## 6. 亮点与贡献（Why it matters）

- **重新定义问题**：把欠定的"恢复源码/数据"改写为可评测的"呈现复现"，方法论干净、可审计。
- **智能体工程范例**：角色化分工 + 每步机器可校验产物 + 下游只消费已审查上游，流水线可迁移到其他数据构建任务。
- **规模与平衡兼备**：6,740 参考包、31 子类 5 领域 3 复杂度、337 严格平衡测试集。
- **执行门控 + 盲评组合**：确定性兜"能不能跑"、不知情 VLM 评"像不像"，避免单一聚合分掩盖失败原因。
- **结论诚实**：明确指出图注收益依赖模型、参数量不决定效率，并用 Pareto 前沿刻画质量—吞吐—规模权衡。

## 7. 局限与可改进点（个人点评）

- **银标准是 AI 生成**：参考程序与被评模型同源（同属前沿 VLM/Codex 生态），存在同源偏差风险，论文未量化裁判一致性。
- **视觉分靠单一 VLM 裁判**（Qwen3.6-27B），未报告其自身稳定性、固定"目标在前候选在后"的位置偏差、多裁判一致性。
- **只测零样本**：无微调/少样本/多轮迭代修正，模型能力上限未探到；图注被压到 1000 字符。
- **未开源**：无代码/数据链接，6,740 参考包获取方式不明，复现门槛高。

## 8. 对我们的启示 / 可借鉴点

（本篇为 Benchmark/评测域，以下均为**对 GUI Agent 的可借鉴点**）

- **"呈现复现 + 执行门控 + 盲评"可迁移到截图→HTML/UI 代码评测**：把"可执行可编辑"当硬门控、盲评打分，比单一相似度更能暴露真实短板。
- **角色化多智能体流水线**（提案—审查—精修—审计 + 失败回退）适合构建 GUI 数据集（如自动标注截图元素）。
- **盲评"信息隔离"设计**（裁判只见目标与候选、不知模型与提示）可有效减少评分偏差。
- **plan-then-code 对四个模型全有效**（最高 +6.37），显式中间推理对结构化输出普遍有帮助，可用于 GUI 动作序列生成。
- **警惕"认对大类但丢细节"**（Type 70 vs Component 46）：对应 GUI 场景"页面大致对但控件层级/交互元素缺失"，须把细粒度组件当一等指标。

## 9. 延伸阅读

- **ChartMimic**：4,800 组人工精选图/指令/代码三元组，图表转代码经典基准。
