## 1. 研究背景与要解决的问题

科研图是论文结论被检验、被复用的"界面"。一张已发表的图板（panel）不只是数据的可视化，而是把坐标轴与刻度、误差与显著性标记、图例、领域专用符号、排版层级全部耦合在一起的**设计产物**。如果能从像素反向恢复出一个可编辑的绘图程序，研究者就能把同一套设计套用到新数据上、自动重绘，而不必手工重画。

难点在于：**最终发表的栅格图是"欠定"的**——它通常经过后期处理，既不暴露原始测量数据，也不暴露作者的绘图脚本。已有图表转代码基准（ChartMimic、Plot2Code、RealChart2Code）要么用人工精选样本，要么假设能拿到原始数据，都没能回答：**当原始代码不可得时，如何评测"从最终发表的图板重建出可审计的呈现程序"？**

本文的立场很清晰：不追求恢复隐藏数据或作者源码，而是定义一个新目标——**呈现复现（presentation recovery）**，即生成的程序必须保留图板"如何被排布、如何被阅读"的可观测属性。

## 2. 核心方法 / 思路

整篇论文的贡献一半在基准构建流程，一半在评测协议。

**（1）AI 重建流水线（四阶段）。** 全部由配置 GPT-5.4 的角色化 Codex CLI 智能体完成：
- **采集与切分**：从开放获取的 Nature 系论文抓取跨生物、环境、地理、材料、物理五领域的全图并记录 DOI、图注；再由提案智能体产出切图逻辑、审查智能体检查图板字母、坐标轴、刻度、图例、色条、注释是否完整，不合格就重切。
- **质量过滤**：用本地 Qwen 系视觉模型给每个图板打清晰度、数据纯度、可复现代码性、美观度、总体分，作为构建期筛选。
- **重建与审查**：代码智能体写出可执行 Python（必须同时输出 PNG 和 PDF），审查智能体把渲染结果与目标图逐项比对（图表类型、数据形态、坐标轴、标签、图例、配色、布局、边缘），不合格退回重写。
- **精修与审计**：精修智能体只在**已通过审查**的一版程序上编辑（禁止用图像操作替换），审计智能体检查排版、标签/刻度/图例重叠、科学符号、边缘裁切等，最后筛出干净样本形成参考池。

**（2）合法性约束。** 提交若直接加载/编辑目标图、或用像素涂画/栅格描摹"造假"，即判无效，保证基准奖励的是"可重建的呈现程序"而非图像复制捷径。

**（3）评测协议。** 两种设定：**仅图像**与**图注辅助**（额外给图注 + 内容摘要，合计上限 1000 字符），均为零样本。执行是硬门控：跑不起来或没产出 PNG，后续所有视觉分直接置零。视觉分由本地 Qwen3.6-27B 作为**盲评裁判**给出——裁判只看到目标图与候选渲染图两张图，不知道模型身份、任务、提示策略、图注和源码，在布局、组件完整性、图例/色条保真、清晰度四个维度打 0~100 分。最终 Overall 是 Valid、Visual、Type 三个确定性分数加四个盲评分的**无权重平均**。

**（4）基准规模。** 产出 **6,740** 个干净参考包，并抽出平衡的 **337 图板**测试集 SciFigureBench，覆盖 31 种图表子类、5 个领域、3 个复杂度等级。

与已有工作的关键差异：对象是"最终发表的图板"，参考标准是"AI 重建 + 智能体审计的银标准程序"而非作者真值，评测的是可执行性 + 可观测呈现，而非数据反演。

## 3. 关键实验结果

在 337 图板测试集上，14 个模型（11 个开源本地跑 + 3 个 Claude API）全部零样本评测。

**总体水平**：仅图像设定下，**Claude Opus 4.7 拿到最高的 Overall 83.50**，Claude Opus 4.6 的 Valid 最高（95.25）与 Type 最高（67.17）。图注辅助设定下，**Claude Opus 4.6 Overall 最高 83.57**，并包揽四个盲评维度。开源模型里 **GLM-4.5V 领先**（64.76 / 65.77），Qwen3.5-122B-A10B 紧随（64.05 / 64.79）；仅 8B 的图表专用模型 CharTide-8B 仍具竞争力（63.02 / 64.93）；最低的 Pixtral-12B 只有 20.15 / 7.25。**开源成绩并非由参数量单独决定**——模型大不代表分高。

**图注与规划的作用**：图注辅助让 14 个模型中的 8 个 Overall 上升、10 个的盲评维度均值上升，最大增益是 Gemma-4-31B-IT 的 +7.02 与 Ovis2.6-80B-A3B 的 +5.50；但 Molmo-72B（−7.06）、Pixtral-12B（−12.90）明显下降，说明图注收益**高度依赖后端**。两阶段"先规划后写码"的提示对四个受测模型**全部有效**，增益从 Phi-4 Vision 15B 的 +1.78 到 Gemma-4-31B-IT 的 +6.37。

**难度分层**：11 个开源模型里 9 个在高复杂度图板上得分更低，池化均值从低到高单调下滑 47.29 → 45.36 → 42.67；而执行通过率几乎不变（70.0% vs 70.7%），说明**高复杂度暴露的是"科学视觉语法"复现失败，而非代码跑不起来**。

**按子类**：可执行输出的 Type 平均分 70.07，而盲评 Component 平均只有 45.93——模型**更擅长认出"这是哪一大类图"，而难以复现具体的科学标记与注释**。最弱的子类是桑基/冲积图（28.19）、地理地图（30.22）、森林图（32.39）、堆叠柱（32.89）、点图（34.63）；较强的折线图、火山图、ROC 曲线分别为 61.78、59.87、59.51。

## 4. 亮点与贡献（Why it matters）

- **重新定义了问题**：把"从最终图板恢复源码/数据"这个欠定难题，改写成可评测的"呈现复现"，并用执行门控 + 盲评把评测锚在可执行程序上，方法论很干净。
- **构建流程本身是智能体工程范例**：角色化（提案/审查/精修/审计）分工 + 每阶段写机器可校验产物 + 下游只消费已审查的上游输出，这套流水线可直接迁移到其他数据构建任务。
- **规模与平衡性兼备**：6,740 参考包覆盖 31 子类 5 领域 3 复杂度，337 测试集按领域与复杂度严格平衡，子类还做了"常见 12 个、稀有穷举"的采样。
- **执行门控 + 盲评的组合设计**：用确定性检查兜住"能不能跑"，用不知情的 VLM 裁判评"像不像"，避免单一聚合分掩盖失败原因。
- **给出了负责任的结论**：明确指出图注收益依赖模型、参数量不决定效率，并用 Pareto 前沿刻画质量—吞吐—规模的权衡。

## 5. 局限与可改进点（个人点评）

- **银标准本身是 AI 生成的**：参考程序由同一批 Codex/GPT-5.4 智能体产出，虽过了审计，但"AI 参考"与"被评模型"之间存在同源偏差风险，论文未做裁判一致性的量化。
- **视觉分全靠单一 VLM 裁判**：所有盲评分来自 Qwen3.6-27B 一个裁判，未报告裁判自身的稳定性、位置偏差（固定"目标图在前、候选图在后"）或与其他裁判的一致性。
- **只评了零样本**：没有微调、少样本、多轮迭代修正等更强设定，"模型能力上限"其实没被探到；图注辅助也被限制在 1000 字符。
- **未开源**：没有代码或数据链接，6,740 个参考包的获取方式不明，复现门槛高。
## 6. 对我们的启示 / 可借鉴点

- **"呈现复现"这套评测思路可迁移到 GUI Grounding / 截图转代码**：把"能否生成可执行、可编辑的产物"作为硬门控，再用盲评打分，比单一相似度指标更能暴露真实短板，适合评测"截图→HTML/UI 代码"。
- **角色化多智能体流水线值得复用**：提案—审查—精修—审计四角色分工、每步落机器可校验产物、审查失败自动回退，这套模式在构建 GUI 数据集（如自动标注截图元素）时同样适用。
- **盲评裁判的"信息隔离"设计**：裁判只看到目标与候选两张图、不接触模型身份与提示策略，能有效减少评分偏差；做 GUI Agent 评测时可借鉴。
- **两阶段"先规划后生成"是低成本提升项**：plan-then-code 对四个模型全部有效（最高 +6.37），说明显式中间推理对结构化输出普遍有帮助，可用于 GUI 动作序列生成。
- **警惕"认对大类但丢细节"的失败模式**：Type 70 vs Component 46 的落差提醒我们，模型容易满足于"看起来对"而丢失关键细节——在 GUI 场景里对应"页面大致对、但控件层级/交互元素缺失"，评测须把细粒度组件作为一等指标。

## 7. 延伸阅读

- ChartMimic：4,800 组人工精选的图/指令/代码三元组，图表转代码的经典基准。
- RealChart2Code：基于 Kaggle 真实数据集的 2,800+ 实例，强调原始数据复现与多轮精修。
- Plot2Code / Design2Code：从视觉参考生成代码的相关基准；HumanEval / LiveCodeBench 则代表"执行优先"的评测范式。
