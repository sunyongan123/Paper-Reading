## 1. 研究背景与要解决的问题

长文档推理是大模型的核心能力，却始终难做。即便上下文窗口已到百万 token 级，**准确率仍随输入变长而下降**——即 context rot（上下文腐化），典型表现是位置偏置：中段证据被系统性忽略。作者在多跳 QA 上复现：文档从 7K 涨到 896K token 时，直接全上下文作答会掉几十分。既然窗口远未用满就已退化，瓶颈就**不是容量，而是"该读什么、按什么顺序推理"**。

主流应对是**顺序记忆范式**：逐块读文档，每步把当前块与旧记忆压成新记忆，最后只凭记忆作答（MemAgent 及后续 ReMemR1、GRU-Mem）。它们解决了"有界工作记忆 + 任意长度 + 端到端可训练"，但共享一个结构性承诺：**文档恰好按顺序被遍历一次**，由此带来两个后果——其一，**对证据分布敏感**：每块被压缩时还看不到后文，判断相关性处于信息赤字，于是准确率受证据的位置、逻辑顺序与间距影响，这在多跳推理中最致命，因为后一跳的相关性往往要等前一跳找到后才显现；其二，**延迟线性增长**：第 t 块更新依赖第 t−1 块，T 个块构成不可约串行链。核心洞察是：**文档的阅读顺序由文档规定，问题的推理顺序由问题规定；顺序记忆 Agent 让前者驱动了后者。**

## 2. 核心方法 / 思路

ParSer（**Par**allel Reading, **S**equential **R**easoning）把两种顺序解耦：**并行读全文，串行只留给问题所需的推理深度**。架构是 lead–subagent 的 scatter–gather：

**（1）并行块阅读器。** 文档切成定长块，每块绑定一个轻量子 Agent；给定主 Agent 查询，子 Agent 只依据自己那块返回发现（finding）。多数块无关，子 Agent 可弃权（abstain），弃权在 gather 阶段被丢弃。所有 T 个子 Agent 每轮**并发执行**，因此每块在同一查询下被**对称**阅读：没有块因索引享有特权，也没有块被一次性丢弃；绑到短块上还能保持子 Agent 有效上下文紧凑，缓解 context rot。

**（2）问题驱动的推理者。** 主 Agent 输入只有问题 q，**永远看不到文档或任何原始块**——它推理的是"问题"而非"文档"。它以 ReAct 风格多步循环交替思考与动作：思考后要么发起一次 scatter–gather，要么给出最终答案，每轮查询以"已收集到的发现"为条件。只有这个推理过程串行；全文阅读每轮都并行。实际轮数 K 由**问题需要的推理跳数**决定，而非块数 T。

**（3）跨轮次的自适应并行阅读。** 独立读块看不到跨块关系，但 ParSer 不要求子 Agent 直接解原多跳问题；主 Agent 把它分解成"能在单块内独立成立"的具体查询，任务级跨块依赖由**推理轮次**承载：第 k 轮发现进入主 Agent 上下文并条件化第 k+1 轮查询。跨块组合因此从"按文档顺序传播记忆"转移到"按问题驱动的查询链"。

**（4）稀疏带来的效率。** 每个查询只有少数子 Agent 返回发现，多数只输出极短弃权并被丢弃；顺序记忆则每处理一块都要生成数百到上千 token 记忆更新，故 ParSer 显著减少解码计算。

**（5）训练：只训主 Agent。** 子 Agent 的任务足够简单，冻结的现成模型就够；需要学的是主 Agent 策略。作者用**可验证奖励的强化学习（RLVR）**：奖励是二值精确匹配 EM(a_pred, a_gold)，不用格式奖励，优化器是 **GRPO**，并在策略梯度中**掩掉 observation token**（只对主 Agent 生成 token 回传梯度）。训练数据为 HotpotQA 合成的 32,768 条样本（每条约 200 段、约 28K token）；底座 Qwen3.5-4B/9B；训练上限 9 轮、块 512 token，推理放宽到 12 轮、块 4,096 token；采用**全异步 RL**。

## 3. 关键实验结果

**主结果（HotpotQA 域内 + 2WikiMultiHopQA 域外，上下文 7K–896K token，指标 Sub_EM）**：ParSer 用 4B 和 9B 底座平均达 **84.6% 和 86.8%**，比最强顺序记忆基线高 **5.7 和 6.7 个百分点**；在最长 896K 设置上差距扩大到 **12.0 和 9.9 个百分点**——顺序方法随长度急剧退化，ParSer 几乎零波动。9B 版平均 **86.8%**，**超过原生支持百万 token 的 DeepSeek-V4-Pro 6.3 个百分点**；域外 2Wiki 上 MemAgent/ReMemR1 明显下滑，ParSer 仍稳定（9B 平均 88.48%）。

**三项受控实验**：① **证据位置**：在 894K token 文档中把证据放到 0–90 分位不同区间，ParSer 曲线基本平坦，MemAgent 在 50–70 分位明显塌陷（中段证据最易被后续记忆更新覆盖），ReMemR1 靠回调模块部分缓解。② **证据顺序**：把两跳证据逻辑顺序反转，MemAgent 从 66.5% 掉到 **23.3%**，ReMemR1 从 75.5% 掉到 61.7%，ParSer 保持 **96.4%→97.1%**。③ **证据距离**：随中间干扰段落增多，MemAgent 从 50.0% 掉到 44.6%，ParSer 稳定在 87%–88.7%。

**推理延迟**：单并发下 896K 时 ParSer 相对 MemAgent 有 **11× 加速**（78.2 s vs 876.2 s 每样本），并发 16 时仍有 **1.7×** 优势，因为 ParSer 串行步数近似常数。**消融**：子 Agent 从 2B 换 4B 提升明显（78.26%→84.57%），再换 9B 饱和（84.77%）；去掉分块平均降到 73.76%，佐证 context rot；主 Agent 还能**不重训**地兼容思考型（85.55%）与 DCI（84.67%）子 Agent。

## 4. 亮点与贡献（Why it matters）

- **依赖结构的重写**：把"T 步串行更新"换成"K 轮并行 scatter–gather"，让关键路径随**推理复杂度**而非文档长度增长；对称访问（每轮所有块在同一查询下被重新审视、且不被永久丢弃）从机制上根除"中段证据被覆盖"。
- **训练极简化**：只训主 Agent、子 Agent 冻结，训练成本与文档长度无关；主 Agent 从不直接看文档，学到的是通用"问题推理"而非"文档摘要"，域外泛化更好。此外分块 + 并行让长文档在有限显存内可处理、墙钟延迟有数量级优势，且主 Agent 与不同子 Agent 实现解耦、工程上可插拔。

## 5. 局限与可改进点（个人点评）

- **任务面偏窄**：评测集中在 HotpotQA 与 2WikiMultiHopQA，训练数据只由 HotpotQA 合成。法律、代码库、多文档综述等更开放的长上下文任务未验证，泛化结论需谨慎。
- **并行意味着重复 prefill**：每轮把所有块重读一遍，解码虽省，但若无 KV-cache 复用，prefill 计算量可能不降反升；主文强调的"高效"主要是延迟视角，且轮数分布与"停太早/太晚"的代价报告不充分。
- **弃权机制与分解假设**：若冻结的子 Agent 漏检（把有证据的块判为无关），主 Agent 无法察觉，错误会被静默放大；方法还假设问题能分解为"单块内可独立判定"的查询，对必须跨块联合才能判定的任务可能不成立。此外，ParSer 用两块 GPU（1×H100 子 Agent + 1×RTX3090 主 Agent）对单 GPU 基线，作者称交替执行故可比，但异构硬件下的延迟数字仍需谨慎解读。

## 6. 对我们的启示 / 可借鉴点

- **"读"与"想"要解耦**：不要把长输入的遍历深度绑到推理深度上。把"扫描/检索"做成可并行的宽操作、把"推理/规划"保留为串行的窄操作；同时不永久丢弃任何一块、每轮用新查询重审全部块，避免让"一次压缩后的摘要"成为不可逆的信息瓶颈。
- **只训核心编排器**：把简单子任务交给冻结的小模型、只训练负责决策的主控，可让训练成本与输入规模解耦，同时提升分布外泛化；奖励上用可验证结果信号（如答案精确匹配）配 GRPO 即可，并用 observation masking 只对自生成 token 回传梯度。

**对 GUI Agent 的可借鉴点**：ParSer 的"并行读取 + 深度推理"可直接迁移到 **GUI 长截图 / 长操作历史的高效理解**。(1) 把超长截图序列或超长 DOM/历史轨迹切成块，每块交给轻量子 Agent 并行"读"，主 Agent 只持有任务目标与各轮汇总的"发现"，不把全部像素塞进上下文——正对应 GUI 的"上下文爆炸"与"中段信息被忽略"两大痛点；(2) 用多轮 scatter–gather 做**按需深挖**：先问"哪个区域含目标控件"，据返回再追问"该控件精确坐标/状态"，以跨轮次承载跨屏依赖，替代一次性全屏理解；(3) 历史步骤的物理先后不应决定 Agent 的推理顺序，否则长流程任务会像顺序记忆一样退化；(4) 只训练负责规划与查询的主 Agent、冻结"看局部画面"的视觉子 Agent，是低成本范式，且子 Agent 可插拔（OCR、DOM 解析或视觉定位模型）。差异点：GUI 观察像素级、冗余高、实时性强，块划分应按 UI 结构而非固定长度，轮数须严格预算。

## 7. 延伸阅读

- MemAgent 及后续 ReMemR1、GRU-Mem：顺序记忆范式的代表与改进，本文主要对照对象。
- ReadAgent / MemWalker / Chain-of-Agents：免训练或顺序传递的 chunk 阅读方案。
- LLM×MapReduce / LongAgent / XpandA：编排者—工作者并行阅读路线。
- GRPO / DeepSeekMath、RLVR（DeepSeek-R1）：本文强化学习与可验证奖励的基础。
