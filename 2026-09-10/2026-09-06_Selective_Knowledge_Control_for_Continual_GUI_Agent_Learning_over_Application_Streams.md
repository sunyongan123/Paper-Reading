# Selective Knowledge Control for Continual GUI Agent Learning over Application Streams

> 一句话 TL;DR：用神经元级梯度手术在应用流上持续训练 GUI Agent，按激活动态区分"专属/共享"知识并分别截断与正交投影，抗遗忘且零推理开销。

## 2. 论文要解决的核心问题

- **要解决什么问题**：GUI Agent 在真实部署中面对的是**持续到来的应用流**——新应用布局在变、工作流是用户特有的、新功能持续引入新任务。Agent 必须一边学会新应用，一边保留并复用旧应用的能力。
- **为什么重要**：现有 GUI Agent 训练几乎都假设"一次性 post-training + 固定数据分布"，而真实部署是流式的。不解决，Agent 学了新应用就会灾难性地丢掉旧应用——这正是下游长期可用性被卡住的地方。
- **现有方法有什么不足**：论文逐条批评了三类范式：① 参数冻结与重要性正则（EWC）把受保护参数**一视同仁地约束**，连新应用需要的共享知识也一起压住；② 梯度手术（PCGrad）只消除冲突梯度，却**不区分"可复用"与"必须保护"**；③ 神经元级保护方法（HAT 等）虽然更细，但**保护集固定**，同样不区分这两类。最接近的 Agent-Dice 走"各应用单独训练后参数融合"的事后路线，与单模型顺序微调本质不同。
- **Research Gap**：GUI 持续学习的关键不在"要不要保护历史知识"，而在**分辨哪些该锁死、哪些该继续演化**。作者 claim：本文首次把知识控制落实为"动态区分受保护专属知识 vs 可复用共享知识"的**神经元级梯度操作**，而非静态保护规则。

## 3. 方法核心思想（三层拆解）

### 3.1 一句话概括方法

用"神经元在当前输入下是否被激活"作为信号，把历史重要神经元动态分成专属/共享两类：专属的梯度直接截断、共享的梯度投影到历史更新方向的正交补，从而既抗遗忘又允许复用。

### 3.2 方法总览（Pipeline）

- **输入 / 输出**：输入是顺序到达的每个应用 stage 的训练轨迹（截图 + 指令 → 动作）；输出是持续更新的策略模型 π_θt。
- **核心数据结构**：紧凑历史状态 S_t = (C_hist, U_down, U_gate, U_up)。C_hist 是被保护 MLP 神经元下标集合；U 是每个受保护神经元在三个投影（down/gate/up）上累积的**历史参数更新方向子空间**（正交基）。存的是"哪些神经元重要 + 它们过去往哪动过"，而非旧模型副本或旧轨迹。
- **三个模块（数据流）**：
  1. **激活条件前向划分**：在 MLP down 投影输入挂 forward hook，统计每神经元当前 batch 的平均绝对激活 a_j，取 top-ρ 比例得到当前高激活集 C_cur；与历史保护集求交得**共享集 C_share**，求差得**专属集 C_excl**。
  2. **神经元级反向梯度手术**：C_excl 的梯度置零（当前不用就不许改）；C_share 的梯度投影到历史方向子空间正交补 g̃ = g − U Uᵀg（可学新但只准在垂直过去方向的空间里动）；其余神经元梯度不变。
  3. **阶段末状态更新**：用整阶段累积激活统计重选 top-ρ 神经元并入 C_hist（保护集只扩张），再把该阶段给受保护神经元带来的参数位移向量按"被选中的阶段"堆成矩阵，做截断 SVD 保留 r_svd 个主方向作为新 U。此步仅在阶段间执行一次。

### 3.3 真正的创新点（去伪存真）

- **真·方法创新**：把"当前输入是否激活该神经元"当作**共享/专属的动态判别信号**，并把梯度截断与正交投影绑定到这个实时分区上——这是前人所没有的"选择性"机制，且不依赖任务标签、旧任务数据或人工指定通用能力。
- **工程组合**：forward hook 采激活、梯度投影（OGD/PCGrad 思路）、截断 SVD（HAT 类子空间存储）都是既有组件，本文的价值在组合方式而非单点发明。
- **对性能提升最关键的设计**：消融证明"激活感知分区"是收益主因——静态投影（41.5%）、静态冻结（40.1%）都远低于本文（47.1%），说明关键不在"冻结还是投影"，而在"按当前激活分区对待"。
- **证据不足 / 仅声称有效**：论文声称端到端抗遗忘，但梯度手术**只作用于 MLP、未覆盖视觉编码器与注意力层**，视觉 grounding 侧的遗忘风险无任何定量支撑；且全部结论建立在单一 backbone 与固定应用顺序上。

## 4. 具体技术细节

### 4.1 模型结构

- **Base model**：UI-TARS-1.5-7B，7B 参数的**多模态大语言模型（MLLM）**，原生视觉-语言-动作模型，含视觉编码器，直接吃截图输出动作（click/type/导航），是典型 GUI 视觉 Agent。
- **是否冻结/微调**：整模型在 OSWorld 上做 **RL 微调**（非冻结）；但梯度手术仅作用于 Transformer block 的 **MLP 三投影矩阵**（W_down 的列、W_gate/W_up 的行），视觉编码器与注意力不参与保护——这是本文一个被隐藏的假设。

### 4.2 训练流程（选择性知识控制是重点）

| 阶段 | 目标 | 训练什么能力 | 数据来源 | 数据形态 | 训练目标 / Loss |
|---|---|---|---|---|---|
| 应用流 stage t（t=1..8） | 学会当前应用且不遗忘历史 | 端到端 GUI 操作策略 | OSWorld 当前应用的任务与 DART-GUI 采样的 GRPO 轨迹 | 截图+指令→多步动作轨迹 | GRPO 策略梯度目标 L_t(θ)，叠加神经元级梯度手术 |

训练范式是**顺序 RL 微调**：基于开源 DART-GUI，用 GRPO 在 OSWorld 上训练，每个应用 stage 从上一阶段初始化并微调，训完把模型 + 历史状态传给下一阶段。**重点不在 RL 本身，而在每个 stage 内叠加的三步梯度控制**：

- **前向划分**（Eq. 4–6）：注册 forward hook，算每神经元平均绝对激活 a_j，取 top-⌊ρd_ff⌋ 得 C_cur；C_share = C_hist ∩ C_cur，C_excl = C_hist \ C_cur。
- **反向手术**（Eq. 7–9）：C_excl 梯度置零 g̃=0；C_share 投影到正交补 g̃ = g − U Uᵀg；未保护神经元梯度不变。优化器用改写后的梯度更新。
- **阶段末更新**（Eq. 10–14）：重选 top-ρ 并入 C_hist；对每个受保护神经元的参数位移矩阵做截断 SVD，保留 r_svd 主方向更新 U。

超参 ρ = 2%、r_svd = 4。整套不重放历史轨迹、不算旧应用梯度、不存每应用 checkpoint。

### 4.3 推理流程

- 推理端**零改动、零开销**：仍走 UI-TARS 标准视觉-动作生成流程，输入当前截图 + 任务指令，输出动作，多步循环直到任务完成或达到终止条件。
- 历史状态 S_t 不参与推理，梯度手术只在训练阶段介入——这也是它能"+1.0% 时间成本"轻量落地的原因。

## 5. Benchmark 与实验设置

### 5.1 Benchmark 一览表

| Benchmark | GUI 场景 | 任务类型 | 数据规模 | 输入格式 | 输出格式 | 评测指标 |
|---|---|---|---|---|---|---|
| OSWorld | Desktop（真实桌面 OS） | 端到端多步任务（文件/办公/多媒体/浏览器等） | 8 阶段应用流：vlc→Thunderbird→libreoffice_writer→libreoffice_impress→Calc→GIMP→VSCode→Chrome；每阶段训完在所有已见应用评 3 次 | 截图 + 自然语言指令 | 动作序列（点击/输入/导航） | 成功率、RP、CP、RAH |

### 5.2 实验结果分析

- **主结果**：与朴素顺序微调基线对比，本文在 Stage 2–8 每个可比阶段整体成功率均更高，中后期提升最明显——Stage 3/6/7 分别 +12.6/+7.1/+10.6 个百分点，Stage 8 为 42.7% vs 37.3%（+5.4）。
- **遗忘-适应拆解**（RP/CP/RAH）：平均 RP +6.3、CP +9.1、RAH +9.8，两个方向同时涨；Stage 2 的 RP 达 100%（基线 89.3%），Stage 3 的 CP 为 57.1% vs 47.6%。**但注意 Stage 8 的 RP 为 90.1% vs 93.0%（−2.9），并非全线占优**。
- **与其他持续学习基线**（同配置，Stage 3 整体）：本文 50.3% > EWC 44.8% > Replay 44.0% > LoRA 41.4%。
- **消融**：朴素微调 37.6%、静态投影 41.5%、静态冻结 40.1%、本文 47.1%——证明收益来自"激活感知分区"而非单纯冻结/投影。
- **超参敏感性**：ρ=1%/3% 掉到 40.9%/44.2%（ρ=2% 为 50.3%）；r_svd=2/8 掉到 38.5%/38.7%（r_svd=4 为 42.7%），两者均"中等最优"。
- **开销**：每步 4279.23s→4324.00s（+1.0%），token 吞吐 −3.3%、算力吞吐 −1.9%。附录还给出 shuffled 顺序（VLC→VSCode→GIMP）下本文仍优于基线。

## 6. 亮点与贡献（Why it matters）

1. **问题 framing 本身有价值**："持续 GUI 学习 ≠ 传统持续学习"，把"共享 vs 专属知识"的分辨提为核心矛盾，解释了 EWC 类方法在 GUI 流上为何失效。
2. **信号选择聪明**：用"当前输入是否激活"判别共享/专属，无需任务标签、旧数据或人工指定通用能力，且消融证明它是收益主因。
3. **工程上真轻**：不做 replay、不算旧梯度、不存多 checkpoint，仅 +1.0% 训练时间，可作插件叠在现有 GRPO pipeline 上。
4. **度量有参考价值**：RP/CP/RAH 把"遗忘了"与"没学会"拆开报告，比单一成功率更能诊断问题。

## 7. 局限与可改进点（个人点评）

1. **统计力存疑**：只有 8 应用、单 backbone、单 benchmark、每阶段 3 次评测，无置信区间或显著性检验；且表格中已现反例（Stage 8 RP −2.9、Stage 6 Thunderbird −2.2、Stage 5 Impress −3.0），"每阶段都更好"的稳健性未被量化。
2. **只管 MLP，不管视觉与注意力**：而 GUI Agent 的核心能力正是视觉 grounding，视觉侧表征是否更易遗忘、是否更需保护，论文完全没碰。
3. **超参敏感 + 隐含假设**：ρ=2% 比 1%/3% 高近 10 点；top-ρ 固定比例假设各阶段重要神经元占比相近，若某阶段引入大量全新知识就会选错。
4. **LoRA 对比不公平**：用"每应用一 adapter + 指令路由"，路由选错即崩，弱项可能来自路由器而非 LoRA 本身。
5. **历史状态增长未分析**：C_hist 单调扩张，论文只说状态"compact"，未给随阶段数的规模曲线，也未讨论长流下保护集饱和的后果。

## 8. 对我们的启示 / 可借鉴点

1. **梯度手术可做成 RL 之上的轻量插件**：仅需 forward hook 采激活 + 反向改写梯度，不改优化器、数据管线与 replay buffer，对现有 GRPO 侵入性极小。
2. **直接借用 RP/CP/RAH 度量**：只报总体成功率无法判断一次改动是"学会了新任务"还是"忘掉了旧任务"。
3. **"激活感知 > 静态保护"是普适结论**：当前输入是否使用某条通路，本身就是判断其可否复用的强信号，可迁移到 GUI Grounding（跨应用视觉定位 vs App 特有控件语义）以及知识隔离、PEFT、MoE 路由等工作。
4. **对 Benchmark 的启发**：应构建多应用顺序流式评测并绘制遗忘曲线，现有 GUI benchmark 多为"单应用能否做对"，无法暴露持续学习能力。
5. **反面提醒**：引用或复现前，先在第二个 backbone（如 Qwen-VL 系）与随机顺序上验证，本文化结论高度依赖单一基座与固定顺序。
