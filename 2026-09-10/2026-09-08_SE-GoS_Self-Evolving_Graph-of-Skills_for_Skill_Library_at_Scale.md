# SE-GoS: Self-Evolving Graph-of-Skills for Skill Library at Scale

> 不改代码、不训模型、不动技能内容，仅用执行轨迹离线"重连"技能图，一次演化就让技能检索奖励从 52.4% 升到 59.4%，并把 token 省掉三分之一。

## 1. 研究背景与要解决的问题

现代 LLM Agent 干活靠调用外部工具和可复用"技能"（skill）。当技能库从几十个涨到上千个时，瓶颈从"要不要用技能"变成了"**如何检索出刚好够用的那一小撮技能**"：把整个库塞进上下文 token 成本线性上涨、模型还会"看漏"；纯向量检索虽压 token，却忽略了技能的**功能前置依赖**——最相似的那个往往是高层求解器，而它底层必需的解析器语义上并不相似，这就是"前置依赖缺口"。

Graph-of-Skills（GoS）用一张带类型的技能有向图补上这个缺口：语义 + 词法混合种子检索，再用**反向感知的 Personalized PageRank（PPR）**扩散，返回有预算约束的执行包。在 1000 技能的 SkillsBench 上，GoS 相比全量加载峰值提升约 25.6% 奖励、省约 56.7% token。**但 GoS 是静态的**：图只构建一次，永不从执行反馈更新。一旦某条依赖被诱导错了、某条有用关系缺失，或某技能描述匹配不上它该服务的查询，仓库就无法自我纠正。而作者的关键观察是：**修复所需的信号早就被免费记录下来了**——每次试验都记着"检索了哪些技能、实际用了哪些、任务成没成功"。本文要做的就是把这些轨迹变成对检索图的修复。

## 2. 核心方法 / 思路

SE-GoS 是 **training-free** 框架，**完全不改动 GoS 的检索流程**，只改检索所读的那张图。之所以"改图就够"，是因为 PPR 的转移算子直接由边权构成，重新连边/调权就会改变检索结果，而检索代码是一个固定的消费者。

**冷启动图更"素"。** GoS 的 workflow / semantic / alternative 关系要靠 LLM 关系验证器离线跑出来；SE-GoS 刻意不假设有这个 LLM，冷启动只用一个**确定性、纯语义的相似图**（每个技能连到签名 token 重叠最高的 top-k 邻居），把缺失结构交给执行反馈来补。
**三类互补的演化更新**（分别作用于离散边集、连续边权、节点文本，互不覆盖对方输出）：

- **拓扑更新**：从成功试验的"检索—使用"共现诱导 **workflow 边**（权重随共现次数增长，上限 0.9）；当成功试验里 u 先于 v 使用、且 u 的输出与 v 的输入 schema 重叠超过 ζ=0.6 时，诱导 **dependency 边**；在失败试验里反复共现（≥θ_avoid 次且从未成功）的技能对加 **avoid 边**（零权重、不被扩散遍历，只在打包时剔除同捆坏伙伴）。同时**剪枝**：某技能被检索 ≥θ_obs 次却从未被使用，就把其入边权重乘 0.5，低于下限的直接删除。作者只诱导 avoid 而**不诱导 GoS 的 alternative 关系**——"同时加载有害"能被失败观测到，而"可互相替代"是反事实断言。
- **边权更新**：在奖励为正（r_t>0）的成功试验中，对每个实际被使用的技能 v，把它所有入边按 w ← w + η·r_t 强化。
- **节点更新**：针对"被用了却没被检索好"的技能（在失败试验中被使用、且排名低于 n_rank=3），认定瓶颈在描述文本。借鉴 ProTeGi 的"文本梯度下降"做**单轮、技能局部**版本：LLM 批评者产出自然语言梯度 → 编辑器沿反方向改写描述 → 生成若干变体 → 用离线评测器（只重跑检索、不跑 Agent）按排名选出最优描述。单技能成本 O(|Q_s|·(1+p)) 次 LLM 调用，与库规模无关；默认开启"禁止驱逐"护栏，防止改写把用过的技能挤出 top-K。

三更新按依赖顺序（拓扑→边权→节点）在一个演化窗口内离线应用一次，之后用**原封不动的 GoS 检索**服务查询，推理期零额外开销。

## 3. 关键实验结果

评测在 **SkillsBench**（87 个任务 + 1000 技能库）与 **ALFWorld** dev split 上进行，主 backbone 是 deepseek-v4-flash-0731，另在两个模型上做跨 backbone 对照。对比 Vanilla（全量加载）、Vector（向量检索）、静态 GoS、SkillDAG（自演化对比方法）。

**主结果（SkillsBench，87×2 次尝试）**：deepseek-v4-flash 上 Vanilla 46.2%、Vector 38.7%、静态 GoS 52.4%、SkillDAG 55.3%，而 **SE-GoS 达 59.4%（比静态 GoS +7.0）**，同时每次尝试输入 token 为 3.45M，**比全量加载的 5.06M 低约 32%**。静态 GoS 已明显优于 Vanilla 与 Vector，说明图结构检索冷启动就领先；而 SE-GoS 演化前状态**恰好就是静态图**，因此增益可归因于演化本身。跨 backbone 也一致：minimax-m2.7 从 18.7% 升到 **28.5%**（+9.8），gpt-5.2-codex 从 34.4% 升到 **38.1%**（+3.7）。

**留出集验证（50 训练 / 37 测试，n=74）**：SE-GoS 把静态 GoS 从 52.9% 提到 **58.3%（+5.4）**，token 基本持平（3.30→3.19M）。评测任务与训练任务不相交，**该增益体现的是可迁移结构而非对轨迹的记忆**。

**多轮演化（表 4）**：第 0 轮（静态）52.4%，第 1 轮 59.4%，第 2 轮 59.8%（基本持平），**第 3 轮掉到 54.0%**，边数从 863 涨到 1,502。这说明**演化是一次性的部署步骤，而不是训练循环**。

## 4. 亮点与贡献（Why it matters）

- **精准定位"静态图"瓶颈**：把问题从"如何检索技能"推进到"检索所依赖的图能否从使用中自我修正"，并指出修复信号本就免费存在于轨迹中。
- **training-free、零推理开销、三类更新正交**：不训参数、不改 SKILL.md、不动检索代码，演化完全离线；拓扑（离散边）、边权（连续权重）、节点（文本）各管一轴、互不覆盖，便于做 2³ 因子消融归因，每处改动可审计、可逆。
- **用"执行"替代"LLM 先验"**：这是与 SkillDAG 最本质的差异——技能相关性由真实使用共现判定，而非让模型去猜，还省掉了 SkillDAG 冷启动的约 200 次 LLM 调用与嵌入服务依赖。
- **诚实的负面结论**：明确报告多轮演化会过拟合、留出集增益落在噪声带内、avoid 边未被实际触发，学术态度可取。

## 5. 局限与可改进点（个人点评）

- **单轮即可，多轮即坏**：这既是结论也是局限——方法无法持续积累，只能做一次"部署前校准"，长期在线学习能力缺失。
- **依赖"实际使用技能集" U_t 的抽取**：作者承认间接使用会被漏计，而边权与拓扑更新都建立在这个集合上，抽取质量直接决定演化效果，却未见对其准确率的评估。
- **泛化与范围均有边界**：留出集 +5.4 分未超出论文自定的 ±6~7 分噪声带；且只在 1000 技能规模与三个模型上验证，作者明确不对其他规模或 backbone 做断言。
- **未开源，且节点更新仍依赖 LLM**：复现材料未给公开链接；文本通道仍由 LLM 改写描述，其偏差未被单独分析。

## 6. 对我们的启示 / 可借鉴点

**通用启发**：经验应沉淀在**检索脚手架**上，而非模型或技能内容上——脚手架便宜、可审计、可回滚，且被所有读同一库的 Agent 共享。
### 对 GUI Agent 的可借鉴点

- **技能图自演化 → GUI 操作技能库的检索层**：GUI Agent 常把"点击某按钮""填写表单"沉淀成可复用技能（SOP、宏动作），规模一大就面临同样的检索瓶颈。SE-GoS 可直接迁移——**不改技能内容、不训模型**，只用历史轨迹去重连"操作技能图"：两个操作在成功轨迹里高频共现（先"展开菜单"再"选择子项"）就加 workflow 边；某操作被检索到却从未被点击就软剪枝降权。
- **把"使用证据"作为边的真值来源**：GUI 场景下"检索到的元素"与"实际点击的元素"天然可记录，正是 SE-GoS 的 U_t 信号。用"点击与否 + 任务成功与否"强化/弱化边权，比让 LLM 判断"两个操作是否相关"更可靠，也避开了 GUI 里 LLM 流程推理不可靠的老问题。
- **失败共现诱导"avoid 边"适合 GUI 防护**：某些操作组合会触发弹窗、误删除或流程中断，这类"共加载有害"关系可由失败轨迹直接观测，用来在动作打包阶段剔除危险组合，与 GUI 不可逆操作防护高度契合。
- **描述文本演化 → 元素检索侧优化，且一次演化即部署**：GUI 元素的描述常让检索匹配不上真实意图，SE-GoS 的"单轮文本梯度 + 离线排名评测"可在不改元素本身的前提下只优化检索描述，成本 O(1)。同时"第 3 轮就掉分"提醒我们，GUI 技能图应"离线跑一轮 → 冻结 → 上线"，保留可回滚快照。

## 7. 延伸阅读

- Graph-of-Skills（GoS）：本文的检索底座，带类型技能图 + 反向感知 PPR。
- SkillDAG / SkillGraph：另两条自演化技能图路线，前者用 LLM 冷启动 + 在线编辑，后者通过强化学习训练。
- ProTeGi / TextGrad：文本梯度下降与文本自动微分，本文节点更新的直接来源。
- HippoRAG：PPR 检索增强的代表工作；Voyager 代表"改技能内容"的另一条路线。
