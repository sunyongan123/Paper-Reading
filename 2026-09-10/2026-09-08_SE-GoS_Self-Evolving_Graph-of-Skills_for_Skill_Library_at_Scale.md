# SE-GoS: Self-Evolving Graph-of-Skills for Skill Library at Scale

> 一句话 TL;DR：不动检索代码、不训模型、不改技能内容，只用历史执行轨迹离线"重连"技能图，一轮演化即让技能检索奖励从 52.4% 涨到 59.4%，并省下约 1/3 token。

## 2. 论文要解决的核心问题

- **要解决什么问题**：当 LLM Agent 的技能库从几十涨到上千个时，"检索出刚好够用的那一小撮技能"取代"要不要用技能"成为核心瓶颈——即大规模技能库下的**有预算、依赖完备的技能检索**问题。

- **为什么重要**：全量加载技能库的 token 成本随库规模线性上涨，且上下文过载会让模型"看漏"关键技能；向量检索虽压缩 token，却忽略技能的**功能前置依赖**（prerequisite gap）——语义最相似的往往是高层求解器，其底层必需的解析器/装配工具语义弱却被功能必需。检索错，下游任务执行就崩，这是真实工具生态的首要障碍。

- **现有方法有什么不足**：本文明确批评三条基线——**Vanilla（全量加载）**贵且低效；**Vector retrieval** 省 token 但丢前置链；**GoS（静态图检索）**虽是当前最强底座（带类型技能图 + 反向感知 PPR），但图只构建一次、**永不从执行反馈更新**：一旦依赖被诱导错、有用关系缺失、或描述文本系统性地匹配不上所需查询，仓库无法自纠。而 SkillDAG 虽"自演化"，其冷启动仍靠约 200 次 LLM 调用做 pair 分类器，结构来源是"模型先验"而非"执行证据"。

- **Research Gap**：作者指出，GoS 自己承认静态图局限、SkillDAG 也证明技能图能在线积累执行结构，但**"历史执行轨迹能否被系统性蒸馏为一张更好的检索图、并泛化到未见任务"这一问题无人回答**。作者的核心主张（claim）：修复信号本就免费存在于每一次试验中（检索了哪些、实际用了哪些、成没成功），本文用三条训练无关的更新把这条信号变成对检索图的重构，补上"从执行经验中学习检索结构"的缺口。

## 3. 方法核心思想（三层拆解）

### 3.1 一句话概括方法

SE-GoS 是一个 **training-free** 框架：保持 GoS 检索管线原封不动（作为"固定消费者"），只离线演化检索所读的那张图——用执行轨迹重连边、调权、改写节点描述。

### 3.2 方法总览（Pipeline）

- **输入**：技能库（归一化技能记录构成的带权有向图 G=(V,E,w,ϕ)）+ 历史执行轨迹 D={T_t}（每条含查询 q、奖励 r、检索包 B、实际使用技能集 U、token 数）。
- **输出**：演化后的图 G(T)、边权 w(T)、描述 d*，供**原样 GoS 检索**直接消费。
- **模块**（三类互补更新，分属三个正交轴：离散边集 / 连续边权 / 节点文本，互不覆盖对方输出）：
  1. **拓扑更新**：从成功试验的"检索—使用"共现诱导 workflow 边；从"先 u 后 v 使用 + schema 重叠达标"诱导 dependency 边；从失败共现诱导 avoid 边；并对"被反复检索却从未被用"的技能软剪枝。
  2. **边权更新**：成功试验（r_t>0）中，对被实际使用的技能 v，强化其所有入边。
  3. **节点更新**：对"用了却排不进 top-K"的技能，用 ProTeGi 式文本梯度做单轮、技能局部的描述改写。
- **连接**：冷启动图为**确定性、纯语义相似图**（无 LLM、无 embedding），三类更新在一个演化窗口内按**依赖顺序（拓扑→边权→节点）**离线应用一次，之后推理零额外开销。

### 3.3 真正的创新点（去伪存真）

- **真·方法创新**：把"技能相关性判断"从 **LLM 先验转移到执行证据**——拓扑/边权通道完全 model-free，只靠计数与算术；这是与 SkillDAG 最本质的分野，也是全文立论的核心。
- **工程组合**：反向感知 PPR、ProTeGi 文本梯度、Hebbian 式边权强化都是既有组件，本身不新；组合成"图作为可演化检索脚手架"有效。
- **对性能提升最关键的设计**：**边权更新**。主效应 +4.7 分、leave-one-out 中删掉它损失 3.6 分，是唯一明显拉动奖励的组件；拓扑与节点更新贡献小（+1.4 / +1.3）。
- **证据不足 / 仅声称有效**：**avoid 边**声称能剔除"共加载有害"组合，但在 k=1 全量轨迹上诱导集为空、k=8 仅 1 条，全程未被实际触发，其价值纯属纸面论证。

## 4. 具体技术细节

### 4.1 模型结构

无被训练模型。**Agent backbone 是纯 LLM（非 MLLM，无视觉编码器）**：主实验用 `deepseek-v4-flash-0731`（经 tcodex wrapper），跨 backbone 对照 `minimax-m2.7` 与 `gpt-5.2-codex`。全部参数冻结，SE-GoS 完全不触碰模型权重；唯一动用 LLM 的是节点更新里的 critic/editor（作为"算子"而非"先验"）。

### 4.2 方法机制（图式技能自演化——本文重点）

**冷启动图更"素"**：GoS 的 workflow/semantic/alternative 关系靠 LLM 关系验证器离线产出；SE-GoS 刻意不假设有 LLM 与 embedding 服务，冷启动只用**确定性 token 重叠相似图**（每技能连签名 token 重叠最高的 top-k 邻居，863 条语义边），缺失结构交给执行反馈补。

**三类演化更新**（逐条写实）：

- **拓扑更新（改边集，改边类型）**：
  - **workflow 边**：成功试验里，检索到的种子 u 与已用技能 v 共现即连边，权重 `w_wf(u→v)=min(0.9, 0.6+0.05(c_uv−1))`，随共现次数增长、上限 0.9。
  - **dependency 边**：成功试验里 u 先于 v 使用、且 u 输出与 v 输入的 schema 重叠 ≥ζ=0.6 时认证连边（schema 预测前置、轨迹背书）。
  - **avoid 边**：失败试验里反复共现（≥θ_avoid=2 次且从未成功）加边，权重为 0、不参与扩散遍历，只在打包时剔除同捆坏伙伴。
  - **剪枝**：技能被检索 ≥θ_obs=2 次却从未被用，则其入边权重 ×0.5（软剪枝），低于下限者直接删除。
  - **关系边界**：只诱导 avoid、**刻意不诱导 GoS 的 alternative 关系**——"可互相替代"是反事实断言，观测轨迹无法认证。
- **边权更新（改连续权重）**：对每个 r_t>0 的成功试验、每个实际使用的技能 v，将其所有入边按 `w(t+1)(u→v)=w(t)(u→v)+η·r_t·I[v∈U_t]` 强化，η=0.1；失败试验不贡献正向信用。PPR 的转移算子直接由这些边权构成，故重连/调权即改变检索结果。
- **节点更新（改节点文本）**：针对"被用了却没检索好"的技能（失败试验中被用、排名低于 n_rank=3，默认 miss 源取 r<r_succ=0.9 的失败试验）。借鉴 ProTeGi 做**单轮、技能局部**版本：LLM critic 产出自然语言梯度 → editor 沿反方向改写描述（预算 ≤50 token）→ 生成 p=2 个变体 → 用**离线评测器**（只重跑检索、不跑 Agent）按排名选出最优描述。单技能成本 O(|Q_s|·(1+p)) 次 LLM 调用，与库规模无关；默认开启"禁止驱逐"护栏，防止改写把用过的技能挤出 top-K。

### 4.3 推理流程

**多步、图扩散式检索**，完全复用 GoS 三阶段管线：① **纯词法种子**（ξ=0，取 GoS 重排函数的 token 重叠项，无 embedding）；② **反向感知 PPR 扩散**（restart α=0.2，`s^(ℓ+1)=αp+(1−α)T^⊤s^(ℓ)`，正向 λ_r 权重 dep>wf>sem>alt、反向 γ_r 分别 1.0/0.5/0.2/0.1），让相关性从匹配种子向结构上重要的前置技能传播；③ **预算重排与注水**（`ρ_i=s*_i+µ·m_i`，按每技能 1,800 字符 / 全局 9,000 字符预算打包出有界执行束）。演化后推理时输入 `ρ_i(q)=s*_i(q;G(T),w(T),d*)+µ·m_i(q;d*)`——函数形式与静态 GoS 完全一致，**变的只是它读的那张图**，因此推理期零额外开销。

## 5. Benchmark 与实验设置

### 5.1 Benchmark 一览表

| Benchmark | GUI 场景 | 任务类型 | 数据规模 | 输入格式 | 输出格式 | 评测指标 |
|---|---|---|---|---|---|---|
| SkillsBench | General（Agent 技能） | 端到端任务执行 | 87 任务 + 1,000 技能库（n=174 次尝试） | 文本指令 + 技能库 | 执行结果（技能调用轨迹） | R 平均奖励 %、T 输入 token/次、S 运行时 |
| ALFWorld | Web/Embodied（跨域 sanity check） | 端到端 | dev split | 文本指令 | 动作序列 | 同上 |

### 5.2 实验结果分析

**主结果（Table 2，deepseek-v4-flash-0731，SkillsBench）**：Vanilla 46.2%（5.06M token）、Vector 38.7%（3.11M）、静态 GoS 52.4%（3.67M）、SkillDAG 55.3%（3.62M）、**SE-GoS 59.4%（3.45M，比静态 GoS +7.0，比全量加载省约 32% token）**。静态 GoS 冷启动即碾压 flat 基线，而 SE-GoS 演化前状态恰为静态图，故增益可归因于演化本身。跨 backbone 一致但幅度各异：minimax-m2.7 从 18.7%→**28.5%**（+9.8）、gpt-5.2-codex 从 34.4%→**38.1%**（+3.7）——弱 backbone 上检索改进最可见。

**留出集（Table 3，50 train / 37 test，n=74）**：SE-GoS 把静态 GoS 从 52.9% 提到 58.3%（+5.4，落在论文自定 ±6~7 点噪声带内），token 基本持平（3.30→3.19M）。训练/测试任务不相交，增益体现**可迁移结构而非记忆**。

**多轮演化（Table 4）**：第 0 轮 52.4%、第 1 轮 59.4%、第 2 轮 59.8%（基本持平）、**第 3 轮掉到 54.0%**，边数从 863 涨到 1,502——**演化是一次性部署步骤，而非训练循环**。

**Ablation（Table 6，2³ 因子）**：单通道 vs 静态 GoS：拓扑 +1.7、边权 **+4.9**、节点 +1.2；最优两因子组合 edge+node 59.1、topology+edge 58.8；全方法 59.4 为全局最优。主效应 +4.7（edge）/ +1.4（topology）/ +1.3（node）；leave-one-out 删边权损失 **−3.6**，删节点 −0.6、删拓扑 −0.3。结论：**边权更新是唯一关键杠杆，其余是锦上添花**。接口消融（Table 7）显示 fused bundle 与三通道呈现几乎无差（0.569 vs 0.572），证明收益不来自界面呈现。

## 6. 亮点与贡献（Why it matters）

1. **精准定位"静态图"瓶颈**：把问题从"如何检索技能"推进到"检索所依赖的图能否从使用中自我修正"，并指出修复信号本就免费存在于每次试验的轨迹中。
2. **training-free、零推理开销、三类正交更新**：不训参数、不改 SKILL.md、不动检索代码，演化全离线；拓扑（离散边）、边权（连续权重）、节点（文本）各管一轴，可做 2³ 因子归因，每处改动可审计、可逆。
3. **用"执行"替代"LLM 先验"**：与 SkillDAG 最本质的差异——技能相关性由真实使用共现判定，而非模型猜测，还省掉其冷启动约 200 次 LLM 调用与 embedding 服务依赖。
4. **经验落地在检索脚手架而非模型/技能内容上**：边权构成一份"压缩、非参数化的成功执行记录"，被所有读同一库的 Agent 共享，便宜、可审计、可回滚。
5. **诚实的负面结论**：明确报告多轮演化会过拟合、留出集增益落在噪声带内、avoid 边未被实际触发，学术态度可取。

## 7. 局限与可改进点（个人点评）

1. **单轮即可、多轮即坏**：方法无法持续积累，只能做一次"部署前校准"，长期在线学习能力缺失；"窗口化部署"仅被提及、未做表征。
2. **依赖"实际使用技能集 U_t"的抽取质量**：作者承认间接使用会漏计，而边权与拓扑更新全部建立在这个集合上，抽取精度直接决定演化效果，却未见对其召回/精度的专项评估。
3. **泛化与范围边界清晰但偏窄**：留出集 +5.4 分未超出噪声带；仅在 1,000 技能规模与三个 backbone 上验证，作者明确不对 200/500/2,000 规模做断言。
4. **未开源 + 节点通道仍依赖 LLM**：无公开复现链接；文本通道由 LLM 改写描述，其引入的偏差未被单独消融。
5. **avoid 通道是"空转"**：全文核心卖点之一（失败共现防护）在实测中从未被触发，属于验证不足的机制。

## 8. 对我们的启示 / 可借鉴点

**通用启发**：经验应沉淀在**检索脚手架**上，而非模型或技能内容上——脚手架便宜、可审计、可回滚，且被所有读同一库的 Agent 共享；这是对 RL/Online/Reflection 方向"经验存哪"问题的一个直接回答。

### 对 GUI Agent 的可借鉴点

- **技能图自演化 → GUI 操作技能库的检索层**：GUI Agent 常把"点击按钮""填表单"沉淀成可复用技能（SOP、宏动作），规模一大即遇同样检索瓶颈。SE-GoS 可直接迁移——不改技能内容、不训模型，用历史轨迹重连"操作技能图"：成功轨迹里高频共现的操作（先展开菜单再选子项）加 workflow 边；被检索到却从未被点击的操作软剪枝降权。
- **把"使用证据"作为边的真值来源**：GUI 场景下"检索到的元素"与"实际点击的元素"天然可记录，正是 U_t 信号。用"点击与否 + 任务成功与否"强化/弱化边权，比让 LLM 判断"两操作是否相关"更可靠，也避开 GUI 里 LLM 流程推理不可靠的老问题。
- **失败共现诱导 avoid 边，契合 GUI 不可逆操作防护**：弹窗、误删除、流程中断这类"共加载有害"关系可由失败轨迹直接观测，用于动作打包阶段剔除危险组合（若 trace 能记录到足够失败样本，本机制在 GUI 比在技能库更易触发）。
- **一次演化即部署，保留可回滚快照**："第 3 轮就掉分"提醒我们 GUI 技能图应"离线跑一轮→冻结→上线"；元素描述常匹配不上真实意图时，可用其"单轮文本梯度 + 离线排名评测"在不改元素本身的前提下只优化检索描述，成本与库规模无关。

## 9. 延伸阅读

- **Graph-of-Skills（GoS）**：本文检索底座，带类型技能图 + 反向感知 PPR（arXiv:2604.05333）。
- **SkillDAG / SkillGraph**：另两条自演化技能图路线，前者 LLM 冷启动 + 在线编辑（arXiv:2606.03056），后者强化学习训练（arXiv:2605.12039）。
- **ProTeGi / TextGrad**：文本梯度下降与文本自动微分，本文节点更新的直接来源。
- **HippoRAG**：PPR 检索增强的代表；**Voyager / SkillRouter**：分别代表"改技能内容"与"固定索引路由"两条不同路线。
