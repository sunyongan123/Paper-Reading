# CA-OPD: Confidence-Aware On-Policy Distillation for Structured Visual Prediction

> TL;DR：用"教师置信度"给学生的自回归输出把关——没把握的位置让教师直接改写并喂标准答案，有把握的位置才保留学生输出并做分布级蒸馏；把关松紧随训练从严到宽，让 GUI 点选与 OCR 的小模型显著追上大模型。

## 1. 研究背景与要解决的问题

现在的视觉语言模型（VLM）喜欢把"看屏点哪里""读出这段字"这类感知任务统统写成**自回归的 token 序列**：坐标是一串数字 token，OCR 文字是字符 token。好处是接口统一、一个模型干所有活；坏处是**输出带上了强顺序依赖**——每一个已生成的 token 都会变成后面预测的输入。这就像写程序时一个括号打错了，后面整段都会跟着乱：局部小错会被一步步放大，污染整条输出轨迹。

在把大模型（教师）的能力蒸馏给小模型（学生）时，这个特性带来了老问题。传统的"离线蒸馏"让学生照着教师生成的示范轨迹学，学生推理时却走的是**自己生成的轨迹**——训练和推理的轨迹分布不一样（业界叫 train-inference mismatch）。"同策略蒸馏（OPD）"对症下药：让学生自己先走一步，教师再在**学生实际到过的状态**上给监督。可这又引入新风险：学生水平不行时，一个错误 token 一旦进了前缀，后续所有教学状态全被带偏，尤其是训练早期。

更近的"交错蒸馏"（如 SKD）让教师对学生提议逐 token 把关、必要时替换。但作者指出它有两个盲区：第一，SKD 用的是**排名**（学生提议在教师分布里排第几）而非**绝对置信度**——排第三可能意味着 90 分也可能只是刚及格，排名高低和教师到底多认可这件事是两回事；第二，教师"出手纠正"本身就是一个高价值的教学信号，但现有方法只把它当轨迹修复工具，白白浪费了"这地方你错了"的明确反馈。本文就是冲着这两点来的。

## 2. 核心方法 / 思路

CA-OPD 的主干一句话：**同一个"教师是否认可"的判断，既决定轨迹里放谁的 token，也决定这个位置用什么损失来教。** 流程分四步：

1. **学生提议，教师打分**。每一步学生生成候选 token ŷ，教师算它在自己分布下的负对数似然 NLL=−log π_T(ŷ|s_t)。NLL 越小 = 教师越支持（绝对支持度，而非相对排名）。给定一个阈值 τ，NLL 超阈值就判定"不可靠"（r_t=1），否则保留（r_t=0）。

2. **按判断分流建轨迹**。被否定的位置，教师用自己 argmax 的 token 改写并写回前缀；被认可的位置，学生的 token 原样留下。之后的自回归生成都基于这条"学生/教师混合前缀"。类比：不是让学生自由发挥（OPD），也不是全程放教师录像（Offline KD），而是"学生先写、教师像批改作文一样只在关键处动笔"。

3. **监督与判断对齐**。被改写的位置（r=1）：学生确实错了，直接上交叉熵（CE），相当于把正确答案喂到嘴边；被保留的位置（r=0）：学生思路对，但别只学一个 token，去拟合教师的**完整预测分布**——为了省算力，只取教师 top-64 的 forward KL。同一个 r 既定轨迹又定损失，这正是全文的"耦合"卖点。

4. **从严格到宽松的放权调度**。阈值按训练进度用余弦曲线从 τ_start=0.693 松到 τ_end=1.386（等价于教师支持度下限 α 从 0.50 降到 0.25，前 10% 步数先保持最严）。早期学生不可靠、教师多出手；后期学生变强、更多自产 token 过关，轨迹控制权平滑交还学生。

实现上用 Qwen3.5-0.8B（先 SFT 初始化）当学生，两个按领域微调过的 Qwen3.5-9B 分别当 GUI grounding 教师和 OCR 教师，训练样本按域动态路由到对应教师（multi-teacher）。对比基线是 Offline KD、标准 OPD（即 GKD 式）和 SKD，全部共享同一初始化、数据与 471 步优化预算，每个配置跑 3 遍取均值。

## 3. 关键实验结果

在 6 个目标任务上评测，教师路由行用 G/O 标注域：

- **相对 0.8B 裸模型**：ScreenSpot-v2 79.33→88.41（**+9.08**）、ScreenSpot-Pro 36.42→45.92（**+9.50**）、OCRBench-v2 English 45.75→52.47（**+6.72**）、Chinese 43.45→53.22（**+9.77**）、CC-OCR 62.19→67.32、OmniDocBench 62.28→70.43，**六个目标全涨**。
- **相对最硬的对手 OPD**：ScreenSpot-Pro 40.82→45.92（**+5.10**）、CC-OCR +3.39、OmniDocBench +1.86、OCRv2-EN +1.68、ScreenSpot-v2 +1.07、OCRv2-ZH +0.77——而且**全面压过 SKD 和 Offline KD**，说明收益不是"做了蒸馏"就有，而是置信度干预机制带来的。
- **保留能力（防遗忘）**：RefCOCO 系列与 MMBench 上 CA-OPD（85.53/77.77/82.64/80.16）与 SFT 初始（85.63/78.08/82.44/79.16）基本持平，没有牺牲 OOD 泛化。
- **消融三连（Table 2）**：随机位置干预（同样 ~3.9% 改写率）只到 40.20，与 OPD 相当——**在哪儿改比改多少重要**；只做置信度门控但不真正写回前缀也只有 40.92——**必须真的修复轨迹**；固定阈值 44.58、反转调度 44.36、替换处用 KL 而非 CE 45.26，都低于完整版 45.92。
- **干预频率不是主因（Figure 2）**：把 SKD 改写率从 0.16% 拉到 3.41%，SS-Pro 只到 44.00，仍差 CA-OPD 1.92 分。而 CA-OPD 触发替换的提议在教师里**中位排名高达第 3、88%~100% 落在 top-25**——排名门控会放走这些"排名高但绝对支持不足"的错误。
- **分桶收益均匀（Table 3）**：按输出长度、初始水平、教师拒绝密度三层切分，CA-OPD 对 OPD 全部为正（如全对组保住 93.83 vs OPD 的 90.18、初始 96.03）。
- **稳定性**：无门控 OPD 在 SS-Pro 上 run 间标准差达 1.46，退火门控降到 0.72。

代价是训练每步约 59.3s，是无干预 OPD 的 1.5 倍（交错式教师查询的开销，门控本身几乎不花钱）。

## 4. 亮点与贡献（Why it matters）

1. **把把关标准从"排名"升级为"绝对置信度"**：论证了排名会系统性漏掉低绝对支持的错误提议，判断更贴近教师真实态度。
2. **首次把"干预决策"和"逐 token 监督"绑成同一个开关**：被改处给 CE、被留处给分布蒸馏，这一设计优雅且可解释。
3. **"从严格到宽松"的进度式放权**：比固定阈值更贴近教学直觉，并用消融证明方向对了才有效。
4. **实验纪律好**：多教师路由、统一预算、3 次独立运行取均值、消融把"位置/写回/调度/损失形式"拆得干净，结论可信度高。
5. **对 GUI 落地的直接价值**：0.8B 小模型在 ScreenSpot 系上逼近 9B 教师的水平，为端侧低成本 GUI grounding 模型提供了省算力的训练配方。

## 5. 局限与可改进点（个人点评）

- **对教师校准质量敏感**：整个门控建立在"NLL 能反映真实可靠性"之上，作者自己也承认域偏移时需重调下限。若教师和学生同病相怜（系统性偏差），这个过滤器会失真，文中没有给出自适应校准方案。
- **"改写即 CE"会单向信任教师**：被替换位置学生完全照抄教师 argmax，若教师在该处恰好也错，错误会被当成真理灌输。全文没讨论教师出错时的兜底。
- **验证面偏窄**：学生只有 0.8B、只训 471 步 / 1.5 万条数据；GUI 侧只做了 grounding 点选，没有端到端的多步操作成功率评估，很难说对完整 GUI Agent 的增益几何。
- **能力侵蚀只是缓解而非消除**：全对样本从 96.03 掉到 93.83，作者诚实报告了这一点，"保留能力不退化"的说法需要打折扣。
- **成本与实现门槛**：1.5× 训练开销来自分块逐位置查询教师；top-k 截断、clamp 等实现细节较多，未开源的情况下复现要费一番功夫（这也正是我们选择保守标注开源状态的原因）。

## 6. 对我们的启示 / 可借鉴点

- **"干预决策即监督信号"是可复用的设计模式**：在 RL / Online 微调里，判断"这条轨迹要不要信、要不要回滚"和"从这条轨迹里学什么"通常被拆成两套逻辑；CA-OPD 用一个开关耦合两者，减少超参面、增强一致性。做在线策略迭代时值得照搬这个思路。
- **筛选准则选绝对置信度而非排名**：凡是"用教师/奖励模型给候选打分再决定是否采纳"的环节（如 rollout 过滤、数据筛选），都可以检查是否只用了相对序而丢了绝对强度信息——后者在低质量长尾上往往更灵敏。
- **进度式放权 = 自动化的探索预算控制**：从严格到宽松的余弦阈值，比固定阈值更稳也更省心。在持续学习/在线适应场景里，可以类比地"早期多信旧策略、后期多信新数据"。
- **多教师按域路由**：GUI grounding 与 OCR 各配一个领域专家教师、样本按域路由，避免单一教师"全能但都不精"。做多模态 GUI Agent 的数据管线时可把"分域教师"当作默认选项。
- **把防遗忘写进评测**：RefCOCO/MMBench 这类 OOD 保留指标与目标指标同表报告，能及时发现"蒸馏猛如虎、回头忘光光"的陷阱——这也是我们后续评测可固化的闸口。

## 7. 延伸阅读

- **GKD**（Agarwal et al., ICLR 2024）：同策略蒸馏的奠基作，本工作的 OPD 基线。
- **SKD**（Xu et al., ICLR 2025）：交错采样蒸馏，本文"排名门控"的对比对象。
- **MiniLLM**（Gu et al., ICLR 2024）：用 reverse-KL 做生成式蒸馏，属"改损失面"的另一路线。
- **DAgger / Scheduled Sampling**：序列预测中"轨迹暴露"问题的经典解法，本文阈值退火与之精神相通。
- **ScreenSpot-v2 / OS-Atlas、ScreenSpot-Pro**：本文 GUI grounding 评测基准，做 GUI Agent 必知。
- **StepX-Edge**（Wang et al., 2026，参考文献）：同团队端侧 UI VLM 工作，可连读理解其部署动机。
