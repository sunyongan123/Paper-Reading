# OmegaUse-SOP: SOP Engineering for Professional Computer Use from Human Demonstrations

> TL;DR：把人类专家在专业软件（PVsyst）里的操作演示，"录制—翻译—配置—执行"变成可复用的 SOP 技能，让 GUI Agent 在专业流程任务上从 1~3/5 稳定到 5/5。

## 1. 研究背景与要解决的问题

大模型正在从"聊天助手"变成能直接操作电脑的 Agent：看屏幕、识别界面元素、用鼠标键盘完成真实任务。近几年通用 GUI Agent 进步很快，一条线是训练专门的视觉语言模型（UI-TARS、GUI-Owl、OmegaUse），另一条线是搭更聪明的框架（Agent S2、UFO2），评测上有 OSWorld 这样的桌面通用基准。

但作者指出一个被通用基准掩盖的短板：**专业软件里的"规范操作流程"（SOP）**。光伏设计、电力仿真这类场景中，能不能成功往往不取决于模型会不会点鼠标，而取决于它懂不懂一堆"屏幕上看不出来"的东西——领域隐含规则、软件自身约定（比如某个旋钮上下箭头各自代表什么）、验证习惯、以及每次任务不同的参数。近期 SOP-Bench、Workflow-GYM 等基准也证实：LLM Agent 在分支逻辑、阶段遗漏、错误传播、目标漂移上大量翻车。

打个比方：通用 GUI 评测像考"会用电脑"，专业 SOP 像考"会按行业规范办业务"。前者背熟界面即可，后者需要把老师傅脑子里的经验显式写出来并照做。作者的核心主张是：提升专业 GUI Agent 不能只靠更强的感知/动作模型，还得有机制**把专家的流程知识捕获下来、变成可复用的技能**——这就是本文提出的 "SOP Engineering"。

## 2. 核心方法 / 思路

SOP Engineering 是全文最关键的概念，作者刻意把它类比成 **Prompt Engineering**：写提示词时要反复加规则、约束、示例、格式要求；同样，做一个可用的 SOP 技能，也要对着真实环境迭代打磨"演示 + 执行规则 + 领域知识 + 任务参数"，直到 Agent 能稳定复现。系统叫 OmegaUse-SOP（是其前作 OmegaUse 通用 GUI Agent 在专业流程方向的延伸），由四个模块组成：

**① Observe（录制）**：专家在目标软件里做一遍示范，系统同时记录鼠标/键盘事件并截屏。关键设计是"动作前截图"——每次操作发生前先存一帧，保留人"先看到、再操作"的顺序证据。坐标类动作（单击/双击/右键）会用 OmniParser + PaddleOCRv5 解析出点击处的 UI 元素并裁出局部图；打字、快捷键等非坐标动作按功能聚合成语义事件（连续字符合成一次文本输入，Enter/Ctrl+C 单独记录）。产出是一份多模态"演示轨迹"。

**② Reason（翻译成语义）**：原始轨迹全是坐标和时间戳——坐标只能说明"点在哪里"，解释不了"点了什么、为什么点"，界面一变就废。Reason 用 VLM 结合"动作前截图 + 点击区域放大图 + 动作后截图"把每一步写成自然语言指令，例如把"在某处输入一串字符"写成"在项目名输入框输入项目名"，把 Ctrl+S 写成"配置完成后保存项目"。注意它**不做新的规划**，只做 grounding 式的语义补全，把演示从"像素坐标回放"升维成"可被未来界面理解的语义步骤"。

**③ Configure（注入专家知识）**：有些东西屏幕上看不出来（隐含惯例、校验习惯），于是提供两种人工可编辑上下文：一是**领域 SOP 指导**（domain SOP guidance），即专家写的执行规则——附录里给了两个真实例子：调"串联模块数"时点哪个方向的箭头、用户显式指定的参数（如倾角 35°）优先于历史值；二是**任务参数**，把演示里"会随任务变"的值（站点、数值、标识符）标记为变量，下次执行时替换成新任务的取值。这让技能可复用而非死板回放。

**④ Execute（执行 + 校验）**：专业 SOP 可能上百步，一次性把全部信息塞给模型会爆上下文。执行模块借鉴 Claude Code 的"技能调用"思路，**按当前步渐进式检索**相关信息（低层轨迹片段、语义理解、领域规则、任务参数）喂给模型，让其输出点击/输入/热键/滚动等动作。每步执行后做**结果校验**：拿当前屏幕与演示中"动作后"的期望屏幕对比并让模型判断是否继续，提示词被设计成容忍光标位置、时间戳等无害差异，只揪出真正偏离 SOP 的执行错误；一旦校验不通过，就进入**人在回路**：用户可选继续、重试或终止。

整体上，这套系统不试图用黑盒策略替代专家判断，而是提供一个"中间层"，把人的专业实践变成可视化、可编辑、可校验的技能。与简单坐标回放或固定宏自动化的本质差异就在于：加了语义描述、可变参数、领域规则和逐步验证四层"护栏"。

## 3. 关键实验结果

作者与电力行业客户合作，在光伏仿真专业软件 **PVsyst 7.2** 上做案例研究，覆盖来自客户真实工作流的 **5 个任务**：气象数据导入、平面朝向设置、并网系统设置、详细损耗设置、仿真执行（其中"详细损耗设置"要在多个子面板里配置热行为、欧姆损耗、老化等参数，最吃领域知识）。

评测 3 个视觉语言模型——开源权重的 **Qwen3-VL-235B-A22B-Instruct** 和闭源的 **GPT-5.5、Opus-4.7**，对比两种设置：基线（只给高层用户指令直接干活）vs SOP 引导（按 OmegaUse-SOP 生成的技能执行），每任务试 3 次取最优、由领域专家人工判定成败：

- **基线成功率**：Qwen3-VL 1/5，GPT-5.5 3/5，Opus-4.7 2/5——失败几乎都集中在需要专业流程知识的任务上。
- **加 OmegaUse-SOP 后**：三个模型**全部 5/5**，提升对所有模型一致。
- **消融实验**（Qwen3-VL）：去掉 Reason 模块、直接拿低层轨迹执行，成功率从 **5/5 掉到 2/5**（只剩朝向设置和仿真执行能过），证明"把演示翻译成语义步骤"这一环是系统成立的关键。

结论很直白：性能差距的主因不在模型"会不会用 GUI"，而在**流程知识的表示形式**——语义化、带校验的技能表示让最弱的开源模型也追平了最强的闭源模型。

## 4. 亮点与贡献（Why it matters）

1. **提出"SOP Engineering"方法论**：把"把专家演示变成可复用技能"这件事抽象成类似 Prompt Engineering 的迭代流程，概念清晰、易被社区接受和复用。
2. **端到端可落地的系统闭环**：Observe→Reason→Configure→Execute 覆盖从数据采集、语义抽象、知识注入到带校验执行的全链路，且天然支持人在回路调试。
3. **渐进式信息披露解决长流程问题**：仿照编码 Agent 的技能调用逐步骤取信息，避免上百步 SOP 撑爆上下文——对做长任务 Agent 是通用技巧。
4. **真实行业验证而非合成任务**：与电力客户合作、任务来自真实工作流，且对开源/闭源模型通用，说服力强于玩具 demo。
5. **消融给出了可迁移的经验**：坐标级行为克隆效果差（2/5），语义级步骤表示效果好（5/5），直接给做演示学习/模仿数据的人指了方向。
6. 开放了可执行演示包、演示视频与 HITL 开源实现，复现门槛低。

## 5. 局限与可改进点（个人点评）

- **评测规模与统计效力偏弱**：单软件（PVsyst）、单领域、5 个任务、3 个模型，每任务只试 3 次且取最优（best-of-3），成败由专家人工判定——无法回答"稳定性/方差"问题，也不排除过拟合到这几个界面。至少应报告多次运行的分布而非仅最优值。
- **"人在回路"的工作量没量化**：演示要专家录、规则要专家写、参数要专家标、失败要专家修。它本质上是把"教模型"的成本转移给了人。论文没给出"做一条 SOP 技能平均耗时多少、ROI 何时为正"，而这恰是企业最关心的。
- **Reason 的质量依赖所用 VLM**，语义步骤的粒度与正确性没有独立评测；若 Reason 模型把某步"翻译歪了"，错误会沿技能链传播，文中未见此类失败模式分析。
- **对界面变化/软件版本迁移的鲁棒性未知**：PVsyst 7.2 内窗口布局变化算被覆盖，但换软件版本、换皮肤、跨软件复用同一 SOP 是否还能 5/5，没有证据。
- **评价只到"任务完成"**，未核对产出质量（如仿真出来的发电量数字与专家结果是否一致）；对"逐步校验"只对比了屏幕外观，语义级正确性难以保证。
- 作为 10 页 preprint（含附录），缺少轨迹规模、Token/时间开销、成本对比等工程细节，复现更多靠仓库而非论文。

## 6. 对我们的启示 / 可借鉴点

- **流程显式化可能是专业 Agent 的第一性短板**：与其继续押注更强的 grounding/RL，不如先把"怎么做才算对"的专家知识结构化。对本项目关注 RL/Grounding 的路线，本文提示：数据层面先做"语义动作单元 + 专家规则"标注，再谈训练，效果可能更直接。
- **Reason 模块的消融（2/5 vs 5/5）是重要信号**：纯坐标/GUI 框行为克隆跨界面脆弱。做演示采集或模仿学习数据管线时，建议参考"动作前截图 + UI 解析交互目标 + VLM 补语义描述"的流水线，把目标表述成"对象+位置+意图"，可迁移性会显著更好。
- **Execute 的"逐步校验 + 人在回路"适合吸收为 Online 执行范式**：校验提示"容忍无害差异、揪出语义偏差"，配合 continue/retry/stop 三元干预，比让模型一口气跑完长流程稳健得多，且实现成本低。
- **渐进式信息注入**（按步检索而非全量塞上下文）是做长流程 Agent 的实用工程技巧，可直接借鉴。
- 若团队要自建"技能库"，Configure 里"领域规则 vs 任务参数"的二分法是一个简洁好用的技能描述 schema 起点。
