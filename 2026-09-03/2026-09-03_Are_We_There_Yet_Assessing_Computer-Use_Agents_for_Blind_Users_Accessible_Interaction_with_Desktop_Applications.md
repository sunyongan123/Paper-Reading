# Are We There Yet? Assessing Computer-Use Agents for Blind Users' Accessible Interaction with Desktop Applications

> 一句话 TL;DR：以 OLLA 无障碍外壳让 8 位盲人三周真实使用 CUA，收集 1258 条指令并跨 5 模型同题重放，成功率最高仅 52.5%，并解剖出 grounding/规划/约束/终止四类系统性失败。

## 2. 论文要解决的核心问题

- **要解决什么问题**：在**真实日常桌面工作流**里，评测计算机使用智能体（CUA）对盲人屏幕阅读器用户到底靠不靠谱、卡在哪一步、用户期望它扮演什么角色。对应三个研究问题 RQ1（有效性）/ RQ2（失败点）/ RQ3（超越自动化之外的期望）。

- **为什么重要**：盲人靠 NVDA/JAWS 逐行"听"界面，操作是键盘顺序式的，与 GUI 的"看见即点到"空间布局天然错位。CUA 若能听懂一句"把这段加粗居中存成 PDF"就执行，理论上能极大消除这一鸿沟；但若可靠性未知就贸然部署，会让本就脆弱的非视觉交互雪上加霜——论文用数据说明它**能做完一部分，但远不够可靠**。

- **现有方法有什么不足**：论文明确批评两条线。其一，主流 benchmark（OSWorld、Windows Agent Arena、WebArena）用的是 **well-formed prompt + 受控初态 + 可测终点**，本质是"考试"而非"日常"：既不捕捉盲人如何措辞下指令，也不提供足够的 step-by-step 证据去解剖失败如何一步步发生。其二，已有的无障碍 CUA 研究（Gubbi Mohanbabu et al. 2026、Peng et al. 2025）大多依赖**模拟评测、persona prompting 或实验室窄任务**，没有真实用户的纵向使用。

- **Research Gap**：作者声称补上的是"真实世界非视觉工作流下 CUA 有效性/失败模式/用户期望"这三者的实证空白——用一个 IRB 批准的、为期三周的纵向 diary study，把"真人出的考卷"同时发给多个模型同题重放，并逐层解剖失败轨迹。

## 3. 方法核心思想（三层拆解）

### 3.1 一句话概括方法

给 CUA 套一层屏幕阅读器可访问的外壳 OLLA，让盲人真实用三周 → 收集的指令原样重放给另外 4 个模型 → 对失败轨迹做定性归因。

### 3.2 方法总览（Pipeline）

- **输入**：参与者的自然语言命令 + 每步的**截图** + **Microsoft UI Automation 树**（控件 label/role/hierarchy/坐标）+ 近期交互历史。
- **输出**：模型给出简短 rationale + 结构化 JSON 动作（action type、目标控件 label、role、坐标 x/y/w/h、text），判定完成时输出 `done`。
- **模块与连接**：OLLA 走的是经典的 **perceive-reason-act 循环**——全局热键唤起 → 提取截图与 UI 树 → 连同命令与历史送 LLM → 模型产出 JSON 动作 → 经 UI Automation 执行（点击/输入/滚动/选择）→ 语音反馈 → 回到观测。日志经 LangSmith 记录，并用有界交互 buffer 让后续动作条件化于近期上下文。**关键点：OLLA 只包在外层，不改底层 agent 的架构与推理**，所以同一管道可无缝替换 5 个模型做公平对比。

### 3.3 真正的创新点（去伪存真）

- **真·方法创新**：① **OLLA 无障碍交互层**——把"视觉媒介"的 CUA 改造成屏幕阅读器可操作、可非视觉监控的系统，且不改底层推理；② **human-centered 数据集 + 跨模型同题重放协议**——用真人措辞、真实初态、统一执行器做公平对比，这是 OSWorld 系做不到的。
- **工程组合**：perceive-reason-act 循环、截图+UI 树双模态、LangSmith 日志、Krippendorff α 标注——都是已有组件，本身不新。
- **对结论最关键的设计**：**UI 树 + 截图的组合**（语义结构补足纯截图的 OCR/坐标 grounding 缺陷），以及**统一 OLLA 管道排除混淆变量**（命令/系统提示/动作 schema/执行器全固定，只换模型）。
- **证据不足 / 仅声称有效**：① 数据集**声称可获取但未给直链**，可复现性存疑；② 第 7.2 节建议的 reward 信号（goal progress、相关控件发现、去重动作、约束保持）**没有任何实验验证**，纯属推论。

## 4. 具体技术细节

### 4.1 模型结构

本文**不训练、不微调**，评测 5 个现成模型，均为 **MLLM**（多模态，含视觉编码器，接收截图 + 文本输入）：

- 闭源：`gpt-5-2025-08-07`、`claude-sonnet-4-6`（Anthropic Computer Use）、`gemini-2.5-computer-use-preview-10-2025`；
- 开放权重：`ByteDance-Seed/UI-TARS-1.5-7B`（7B 专用 GUI agent）、`Qwen/Qwen3-VL-8B-Instruct`（8B 通用视觉语言模型）。

所有模型最大输出长度 2048 tokens，全部冻结推理。

### 4.2 训练流程

**本文不训练**（用户研究 + 多模型黑盒评测）。无任何 SFT/RL 阶段。

### 4.3 推理流程

**多步推理**。OLLA 运行的是迭代的 perceive-reason-act 循环：每步把"命令 + 截图 + UI 树 + 近期历史"送模型，模型输出 rationale + JSON 动作，经 UI Automation 执行后重新观测界面。**终止条件**为模型显式返回 `done`；失败往往正发生在这——模型该停不停、重复无意义动作（见 §5.2）。推理输入/输出与 3.2 一致。跨模型重放时，每条命令都在**全新的干净应用实例**中独立执行，防止"吃别人进度"。

## 5. Benchmark 与实验设置

### 5.1 Benchmark 一览表

| Benchmark | GUI 场景 | 任务类型 | 数据规模 | 输入格式 | 输出格式 | 评测指标 |
|---|---|---|---|---|---|---|
| 自建（OLLA 日志 + 跨模型重放，非公开标准基准） | Desktop | 8 类真实办公任务：文档编辑 24.0%、表格操作 17.0%、应用配置 12.2%、界面导航 11.0%、演示编辑 10.2%、文件管理 10.0%、故障排查 9.7%、媒体播放 5.9% | 1,258 条命令 / 304 归一化任务意图（覆盖 12 应用，Word 210 居首） | 自然语言命令 + 截图 + UI Automation 树 + 交互历史 | 结构化 JSON 动作（类型/控件/坐标/文本）+ done | 成功率、partial/failure 占比、StepProgress（失败前参考步骤完成比例）、失败模式占比、标注一致性 Krippendorff α=0.84 |

### 5.2 实验结果分析

**主结果（N=1,258）**：GPT-5 成功率最高 **52.5%**（95% CI 49.8–55.3%），Claude Sonnet 48.5%，Gemini 2.5 CU 43.9%，UI-TARS 39.8%，Qwen3-VL 37.9%。但 GPT-5 对第二名的 **4.0 个百分点优势在配对 McNemar 检验中不显著**（χ²=3.25, p=.071）——头两名实质"并列垫高"。Partial 完成率各模型约 1/3（33.3%–34.9%）；**StepProgress** 显示 partial 轨迹失败前平均已走完 68.3%（GPT-5）到 53.0%（Qwen3-VL）的参考步骤，说明"快做完但最后一脚没踩对"是常态。

**失败模式占比（RQ2 诊断）**：这是全文最有价值的"诊断性结果"，替代了传统 ablation——它直接告诉读者钱该花在哪：
- **UI grounding**：幻觉控件名/类型/坐标对不上，全模型失败轨迹中占 22.6%（789/3489）；
- **隐藏路径发现**：能点"窄边距"却不会开"自定义边距"对话框，占 20.7%（722/3489）；
- **先验知识压过现场观察**：把 Word 流程套到 OneNote、忽略界面已暴露的控件，learned-procedure 9.6% + default-collapse 6.5%；
- **约束绑定**：改 Arial 忘字号 14，partial 轨迹中占 22.4%（481/2148）；
- **终止识别**：Excel 反复建 sheet 或走到"另存 PDF"不点保存，partial 轨迹中占 19.1%（410/2148）。

**它说明了什么**：失败不是模型"不会"，而是**暴露在眼前的控件能点、需要中间导航/开对话框/保多约束/判终态就崩**。这直接指向三条可落地的改进：显式约束清单、过程级奖励、终止/死循环判定器——对做 RL 训练与 planning 的人，这是一份带占比的改进清单。

## 6. 亮点与贡献（Why it matters）

1. **填补"实验室 vs 真实"的鸿沟**：首个以盲人真实日常桌面使用为基础的 CUA 纵向实证，用数据证明 OSWorld 这类受控基准会**高估**真实（尤其无障碍）场景的能力——基准分数 ≠ 现实可用性，这对所有 GUI Agent 从业者是一记清醒剂。
2. **可复用的"真人考卷"**：1,258 条真实盲人指令 + 带截图的逐轮执行轨迹 + 标注，OLLA 代码开源，为后续训练/评测提供了脱离 benchmark 模板措辞的压力测试素材。
3. **带占比的失败归因清单**：把"agent 不行"拆成 grounding、隐藏路径、先验依赖、约束跟踪、终止识别等可操作类别，每类有数字、有具体 trace，直接可翻译成工程改进方向。
4. **为 reward/feedback 设计指明信号**：明确建议 reward 应纳入目标进度、相关控件发现、重复动作惩罚、约束保持与"对难验证操作保持谨慎"，是给 RL 训练者的免费设计草案。
5. **矫正产品定位**：用访谈证据说明辅助场景的 CUA 应是"混合主动权 + 解释 + 可撤回"的协作者，而非黑箱包办。

## 7. 局限与可改进点（个人点评）

- **样本与外部效度**：8 位参与者、自选任务、鼓励每天 ≥10 条，成功率本质是**"用户愿意交给 agent 的任务"的条件成功率**。访谈承认用户回避银行/密码等敏感任务、失败几次后不再尝试同类任务——真实难度分布未知，52.5% 可能偏乐观也可能偏悲观；每日保底指令量还可能混入"凑数"的简单操作。
- **对比公平性的混淆变量**：所有模型都被塞进 OLLA 的"截图 + UI 树 + 统一 JSON"管道，未必是各自主场；且 UI-TARS-1.5-**7B**、Qwen3-VL-**8B** 与闭源旗舰比，**参数量这个混淆变量全程没讨论**。论文说"不宜当排名"是对的，但表格数字极易被读者误读为排名。
- **技术范围窄**：仅 Windows + Microsoft UI Automation 暴露的 UI 树（macOS 无障碍树不完整时结论可能反转）、仅英文、仅桌面应用、仅 5 个时间快照模型；**web 动态渲染（DOM 与屏幕不一致）恰好是 grounding 失败高发区，却被排除在外**。
- **失败责任归属模糊**：OLLA 的语音反馈是延迟的，盲人无法像明眼人一样实时盯屏纠偏，这会放大 agent 错误；论文把多数失败算在 agent 头上，但"无障碍交互层带来的额外信息损失"占比多大**没有剥离**。标注参考步骤本身也有主观性。

## 8. 对我们的启示 / 可借鉴点

本篇是 **GUI 落地评测**，直接写启示：

- **评测设计学"真人生成指令 + 同题重放"**：把一组真实用户指令固化为考卷，多模型在同一管道/同一初态/同一标注协议下对比，比各跑各的 benchmark 更干净；"用户措辞不标准"正是压测 grounding 的好素材。可直接借鉴其 304 意图归一化与 α=0.84 的多人标注流程。
- **给 grounding/planning 造"隐藏路径"压力测试**：可见选项能点、深层对话框就迷路的模式说明，评测任务应刻意区分"表面操作"与"需要中间导航/开对话框"的孪生任务对（窄边距 vs 自定义边距），这能暴露纯截图 grounding 的短板。
- **过程级信号优于结果信号**：partial 平均走了 68% 步骤仍判失败，意味着只看"最后成没成"的 reward 对这类任务几乎无梯度。RL/Online 训练应引入过程奖励（约束保持、去重动作、状态变化检测），尤其需要**显式的终止/死循环判定器**——这是可工程化的高性价比改进。
- **显式约束清单 + 跨应用状态记忆**：Arial+14、Excel 复制到 Word 这类多约束/跨应用失败提示：agent 内部应维护"未满足的用户约束 checklist"和"活动文档/来源-目标"记忆，而不是把一切押在隐式上下文里——这是对 planning 模块最直接的落地项。
- **人机协作层值得独立做**：把"执行前解释、执行中可确认、失败后可教学"做成 CUA 上层的混合主动权壳（类似 OLLA），既服务盲人，也通用地缓解"高风险动作不可撤销"的信任问题。

## 9. 延伸阅读

- OSWorld（Xie et al. 2024）/ Windows Agent Arena（Bonatti et al. 2024）：文中对比的通用桌面 CUA 基准，可对照其"受控初态"与本文"真人初态"的差异。
- A11y-CUA（Gubbi Mohanbabu et al. 2026）：从辅助技术交互条件刻画 CUA 无障碍差距的数据集。
- BLIND-ACT（Shayegani et al. 2025）：从"指令不可行/含糊/不当"角度评测 CUA 的目标盲目性。
- Online-Mind2Web（Xue et al. 2025）：证明离线基准在真实在线场景会高估 CUA 能力的姊妹工作。
- Kodandaram et al. 2024：作者前序 LLM 驱动的非视觉桌面支持系统，OLLA 的 UI-tree 表示即承袭于此。
