# Are We There Yet? Assessing Computer-Use Agents for Blind Users' Accessible Interaction with Desktop Applications

> 让 8 位盲人屏幕阅读器用户在日常办公中真实使用计算机操作智能体（CUA）三周，收集 1258 条指令与执行轨迹，评测 5 个主流模型——最高成功率仅 52.5%，系统失败集中在定位、规划与状态跟踪，用户真正想要的是"教练型陪练"而非"全自动代工"。

## 1. 研究背景与要解决的问题

GPT-5、Claude 的 Computer Use、Gemini 2.5 CU、UI-TARS 这类"计算机使用智能体"（CUA）已经能看屏幕、点按钮、敲键盘，像个"会操作电脑的实习生"。多数评测（OSWorld、Windows Agent Arena、WebArena 等）给它一个干净任务、一句完整指令，看它能不能跑通——类似考试。但这些评测有个共同盲区：**真实用户，尤其是盲人用户，到底怎么用、好不好用，几乎没人知道**。

盲人日常靠 NVDA/JAWS 这类屏幕阅读器逐行"听"界面，操作是键盘顺序式的，和鼠标"看见即点到"的图形界面天然错位。CUA 若能听懂一句"帮我把这段加粗、居中、存成 PDF"，理论上能极大解放他们。此前研究多用模拟评测、用"扮演盲人"的提示词，或在实验室做窄任务，**真实世界里 CUA 对盲人到底靠不靠谱、卡在哪一步、盲人自己期望它扮演什么角色**，是三个没人回答的问题（对应文中的 RQ1/RQ2/RQ3）。

## 2. 核心方法 / 思路

论文的思路可概括为三步：**让盲人真的用 → 原样重放给别的模型 → 解剖失败轨迹**。

**(1) OLLA：给 CUA 加一层"无障碍外壳"。** 现有 CUA 界面依赖看截图、盯光标，盲人无法直接操作，所以作者做了 OLLA——它不改底层智能体的任何推理，只在外面包一个屏幕阅读器可访问的交互层：用户按全局热键唤起、用自然语言下指令，OLLA 每一步抓"截图 + UI 树（Microsoft UI Automation 提供的控件语义结构）"，连同用户指令与近期历史喂给模型，模型输出结构化 JSON 动作（类型、控件名、坐标、文本），由 OLLA 执行，再用语音反馈进度。类比：OLLA 像一个"盲文仪表盘"，让盲人能坐进一辆自动驾驶汽车并知道车在干什么。

**(2) 三周日志研究（diary study）。** 8 位使用 JAWS/NVDA 的盲人（24–68 岁、自评新手到专家）在自己电脑上装 OLLA，日常办公照常进行，三周内共发出 **1258 条真实指令**，覆盖 **12 个桌面应用**（Word 210 条居首，其次 Excel、PowerPoint、OneNote、Outlook、文件资源管理器等）和 **8 类任务**（文档编辑 24%、表格操作 17%、应用配置、界面导航、演示编辑、文件管理、故障排查、媒体播放）。每条指令都留存完整证据链：截图、UI 树、模型回复、动作、历史。指令被人工归一为 304 个任务意图（平均每个意图被不同措辞重复了 4.14 次）。期间部署统一用 GPT-5，保证体验一致。

**(3) 跨模型重放对比。** 为了公平比较，作者把 8 位用户发出的同一条条真实指令，原样喂给另外 4 个模型——Claude Sonnet、Gemini 2.5 CU、UI-TARS、Qwen3-VL——每次都在全新的干净应用实例里执行，避免"吃别人进度"。命令、提示词、动作格式、执行器全部固定，只有模型不同。这是把"真人考卷"发给 5 个"考生"做同题对比。

**(4) 失败轨迹解剖。** 4 名标注员先手工执行任务确定"参考步骤"，再给每条执行结果打成功/部分/失败标签（标注一致性 Krippendorff α=0.84），并按类别统计失败原因；辅以对执行日志的逐层细读与访谈主题分析。

## 3. 关键实验结果

**成功率：最好的也只刚过半。** GPT-5 最高 **52.5%**（661/1258，95% CI 49.8–55.3%），Claude Sonnet 48.5%，Gemini 2.5 CU 43.9%，UI-TARS 39.8%，Qwen3-VL 37.9%。注意 GPT-5 对第二名的 4 个百分点优势在配对 McNemar 检验里**并不显著**（p=.071）——头两名实际是"并列垫高"。此外每模型约 1/3 指令是"部分完成"：**GPT-5 在失败前平均已走完 68.3% 的必需步骤**（Qwen3-VL 也有 53.0%），说明"快做完了但最后一脚没踩对"是常态，而非完全不会。

**系统性失败（RQ2），按占比排序：**
- **UI 定位失真（22.6% 失败轨迹）：** 幻觉不存在的控件名/类型，或坐标对不上——功能区和隐藏面板是重灾区。例：把"保护文档"放进 Home 选项卡，实际在 Review 下。
- **隐藏路径发现失败（20.7%）：** 能改"窄边距"，但"自定义边距"要开对话框填参数就做不了；"插入 15×15 表格"停在可见网格上限，不懂点"自定义表格"。
- **约束丢失（部分完成轨迹中占 22.4%）：** 说好"改 Arial 且字号 14"，只改了字体忘了字号；页脚页码忘了居中。
- **终止行为失能（部分完成轨迹中占 19.1%）：** 该停不停、重复无意义动作——Excel 里反复点"新建工作表"制造了一堆多余 sheet，或走到"另存为 PDF"最后一步不点保存。
- 另有先验知识压过现场观察（把 Word 的操作流程套到 OneNote）、跨应用协作断链（Excel 复制了却忘记切到 Word 粘贴）等。

**访谈（RQ3）：盲人要的不是"全自动"。** 用户明确说"可能不想让它替我做完全部"（P6）；更想要：做事前解释界面内容帮我决策、卡住时告诉我"你在哪、有哪些选项、下一步做什么"、点重要按钮前先征求同意（"不想让它自己拿主意"）、以及把操作流程拆解成可学的步骤（"讲明白我下次就能自己来"）。一句话：**他们要的是看得懂、可叫停、能教人的陪练，而不是黑箱包办。**

## 4. 亮点与贡献（Why it matters）

1. **填补"实验室 vs 真实"的鸿沟**：首个以盲人真实日常桌面使用为基础的 CUA 纵向实证，指出 OSWorld 这类受控基准对真实（尤其无障碍）场景会高估能力——这提醒所有 GUI Agent 从业者：基准分数≠现实可用性。
2. **可复用的人本数据集**：1258 条真实盲人指令 + 带截图的逐轮执行轨迹 + 标注，代码（OLLA）开源，为后续训练/评测提供了"真人出的考卷"。
3. **给出失败归因清单和量化**：把"agent 不行"拆成定位、隐藏路径、先验依赖、约束跟踪、终止识别等可操作类别，每类带占比与具体 trace——直接可翻译成改进方向。
4. **为奖励/反馈设计指明信号**：文中明确建议 reward 应纳入目标进度、相关控件发现、重复动作惩罚、约束保持与"对难验证操作保持谨慎"，对做 RL 训练的人极具参考价值。
5. **矫正产品定位**：用证据说明辅助场景的 CUA 应是"混合主动权 + 解释 + 可撤回"的协作者，为盲人可访问 AI 交互设计立了标杆。

## 5. 局限与可改进点（个人点评）

- **样本与外部效度**：8 位参与者、自选任务、鼓励每天 ≥10 条，成功率本质是"用户愿意交给 agent 的任务"的条件成功率；访谈也承认用户会回避银行/密码等敏感任务、失败几次后干脆不再尝试同类任务——真实难度分布是未知的，52.5% 可能偏乐观也可能偏悲观。要求每日保底指令量也可能混入"凑数"的简单操作。
- **对比公平性存疑**：所有模型都被塞进 OLLA 的"截图+UI 树+统一 JSON 动作"管道，这未必是每个模型的主场；且 UI-TARS-1.5-7B、Qwen3-VL-8B 是 7B/8B 级开放模型，与闭源旗舰比能力差距时"参数量"这个混淆变量没有讨论。结论说"不宜当排名"是对的，但数字容易被读者误读为排名。
- **技术范围**：仅 Windows + Microsoft UI Automation 暴露的 UI 树（macOS 无障碍树不完整时结论可能不同）、仅英文、仅桌面应用、仅 5 个时点快照模型——web 动态渲染（DOM 与屏幕可能不一致）恰好是 grounding 失败的高发区，却被排除在外。
- **失败责任归属模糊**：OLLA 的语音反馈是延迟的，盲人用户无法像明眼人一样实时盯屏幕纠偏，这本身会放大 agent 错误——论文把多数失败算在 agent 头上，但"无障碍交互层带来的额外信息损失"占比多大没有剥离。标注参考步骤也有一定主观性。

## 6. 对我们的启示 / 可借鉴点

- **评测设计学"真人生成指令 + 同题重放"**：把一组真实用户指令固化为考卷，多模型在同一管道/同一初态/同一标注协议下对比，比各跑各的 benchmark 更干净——且"用户措辞不标准"正是压测 grounding 的好素材。可直接借鉴其 304 意图归一化与 α=0.84 的多人标注流程。
- **给 grounding/planning 造"隐藏路径"压力测试**：可见选项能点、深层对话框就迷路的模式说明，评测任务应刻意区分"表面操作"与"需要中间导航/开对话框"的孪生任务对（如窄边距 vs 自定义边距），这能暴露纯截图 grounding 的短板。
- **过程级信号优于结果信号**：部分完成平均走了 68% 步骤仍判失败，意味着只看"最后成没成"的 reward 对这类任务几乎无梯度。RL/Online 训练应引入过程奖励（约束保持、去重动作、状态变化检测），尤其需要显式的"终止/死循环"判定器——这是可工程化的高性价比改进。
- **显式约束清单与跨应用状态**：Arial+14、Excel 复制到 Word 这类多约束/跨应用失败提示：agent 内部应维护一份"未满足的用户约束 checklist"和"活动文档/来源目标"记忆，而不是把一切都押在隐式上下文里——这对我们做规划模块是最直接的落地项。
- **人机协作层值得独立做**：把"执行前解释、执行中可确认、失败后可教学"做成 CUA 上层的混合主动权壳（类似 OLLA 的思路），既服务盲人，也通用地缓解"高风险动作不可撤销"的信任问题。
