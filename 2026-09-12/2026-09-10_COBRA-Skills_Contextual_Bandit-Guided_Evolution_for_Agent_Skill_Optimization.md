# COBRA-Skills: Contextual Bandit-Guided Evolution for Agent Skill Optimization

> 一句话 TL;DR：把"技能（skill）优化"建模成预算受限的序列决策——用神经奖励预测 + LinearUCB 挑优先级最高的技能去执行，再按执行证据做种群演化；成本比 SkillOpt 低 55–58%，每个 benchmark 只用 50 条优化样本。

## 2. 论文要解决的核心问题

- **要解决什么问题**：在**少量任务样本 + 有限执行预算**下自动构造并优化"agent skill"（可复用的过程性知识文本），使其注入上下文后稳定提升下游表现；横跨问答、表格、文档、数学、社会推理与具身决策六类任务。
- **为什么重要**：skill 让同一模型**不改权重**就能复用历史经验；若获取它必须靠大量评测试错，它在成本上打不过直接换一个更强的模型。
- **现有方法的不足**：①**候选评估昂贵**——必须真跑一遍才知道好坏；②**精修昂贵**——反复调用 LLM 分析轨迹、重写 skill；③纯凭参数知识生成易产出无法落地的指导。
- **Research Gap**：缺"有限算力下**如何选择性分配候选评测、并高效复用执行证据**"。论文把两件事拆开：bandit 决定"评测分配给谁"（候选是语义嵌入描述的臂，目标 agent 表现为奖励），演化解决"候选空间本身在变"。

## 3. 方法核心思想（三层拆解）

### 3.1 一句话概括方法

维护固定大小 skill 种群，用"神经奖励预测 + LinearUCB 不确定性奖励"给每个 skill 打优先级，每轮只评测分数最高的那一个；每隔若干轮按累计证据用三种演化算子生成新 skill，并用同一分数剪掉低优先级 skill。

### 3.2 方法总览（Pipeline）

- **输入/输出**：优化集 D_opt（每基准 50 条）、初始轨迹 T_0、初始种群 P_1、轮数 T、演化参数 d 与 η → 历史平均奖励最高的 skill s*。
- **流程**：①**打分**（嵌入 z_s=φ(s)，φ 固定为 Qwen3-Embedding-4B；MLP f_θ 预测奖励 + 置信奖励 b_t=ν√(z_sᵀA_{t-1}^{-1}z_s)，A_{t-1}=λI+Σzzᵀ；取 U_t(s)=f_θ+b_t 的 argmax）→ ②**目标评测**（在 D_opt 上执行，得 r_t 与轨迹 T_t）→ ③**在线更新**（A_t←A_{t-1}+zzᵀ，全历史重拟合 f_θ）→ ④**定期种群更新**（剪最低分 skill，空位由再生/rollout 变异/交叉填充）→ ⑤**最终选择**。
- **关键约束**：新 skill **不继承任何奖励**，必须重新进入评测循环；分数只来自目标 agent 实际执行。

### 3.3 真正的创新点（去伪存真）

**真·方法创新**
- **形式化为"候选空间动态演化的预算受限序列优化"**：候选效用只能靠昂贵评测揭示，且候选集合每轮在变——"该评谁"与"该生成谁"需在同一循环内决定。
- **语义嵌入作臂特征以实现跨 skill 奖励迁移**：一次评测可外推到"语义相近但从未评测过"的 skill；纯 UCB 或纯进化搜索做不到，也是 50 条样本够用的根本原因。
- **同一分数兼作评测分配与种群保留**：探索不足的 skill 因 UCB bonus 较大而不被误剪，避免过早收敛。

**工程组合**：2 层 MLP + LinearUCB、以及再生/变异/交叉算子，都是现成组件的拼接。

**对性能最关键的设计**：**证据接地的再生是最大单一贡献来源**——LLM Skill 基线（同样再生初始化、之后不优化）已把平均分从 60.4/30.0/46.4 提到 66.2/48.3/55.2，COBRA 再加 +7.3/+8.6/+13.7pp。**bandit 与演化互补**：去 bandit −2.2pp、去演化 −2.4pp、Best-of-30 −2.5pp，说明增益不是"多生成候选再挑最好"。

**证据不足/仅声称有效**：三种演化算子未单独消融（交叉启用条件是硬编码的"评测过 >8 个 skill"，无敏感性分析）；消融幅度与标准误（w/o Bandit ±1.5）重叠，无显著性检验；"50 条样本"只对基线更大的池子成立，COBRA 目标模型 token 反而更多。

## 4. 具体技术细节

### 4.1 模型结构

不训练目标模型权重：Qwen3.6-35B-A3B、GPT-5.4-Nano、Gemma-4-26B-A4B-it 全部冻结且关闭显式推理。唯一"可学习"部件是 2 层 MLP f_θ（ReLU 隐层 + 标量输出），输入为 skill 的固定语义嵌入（φ=Qwen3-Embedding-4B）；教学模型 GPT-5.5。

### 4.2 训练流程

**不训练（不更新任何模型权重）**；被优化的是 skill 文本，唯一做梯度更新的是奖励预测 MLP，且为在线增量拟合。

| 阶段 | 目标 | 训练什么能力 | 数据来源 | 数据形态 | 目标 / Loss |
|---|---|---|---|---|---|
| Stage 0 初始化 | 构造 P_1 | — | T_0 | 轨迹文本 | 逐次施加再生算子（M_teach），**不继承奖励** |
| Stage 1 每轮打分 | 决定评测谁 | 奖励预测 + 探索 | H_{t-1} | skill 嵌入 z_s | U_t(s)=f_{θ_{t-1}}(z_s)+ν√(z_sᵀA_{t-1}^{-1}z_s)；ν=0.1、A_0=λI |
| Stage 2 目标评测 | 获取真实效用与轨迹 | — | D_opt（每基准 50 条） | 轨迹 + 标量奖励 | (r_t,T_t)←EVALUATE(s_t,D_opt)；分数只来自目标 agent |
| Stage 3 预测器更新 | 跟踪真实奖励 | 神经奖励回归 | H_t（(s_i,z_i,r_i)） | 嵌入-奖励对 | L(θ)=(1/\|H_t\|)Σ(f_θ(z_i)−r_i)²+β‖θ‖²₂，每轮全历史重拟合；A_t←A_{t-1}+zzᵀ |
| Stage 4 定期演化（t−t_last≥d=3 且 log(t/t_last)≥η=0.35） | 更新候选空间 | — | H_t、T_0、s_t 及 T_t | 新 skill 文本 | 剪掉 m=3 个最低分 skill；空位由再生/rollout 变异/交叉填充（交叉需 >8 个已评测 skill） |
| Stage 5 最终选择 | 输出 skill | — | H_T | — | 返回 H_T 中平均奖励最高的 skill |

> T=30 轮，种群 K=10，超参跨模型与基准固定；每次被评 skill 在全部 50 条优化样本上执行。

### 4.3 推理流程

- **模型**：冻结的目标模型（三选一）+ 最终选出的单个 skill；输入任务实例 + skill 文本，输出答案或动作。
- **单步/多步**：混合。SpreadsheetBench 与 ALFWorld 是**多轮**（≤30 turn），其余单轮。
- **测试期自适应**：无——skill 在 held-out 上**冻结使用**。除 SocialMaze 用官方软分（0/0.5/1）外均为二值准确率，取 3 次运行均值 ± 标准误。

## 5. Benchmark 与实验设置

### 5.1 Benchmark 一览表

| Benchmark | GUI 场景 | 任务类型 | 数据规模 | 输入格式 | 输出格式 | 评测指标 |
|---|---|---|---|---|---|---|
| SearchQA | General（检索） | 单轮问答 | 测试 100 / 优化 50 | 问题+检索上下文 | 答案 | 二值准确率 |
| SpreadsheetBench | Desktop（电子表格） | 多轮（≤30 turn）表格操作 | 测试 100 / 优化 50 | 指令+表格 | 操作序列 | 二值准确率 |
| DocVQA | General（文档） | 单轮文档问答 | 测试 100 / 优化 50 | 文档图像+问题 | 答案 | 二值准确率 |
| LiveMath | General | 单轮数学推理 | 测试 100 / 优化 50 | 数学题 | 数值/表达式 | 二值准确率 |
| SocialMaze（HRD） | General（社会推理） | 单轮角色推理 | 测试 100 / 优化 50 | 情境描述 | 角色判断 | 官方软分 0/0.5/1 |
| ALFWorld | General（具身） | 多轮（≤30 turn）决策 | 测试 100 / 优化 50 | 观测+目标 | 动作序列 | 二值准确率 |
| 外部 harness | — | 同上 | 同上 | 同上 | 同上 | 同上（Claude Code / Codex） |

基线：No Skill、LLM Skill（同样再生初始化后不优化）、Trace2Skill（从轨迹归纳）、SkillOpt（用目标 agent 反馈迭代）。

### 5.2 实验结果分析

- **主结果（六基准平均）**：三个目标模型均最高——Qwen3.6-35B-A3B **73.5%**（基线 60.4%，+13.1pp；SkillOpt 69.6%），GPT-5.4-Nano **56.9%**（基线 30.0%，+26.9pp；SkillOpt 53.7%），Gemma-4-26B-A4B-it **68.9%**（基线 46.4%，+22.5pp；SkillOpt 67.6%）。
- **成本与样本效率**：总成本相对 SkillOpt 降低 **55%–58%**，每提升一分的成本降低 **60%–69%**，每 benchmark 只用 **50 条唯一优化样本**；教学 token 少用 67%–80%，目标 token 略升。
- **逐基准不均衡**：LiveMath 增益最大（Qwen 32.3→55.3）；SearchQA 上 COBRA（84.3）**低于** SkillOpt（86.3）；DocVQA 上 GPT-5.4-Nano 从 30.0 提到 70.7。
- **泛化与迁移**：同一套 Qwen 演化的 skill 在 Claude Code 下 68.2、Codex 下 72.4，均为同 harness 最高；教学模型换成目标模型自己，平均分只从 73.5 降到 72.5；36 个组合中 **34 个**超过评测模型的无 skill 基线。
- **Ablation**：完整 73.5%；去 bandit 71.3%（−2.2）、去演化 71.1%（−2.4）、Best-of-30 71.0%（−2.5）。**"评测分配"与"候选空间演化"互补，增益不能由"多生成候选再挑最好"解释**。探索系数 ν=0.1 时最优（73.5%，ν=0.03/0.06/0.2/0.3 为 69.8/70.8/71.1/70.8）。

## 6. 亮点与贡献（Why it matters）

1. **正面拆开"经验复用"的成本问题**：区分"评测贵"与"精修贵"并各配机制；省的不是评测次数（反而更多），而是把教学模型从"反复读轨迹重写 skill"中解放出来。
2. **语义嵌入做跨候选奖励外推**：让"评测一次、受益一片"成立，是 50 条样本能跑通的关键。
3. **同一分数用于评测与剪枝**：探索不足的候选因 UCB bonus 免于被剪，避免"没评过→被剪→永远评不到"的死循环。

## 7. 局限与可改进点（个人点评）

- **消融幅度接近噪声**：−2.2/−2.4/−2.5pp 与标准误（最大 ±1.5）重叠，无配对检验；100 条样本、3 次运行下可能只是波动。
- **叙事被自己的基线削弱**：LLM Skill 已拿到 66.2/48.3/55.2，COBRA 的增益有相当大一块来自**初始化**而非优化机制。
- **逐基准不均衡未被讨论**：SearchQA 上输给基线，LiveMath/DocVQA 上大幅领先；"简单任务优化空间小"只是猜测，未做分层分析。
- **成本结论对 token 单价敏感**：优势建立在"教学 token 贵、目标 token 便宜"上；若目标模型本地部署而教学按量计费，结论会反转。
- **"50 条 vs 更大池子"未对齐，skill 工程属性也缺失**：基线池子规模未报告，也没做"基线也用 50 条"的对照；skill 长度、上下文开销、提示注入风险均未报告。

## 8. 对我们的启示 / 可借鉴点

- **把"经验资产"的优化当预算分配问题**：任何可枚举候选（prompt、skill、工具描述、检索策略）都可用"嵌入 + 奖励预测 + UCB 奖励"打分，**只评测最高分的那个**，比逐个跑或随机抽样都省；回归器每轮用**全部历史**重拟合而非 SGD 增量。
- **让同一分数承担评测与淘汰两个职责**：只用预测奖励剪枝会剪掉探索不足的候选；加 UCB bonus 后，"没评过"本身就是保留理由。
- **把成本结构当设计目标**：真正的杠杆是把贵的模型调用从"每个失败一次"降到"每轮一次"。

### 对 GUI Agent 的可借鉴点

1. **GUI 的"操作配方"天然适合这套预算分配**：GUI 任务族（如"批量导出报表"）反复出现，可把每个候选配方当一条臂、用端到端成功率当奖励，**只评测最高优先级的那一个**；GUI 执行成本高（截图 + 多步点击），"少评多算"收益比文本任务更大。
2. **用 UCB bonus 避免"冷门 App 永远没机会"**：只按预测成功率挑选会让长尾 App 的配方永久饿死；不确定性奖励正好对应"这个 App 还没试过"的探索价值，可直接照搬 b_t(z)=ν√(zᵀA⁻¹z)。
3. **把"跨设备泛化"写进 skill 接受准则**：本文验证同一 skill 在 Claude Code 与 Codex 下都有效；GUI 场景对应"同一套配方能否从 A 机型/分辨率迁移到 B"，建议把跨设备迁移成功率列为验收项。
4. **警惕 skill 注入的上下文成本与安全面**：GUI 上下文已被截图/无障碍树占满，注入 skill 会挤占观测预算；建议报告"skill 长度 vs 成功率"曲线，并做与提示注入相同的审查。
