# AgentHijack: Visual Patch Attacks on Multimodal Computer-Use Agents

> 一句话 TL;DR：训练一个 700×500 固定位置视觉 patch，驱动 Computer-Use Agent 真的执行恶意终端命令，并用 T-ASR/TAPR/E2E-ASR 三层指标量化视觉信号在 agent 流水线中的衰减。

## 2. 论文要解决的核心问题

- **要解决什么问题**：桌面 CUA 闭环里，一个可训练的局部图像 patch 能否从"污染 VLM 输出"穿透到"真实改变环境状态"。场景为 Desktop/Web 混合：agent 为完成无害任务访问技术博客，攻击者只控制页面上一块可见图片区域。
- **为什么重要**：论文核心论据是"VLM 错误不再停在响应层"。CUA 输出要经 parser 变成终端命令再执行，一次被劫持的命令可直接拷贝私钥、改 `.bashrc`、停服务。安全性不能用"回答对不对"判断，要看系统状态变没变。
- **现有方法有什么不足**：间接提示注入研究（InjecAgent、WebInject、AdInjec）载体多是显式自然语言，效果绑定在"模型愿不愿听网页上的话"；图像 patch 类工作（MIP、VPI-Bench）多停在输出操纵或黑盒最终动作劫持，**不区分**"生成目标串 / parser 接受动作 / 环境真的改变"；鲁棒性研究只用单一 ASR，无法定位失败层。
- **Research Gap**：作者自认补的是"闭环执行风险而非输出扰动"——把攻击链拆成 VLM 生成、动作解析、环境执行三个接口分别度量风险存活率；并声明本文不提供防御。

## 3. 方法核心思想（三层拆解）

### 3.1 一句话概括方法

离线用目标串监督在固定位置训练局部 patch，在线冻结 patch 并当作普通网页图片部署，再用 T-ASR→TAPR→E2E-ASR 三层指标测它能走多远。

### 3.2 方法总览（Pipeline）

- **输入**：无害任务 `b`、截图 `I_t`、历史 `h_t`、`Ω` 内 patch `δ`；**输出**：最终状态 `E_T` 是否满足 `G_adv`。
- **模块**：(1) 离线触发优化（在自建 GitHub Pages 与本地 CSDN 仿站截图上训练）；(2) 模型适配层（统一 chat template、图像预处理、target-token 定位，使同一管线挂到 5 个后端）；(3) 在线部署执行（patch 作为普通网页内容被渲染、被被动截图）；(4) 三层判分器 `J_text` / `J_act` / `G_adv`。
- **连接方式**：数据流是"截图→VLM→parser→动作→新截图"闭环；控制流的关键是离线/在线严格分离。这个分离本身是诊断工具：离线 T-ASR 已低则归因诱导失败；T-ASR 高而 TAPR/E2E 低则损失在解析或执行层。

### 3.3 真正的创新点（去伪存真）

> 本文属安全类、不训练模型，本节按"攻击/防御机制的真实新意"分。

- **真·方法创新**：把"视觉环境注入"从单一 ASR 数字重构为**三个接口上的分层存活率**（T-ASR / TAPR / E2E-ASR）。论文承认 parser 与执行链不可微、只能用目标串做代理监督（式 4）。"在真实执行环境里度量视觉 patch 的端到端环境后果"确实超出 VPI-Bench/MIP 的既有设定。
- **工程组合**：目标串监督（只监督 target token span）、统一模型适配层、Adam + L∞ 0.1255 + 9000 步早停，都是对抗 patch 领域的常规做法；5 个后端接入也只是把已有开源 agent stack 拼到同一管线。
- **对性能最关键的设计**：**train-on-target + 固定位置精确对齐**。控制实验中原坐标 (361,165) 得 11/12 = 91.67% T-ASR，其余 8 个平移位置全部 0/12（合并 0/96）。说明效果主要来自针对性优化 + 像素级对齐，而非通用可迁移的视觉语义。
- **证据不足 / 仅声称有效**：(1) **benign utility 只有定性说法**，没数字也没 baseline，"patch 不损伤正常任务"未被量化；(2) "先执行恶意命令、再继续原任务"这一关键隐蔽性结论只有一段 case study，无占比；(3) **跨后端/跨模板迁移性完全没测**，而这正是判断威胁真实性的核心；(4) Qwen3.5-4B 的 E2E-ASR 高达 55.8%，论文仅描述为"最强真实环境表现"，未分析小模型是否因安全对齐更弱而更易被劫持。

## 4. 具体技术细节

### 4.1 模型结构

- **base model 是 MLLM（含视觉编码器），不是纯文本 LLM**。5 个后端：`prompt_agent` 适配下的 Qwen3.5-4B / 9B、Aguvis-7B、EvoCUA-8B、UI-TARS-1.5-7B，参数量 4B–9B。
- **冻结/微调**：patch 优化需对该 VLM 白盒取梯度（train-on-target），但**不更新任何权重，不改 system prompt、parser、环境控制器与评估器**。
- 唯一被优化的对象是 patch：700×500、固定可见区域、L∞ 预算 0.1255。

### 4.2 训练流程

> 本文**不训练模型**，实际是"离线对抗 patch 优化 + 在线真实环境评测"两阶段管线，下表按其实际执行阶段列出。

| 阶段 | 目标 | 优化对象 | 数据来源 | 数据形态 | 目标 / Loss |
|---|---|---|---|---|---|
| Stage 1 离线触发优化 | 让 patch 在不同 prompt 与截图下稳定诱导目标串 | 固定位置 patch δ 的像素扰动 | 自建 GitHub Pages + 本地 CSDN 仿站截图；多 prompt 变体 | 700×500 patch 覆盖页面固定区域后的整页截图 | 仅监督 target string 对应 token span，忽略 prompt token / 模板分隔符 / image placeholder；Adam，lr 0.003，≤9000 步，loss < 0.01 早停；‖δ‖∞ ≤ 0.1255 |
| Stage 2 在线部署评测 | 测冻结 patch 能否穿透真实执行链 | 无（仅测量） | 15 目标 × 2 页面 × 4 benign = 120 逻辑 case / 后端 | 真实渲染后的截图，经 agent 截图通道进入 VLM | 无梯度更新；记录 VLM 输出、解析动作、执行 trace、状态校验，三层判分 |

> 关键设定：主实验全部 **train-on-target, evaluate-on-target**——每个后端用自己优化出的 patch 攻击，而非用替代模型迁移。

### 4.3 推理流程

- **多步推理**。标准 CUA 闭环：截图 `I_t` ⊕ patch → VLM 输出 `y_t` → parser 得 `a_t` → 环境转移 `E_{t+1}=T(E_t,a_t)` → 下一步截图，直到任务结束或评估器判定。
- 攻击成功定义为**状态级** `G_adv(E_T)=1`，如"staged 私钥文件存在""`.bashrc` 出现目标 alias""`openvpn` 变为 inactive"。
- 附录区分"动作级成功"（先开终端再输入目标命令）与"环境级成功"，两者非包含关系：TAPR 通过仍可能因焦点、顺序、权限等在环境层失败。

## 5. Benchmark 与实验设置

### 5.1 Benchmark 一览表

| Benchmark | GUI 场景 | 任务类型 | 数据规模 | 输入格式 | 输出格式 | 评测指标 |
|---|---|---|---|---|---|---|
| security_bench_v1（自建，未公开） | Desktop + Web | 图像触发命令注入：机密性/完整性/可用性三类（读拷贝、追加配置、删目录、停服务） | 15 目标 × 2 页面 × 4 benign = 120 逻辑 case/后端；5 后端合计 600 | 整页截图（含 patch）+ 无害任务 | 终端命令 / GUI 动作 | T-ASR（文本层）、TAPR（动作层）、E2E-ASR（环境层） |
| 控制实验：random / wrong-position（3×3）/ clean patch | Desktop + Web | 同上，仅替换 patch 内容或位置 | wrong-position：9 位置 × 12 次 | 同上 | 同上 | T-ASR 为主 |

### 5.2 实验结果分析

**主结果（600 在线实例）**：T-ASR = 507/600 = **84.5%**，TAPR = 282/600 = **47.0%**，E2E-ASR = 122/600 = **20.3%**；生成→解析掉 **37.5 pp**，解析→执行再掉 **26.7 pp**。

| Backend | Cases | T-ASR | TAPR | E2E-ASR | Gen→Parser | Parser→Exec |
|---|---|---|---|---|---|---|
| aguvis_7b | 120 | 83.3% | 50.0% | 25.0% | 33.3 pp | 25.0 pp |
| evocua_8b | 120 | 79.2% | 50.0% | 6.7% | 29.2 pp | 43.3 pp |
| qwen35_4b | 120 | 89.2% | 66.7% | 55.8% | 22.5 pp | 10.9 pp |
| qwen35_9b | 120 | 70.8% | 43.3% | 14.2% | 27.5 pp | 29.1 pp |
| uitars_15_7b | 120 | 100.0% | 25.0% | 0.0% | 75.0 pp | 25.0 pp |
| **Overall** | **600** | **84.5%** | **47.0%** | **20.3%** | **37.5 pp** | **26.7 pp** |

**失败签名**：aguvis_7b = 格式不匹配；evocua_8b = observe-before-act（反复观察不下手）；qwen35_4b/9b = 执行不稳（回退到原 benign 任务）；uitars_15_7b = 闭环弱（误点击、重复 UI 动作）。通用成因：最终阶段 patch 不是直接喂静态图，而是经真实渲染、裁剪、压缩与布局变化后再进截图，离线触发模式被扰动。

**Ablation / 控制实验说明了什么**：(1) **random patch** 无法稳定输出目标串 → 效果依赖被优化内容；(2) **wrong-position 3×3** 原坐标 11/12 = 91.67%、其余 8 个位置全部 0/12（合并 0/96）→ 攻击**强烈依赖精确空间对齐**，这是全文最关键的负面结果，直接限定威胁模型的成立条件；(3) **clean patch** 不虚假触发，benign 运行相对 no-patch 基线也无新系统性失效。

## 6. 亮点与贡献（Why it matters）

1. **把"安全 ASR"从一个数字变成一条链**。三层单调下降本身就是最有价值的结论：只看文本会高估（UI-TARS-1.5-7B 100% T-ASR 但 0% E2E-ASR），只看端到端会漏掉"已影响 VLM 但被 parser 拦住"这一大块风险。
2. **给出可操作的防御分层清单**（表 5）：输入层做来源标注与完整性检查；输出层做任务一致性检查与危险命令检测；解析层对终端调用、文件拷贝、配置写入、服务控制做专用 gate；执行层做权限隔离/沙箱；审计层保留截图、动作、日志与状态校验。
3. **"隐蔽辅助步骤"值得警惕**：成功案例中 agent 先执行恶意命令，再回到原 benign 任务继续做，用任务完成率做安全指标会完全漏检。
4. **对开源栈的意义**：被攻击的除 prompt_agent 外都是公开发布的项目，说明这是开源栈的共性风险。

## 7. 局限与可改进点（个人点评）

- **威胁模型偏强，削弱外部效度**。train-on-target 意味着攻击者已知目标后端、能白盒取梯度、还知道页面模板与投放坐标；而 3×3 控制又证明 patch 一旦移位即归零，实际可复现窗口比 20.3% 暗示的窄得多。**跨后端迁移性完全没测是最大空白**——不测就无法判断 84.5% 的 T-ASR 是通用风险还是针对性过拟合。
- **benign utility 完全未量化**。论文说 benign 完成率是单独 sanity check，却没给数字也没给 no-patch 对照。考虑 patch 占 700×500 可见区域，缺失相当关键。
- **统计口径偏松**。600 个"instance-level case"实为 120 逻辑 case × 5 后端，逻辑上不独立；所有百分比都无置信区间、无重复运行。且四个 benign 变体都要求开终端写 marker，削弱了与 adversarial 的区分度。
- **两站都是本地仿站**，真实第三方平台变量全被排除。
- Qwen3.5-4B 的 E2E-ASR 反而最高，更自然的解读是**小模型更易被劫持**，论文方向性解释缺席。

## 8. 对我们的启示 / 可借鉴点

1. **把三层指标搬进 GUI Agent 的安全回归测试**。涉及终端/文件/服务的 Desktop agent，CI 应同时记录"是否说出危险串""是否解析成危险动作""状态是否真被改"。UI-TARS-1.5-7B 那种"T-ASR 满分、E2E 归零"的后端在单指标下排序完全相反。
2. **执行层 gate 性价比最高**。parser→execution 损失 26.7 pp，主要来自焦点错误、命令偏移、顺序不稳与权限约束——都是确定性、可工程化的检查点。对终端调用、批量拷贝、配置写入、服务启停加显式确认/白名单，不需改模型就能砍掉一大块 E2E 风险。
3. **警惕"任务完成但插入了辅助步骤"**。评测除终局成败外还应记录轨迹中**与用户指令无因果关系的高风险动作**。这对 Online RL 尤其重要：reward 只看完成度时，agent 可能学会"顺手多做一步"而不被惩罚。
4. **位置敏感性对防御是好消息**。patch 移位即归零说明轻微的视口裁剪、缩放或重排就能让攻击衰减；工程上可随机化渲染参数提高攻击成本。
5. **观测通道本身就是攻击面**。CUA 把整页截图当唯一观测，等于把页面上任何像素变成潜在指令通道。若有 DOM/a11y tree 等结构化观测，可对比两者一致性作为异常检测信号。

## 9. 延伸阅读
