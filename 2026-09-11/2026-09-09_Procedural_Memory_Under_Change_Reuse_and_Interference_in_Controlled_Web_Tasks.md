# Procedural Memory Under Change: Reuse and Interference in Controlled Web Tasks

> 一句话 TL;DR：用冻结 prompt 的受控实验检验"程序性记忆与当前任务不匹配时是否必然致错"，在 32 个一次性单元格中未观察到任何预定义干扰签名。

## 2. 论文要解决的核心问题

- **要解决什么问题**：Web Agent 的记忆子问题。agent 学会"按品类搜索→剔除语义假阳性→取各类最小值→求和"后，任务引入捆绑折扣、数量变化或换成完整候选表时，程序仍可执行、曾成功、文本自洽，但局部最优化假设已失效。论文问：这种不匹配在什么额外条件下才变成可观测错误。
- **为什么重要**：记忆普遍只优化"存得下、检索得到"，而检索相关度不等于适用性。若陈旧程序会静默致错，所有经验复用式 agent 都缺安全阀。
- **现有方法有什么不足**：批评落点是三件事被混为一谈——不匹配、可观测错误、由记忆导致的错误。记忆条件下出错不是因果证据，因为无记忆时任务可能一样难。程序性记忆这条线（ProcMEM、AFTER 等）把适用性当一等公民，却缺少行为级隔离实验。
- **Research Gap**：固定检索策略与记忆更新算法，只改任务需求，预先定义"陈旧程序若主导行为则应当出现的签名"，再逐条证伪。

## 3. 方法核心思想（三层拆解）

### 3.1 一句话概括方法

冻结程序性记忆文本，只改任务需求，用 A 原记忆／B 无记忆／C 表格适配／D 语义改写四条件 × 预定义干扰签名，在单次生成、温度 0、无重试下检验不匹配是否外化为错误。

### 3.2 方法总览（Pipeline）

- **输入**：记忆文本（M1／C／D 或空）+ 合成购物任务（中文 prompt、候选表、价格、数量、折扣规则）+ 冻结参考答案与签名。**输出**：商品 ID、数量、推理、计算、总额，由冻结评测器判 reference-compatible／全局最优／严格正确／是否触发签名。
- **模块**：① Phase 1 回顾性案例——WebShop V1–V6 上的 `baseline_v05.py`，负责搜索、解析标题价格、处理 UI 与 locator 变体；② Phase 2 冻结 prompt 比较器——保存首答、不重跑不重标注；③ 分层评测器——把"选择匹配参考／全局最优／严格正确／诊断签名"拆成互不替代的字段。
- **连接**：Phase 1 只提供"接口层反复打补丁、高层程序未报告修改"的来源说明，不进入打分；Phase 2 内部 Pilot 01 → Batch 02 → Batch 03 四对，论文声明这不是独立重复实验。

### 3.3 真正的创新点（去伪存真）

- **真·方法创新**：没有新机制，创新在问题形式化与证据纪律。① 把"记忆适用性"与"行为干扰"切开，给出三级证据链（不匹配 → 可观测错误 → 与陈旧程序一致）；② 提出"预定义诊断签名"这一可证伪工具（如 T11 若总额为 $5），把"记忆是否主导行为"变成可预先登记、零成本检验的假设；③ 把无记忆条件 B 定为必需对照。
- **工程组合**：Phase 2 是既有件拼装——本地 qwen3:8b、温度 0、seed 0、保存首答、四条件对照、记忆文件带 SHA256，组合起来构成可审计的负结果实验。
- **对性能最关键的设计**：**无记忆条件 B**。它是唯一能区分"记忆致错"与"任务本身难"的设计；Batch 03 中 B 与三个记忆条件在主要任务级指标上完全一致，正是这一致性支撑了"非干扰"结论。其次是签名的任务绑定：A01+R01=$8 在 T14 上正确、只在 T15 才构成干扰，避免把签名当无条件红旗。
- **证据不足 / 仅声称有效**：① Phase 1"高层程序未修改"无逐版本快照，只是回顾性陈述；② T2 异常在 18 个后续单元格后仍未复现，成因未定；③ 条件 C 相对 A 同时改了接口假设、数量显式性与措辞长度，非单因子干预；④ 单模型单次生成、无多 seed、无跨模型，作者自认不能估计失败率。代价是"非干扰"只到"在极窄条件下未观察到"。

## 4. 具体技术细节

### 4.1 模型结构

base model 是 **LLM，不是 MLLM**：`qwen3:8b`，纯文本，**无视觉编码器**，约 8B 参数，**完全冻结、不训练**（`think=false` 关闭思维链）。Phase 1 的 `baseline_v05.py` 不含任何模型，是人工编写的规则脚本。论文未披露量化方式与硬件。

### 4.2 训练流程

**不训练。** 全文无任何梯度更新：32 个正式单元格共用同一份 qwen3:8b 配置（temperature 0、inference seed 0、`num_predict=512`、`num_ctx=16384`、`think=false`、`stream=false`），每格只发 1 次生成请求、1 次调用尝试、0 次自适应重试。Phase 1 也不训练，其"开发"是人工在 V3（标题/价格解析）、V4（提交控件与结果边界）、V5（搜索按钮路径）打补丁，V6 无补丁。附录 E.2 记录了 Pair 04 的一次执行管线修正（补入已冻结的 seed 0），声明不构成实验干预。

### 4.3 推理流程

**单步推理，不存在 agent 循环。** 每格把"任务 + 记忆文本"一次性喂给模型，取一次输出即结束；无 ReAct 循环、无规划-执行分解、无反思重试。Phase 1 的脚本也不加载 M1、不做最终语义选择与聚合、不提交答案，因此论文明确否认"六版本任务成功"的主张。

## 5. Benchmark 与实验设置

### 5.1 Benchmark 一览表

| 证据块 | GUI 场景 | 任务类型 | 数据规模 | 输入格式 | 输出格式 | 评测指标 |
|---|---|---|---|---|---|---|
| Phase 1（TimeWarp Task 57 / WebShop V1–V6） | Web | 界面适配：搜索/解析/动作 | 1 任务 × 6 个界面版本 | 网页 + 终端/截图证据 + Python 脚本 | 代码补丁 | 人工归因（非端到端成功率） |
| Pilot 01（T1–T3） | Web 合成购物 | 多品类最低成本决策 | 3 任务 × 3 条件 = 9 格 | 中文纯文本任务 + 候选表 + 记忆文本 | 商品 ID + 数量 + 计算 + 总额 | reference-compatible 选择/总额 |
| Batch 02（T4–T9） | 同上 | 行序扰动、身份-价格绑定、复制式探针 | 6 任务 × 3 条件 = 18 格 | 同上 | 同上 | 同上（沿用各自历史口径） |
| Batch 03 Pair 01–04（T10–T17） | 同上 | 数量变化 / 表征变化 / 局部-全局冲突 / 分布式证据组合 | 8 任务 × 4 条件 = 32 格 | 同上 | 同上 | 参考总额、全局最优、严格正确、诊断签名 |

### 5.2 实验结果分析

**主结果**（按证据块分列，论文拒绝汇总成功率）：

- **Phase 1**：失败归因到接口层（V3 标题/价格解析、V4 提交控件与结果边界、V5 缺兼容搜索按钮路径），补丁为标题与价格节点读取、图标按钮与推荐边界处理、Enter 键提交，V6 无补丁。高层程序未报告修改，但保留的 baseline 读不到 M1、也不能独立完成任务。
- **Pilot 01 与 Batch 02**：Pilot 为 A 2/3、B 3/3、C 2/3；T2 上 A 与 C 报 $36.80，B 报参考最小值 $20.00（参考 4×3.20+3×2.40=$20.00）。Batch 02 为 A 5/6、B 6/6、C 6/6；T5_A 选 A01 却用 A02 的价格，属身份-价格绑定错误；后续 12 格全对，未建立"总选第一行""被 A01 吸引"等可复现模式。
- **Pair 01**：8/8 选择与总额与参考一致；T11 四条件都显式计算 4×2+3×3=$17，**数量遗漏签名（$5）出现 0 次**。历史 strict 字段为 null，不回溯赋分。
- **Pair 02**：8/8 选 A03+R02 并报 $5.10；**显式界面混淆 0/8**，无人请求多余搜索或声称信息不完整。
- **Pair 03**：全局最优 **8/8**。T14 上 A01+R01=$8 同时是局部与全局最优；T15 上四条件全选 A02+R02 并应用 $5 折扣得唯一全局最优 $7，**陈旧局部最小签名 0/4**。严格正确性 2 true / 6 null（null 源于答案未显式给出数量证据，拒绝插补）。
- **Pair 04**：全局最优、严格正确、给定所选商品的算术正确全部 **8/8**；答案均为 A03+R03 且报 $6+$6−$5=$7；**组合错误 0/4**，B 与三个记忆条件打平。

**Ablation 说明了什么**：本篇没有 ML 意义上的消融，等价物是条件对照，可读出三点——① B 与 A/C/D 在 Batch 03 无差异，记忆既没帮忙也没添乱；② 记忆文本内容几乎不影响结果（M1、C、D 三者表现一致），说明模型没按记忆的接口假设行事；③ Pair 03 的六个 null 说明"选对全局最优"与"给出满足严格评测器的完整证据"是两件事。

## 6. 亮点与贡献（Why it matters）

1. 把记忆研究从"平均收益"扭到"适用性"：检索相关度无法回答"记忆还适用吗"。
2. 给出可复用的证据纪律——mismatch ≠ observable error ≠ memory-caused error，以及"预定义签名 + 无记忆对照"这套低成本证伪流程。
3. 诚实的负结果本身是知识：在"当前证据显式充分、短视野"下不匹配未转化为干扰，提示证据可及性可能是关键边界变量。
4. 评测层级分离的示范：reference-compatible、全局最优、严格正确、签名回答不同问题，null 不等于失败也不等于成功。

## 7. 局限与可改进点（个人点评）

1. **外部效度极低，且作者自己清楚**：两品类、显式候选表、单一折扣规则的合成购物，短视野、无噪声、无主动取证，无法外推。
2. **统计上近乎 n=1**：每格单次温度 0 生成，作者自认不能估计失败率。最低成本的加强是每格跑 20–50 次并报告签名出现率的置信区间。
3. **只看结果、不看过程**：签名全是响应级模式，捕捉不到"答案对但推理路径已被污染"这类影响；论文也承认无法区分忽略记忆、弱加权与中间纠偏。
4. **Phase 1 与 Phase 2 拼接感强**：Phase 1 动机好，但不加载 M1、不完成任务、无逐版本快照，作为证据偏弱。
5. **缺最关键的操纵变量**：讨论里提出应削弱当前证据的可及性（长上下文、干扰项、多记忆竞争），实验一个都没做，32 格全落在"证据显式充分"一侧，等于只在安全区取样。

## 8. 对我们的启示 / 可借鉴点

1. **记忆条目应带适用性前提**：除 procedure 文本外还要存 preconditions 与失效触发信号。界面结构、字段名、按钮语义、结算规则都属于会漂移的前提。
2. **记忆评测必须设无记忆对照**，否则无法排除"任务本来就难"。
3. **把关键约束显式化，可能比"记忆去毒"更便宜**：当数量、折扣规则、候选表完整摆在 prompt 里时，陈旧记忆几乎无法致害。与其做记忆冲突检测，不如在观察构造阶段把决定性证据显式、就近地呈现。
4. **指标分层，null 不要当 0**：选择正确 ≠ 计算正确 ≠ 严格任务正确；只盯最终答案会掩盖"过程侥幸"与"证据不完整"。
5. **签名式证伪适合做 CI**：预定义"若陈旧技能主导则应当出现的动作序列"，固定 seed 批量跑，成本极低。
6. **下一步实验已写在论文讨论里**：保持任务客观可解而削弱当前证据可及性，正对应 GUI agent 的长截图 / 长 DOM 场景。
