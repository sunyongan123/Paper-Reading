## 2. 论文要解决的核心问题

- **要解决什么问题**：如何在通用 LLM Agent 场景下，把大量冗长、冗余、贴着具体任务的原始执行轨迹，压成紧凑且可靠的**多层技能结构**（动作—程序—策略）。
- **为什么重要**：Agent 的价值不止于单任务，而在于"越用越强"。历史轨迹里藏着有效动作模式、中间状态、恢复流程与长期策略，但若不做结构化提炼，这些经验无法跨任务复用；不解决则只能靠检索原始片段或手写技能，泛化与成本都受限。
- **现有方法的不足**：作者把两条路线都判了"结构缺失"。经验复用派（ReAct / Reflexion / ExpeL / SEER）是"存什么、取什么"的搬运工，行为间的关系（谁该跟着谁、哪条分支通向成功）是隐式的；技能库派（Voyager / SkillX / Trace2Skill）把经验沉淀成工件，但**层级是在既有技能之上人为施加的**，回答不了四个前置问题——哪些行为该归组、哪些行为该跟在后头、哪些模式导向成功而非失败、局部技能如何组成程序与策略。
- **Research Gap**：作者主张的缺口是"**技能尚未成型之前的行为结构归纳**"——在技能工件存在之前，从轨迹里显式恢复"成功对齐的行为结构"，让技能层级从数据里长出来，而不是事后在已有技能上排结构。

## 3. 方法核心思想（三层拆解）

### 3.1 一句话概括方法

用一条 `D→E→G→Z→T` 的流水线，把轨迹抽象成规范事件，构造成败双份的转移图，经对比谱分解发现成功对齐的行为模态，归纳成三层技能塔。

### 3.2 方法总览（Pipeline）

- **输入**：交互历史 `D={(τi, yi)}`，每条 `τi` 是含观测、动作、反馈的分步序列，`yi∈{0,1}` 标成败。**输出**：三层塔 `T={S(1), S(2), S(3)}`。
- 模块链条：**① 事件抽象 E**（按子目标/动作族/操作对象/状态/反馈变化切分，typed arguments 归一同一身份）→ **② EigenTrace 构图 G**（融合语义/转移/结果三类证据，成 `A⁺`、`A⁻` 两份亲和度）→ **③ 对比谱分解 Z**（失败抑制变换后归一化 Laplacian 谱聚类）→ **④ 技能塔 T**（动作=规范事件，程序=谱簇，策略=压缩序列后的成功路径）。部署时按 token 预算分层检索，并支持验证器反馈下的图编辑修订，全程无需重新归纳。

### 3.3 真正的创新点（去伪存真）

- **真·方法创新**：对比谱分解（`Ā_uv=(A⁺_uv)²/(A⁺_uv+A⁻_uv)`）是本文唯一的新机制——随成功亲和度单调增、随失败亲和度单调减，且有 Lemma 1（不放大亲和度估计误差）与 Theorem 1（Davis–Kahan 子空间稳定性）双重背书，把"失败抑制"做成参数无关、可独立复用的算子。
- **工程组合**：事件抽象（typed-argument 归一）、K-means 谱聚类、最大特征间隙定簇数、SCC 缩并取路径，都是既有组件的组合，本身不新。
- **对性能提升最关键的设计**：消融显示**转移证据**最关键（去掉后 87.31%→70.15%），结果证据与对比变换并列次之（均掉到 73.88%）——三类证据缺一不可，且语义从不单独创造边。
- **证据不足 / 仅声称有效**：验证器图编辑的四个算子（Split/Merge/Promote/Downweight）只有"冻结塔 80.42%→84.58%"的反馈实验，缺逐算子消融，属"组合有效但单点贡献未证"。

## 4. 具体技术细节

### 4.1 模型结构

- 纯 **LLM**（文本观测环境，无视觉编码器，非 MLLM）。角色解耦：**GPT-5.4** 作 Skill Author / plan rewriter，**DeepSeek-V4-Flash** 作默认 Skill User（另用 DeepSeek-V4-Pro 做跨模型对照）。参数量均未披露，全程**冻结、零微调**——本方法不改模型权重，是对轨迹做无监督归纳。
- 事件/商节点表征用 4,096 维嵌入，按 batch 16 处理；嵌入模型 identifier 论文承认"不可复现地从记录中恢复"。

### 4.2 训练流程（无训练，为归纳流水线）

| 阶段 | 目标 | 归纳什么 | 数据来源 | 数据形态 | 目标 / Loss |
|---|---|---|---|---|---|
| Stage 1 事件抽象 | 抹平表层语言差异 | 规范事件身份 | 原始轨迹分步序列 | 带类型参数的 canonical event | 无 loss（切分+归一） |
| Stage 2 构图 | 融合三类证据 | 成败双份亲和度 `A⁺/A⁻` | 观测到的转移计数 | 稀疏有向图 | `A±=M·ω·(s·t±·o±)^{1/3}`，几何平均免配权 |
| Stage 3 谱分解 | 抑制失败捷径 | 稳定行为模态 | 对比矩阵 `Ā` | 归一化 Laplacian | 谱松弛 + 最大特征间隙定簇数 + K-means |
| Stage 4 策略归纳 | 组出长期策略 | 程序序列上的成功路径 | 压缩后的程序序列 | 有向图 + SCC | 保留有成功对比边支撑的最大路径 |

- 关键算子（重点）：转移依赖 `t±_uv = c±_uv/max{1, c±_u}`；结果倾向 `ρ±_u=(n±_u+1)/(n⁺_u+n⁻_u+2)`、`o±_uv=√(ρ±_u·ρ±_v)`；掩码 `M=1[c⁺+c⁻>0]`（语义相似度**从不创造边**，转移必须真实被观测到）；证据强度 `ω=(c⁺+c⁻)/(1+c⁺+c⁻)` 压低偶发边。对称化 `W=(Ā+Āᵀ)/2` 后做归一化谱分解，逐连通分量处理，`rc=argmax(λ_{k+1}−λ_k)` 动态定簇数，行归一化后 K-means（20 次初始化/300 迭代/seed 42）。

### 4.3 推理流程

- 推理 = 部署：Skill User（DeepSeek-V4-Flash，temperature 0，每步最多 512 输出 token）在 20 步交互预算内执行**多步循环**，步与步间由环境反馈驱动。
- 两种部署策略共用同一座塔：**High-only** 取 3 条策略路径改写成紧凑计划；**Full** 额外注入最多 8 个 step-aligned 程序卡（余弦阈值 0.45 过滤、去重）。检索按 `log(1+ζ_t(σ)·ϱ_σ)` 在 token 预算 `B_t` 下择优，`ζ` 为匹配度、`ϱ_σ=(n⁺_σ+1)/(n_σ+2)` 为平滑可靠度。

## 5. Benchmark 与实验设置

### 5.1 Benchmark 一览表

| Benchmark | GUI 场景 | 任务类型 | 数据规模 | 输入格式 | 输出格式 | 评测指标 |
|---|---|---|---|---|---|---|
| ALFWorld | General（文本家居） | 长时程规划 + 端到端操作 | 134 solvable valid_unseen（310 train→1,240 轨迹） | 纯文本观测+指令 | 动作序列 | 成功率 / 步数 / 非法动作 / input tokens / context chars |
| WebShop | Web | 搜索 + 购买端到端 | 100 test（100 train→400 轨迹） | 纯文本页面+指令 | 动作序列 | 精确成功率 / reward / 非法动作 |

> 两环境均强制 20 步交互预算；ALFWorld 成功率取最终完成指示，WebShop 精确成功 = 官方 reward≥0.999。

### 5.2 实验结果分析

- **主结果**（三次运行均值）：ALFWorld **Full 87.31%±0.75**（10.35 步、0.26 非法动作），High-only 84.83%；最强基线 ExpeL 81.59%（+5.72 点）、SkillX 78.61%（+8.70 点），No-Skill 仅 46.27%。WebShop **Full 精确成功 50.67%±2.89**（reward 0.7115，逼近专家手写 0.7183），超 SkillX 1.34 点，非法动作从 No-Skill 的 0.68 压到 0.27。
- **上下文效率**：比 SkillX input tokens 减 30.5%、注入技能上下文减 63.9%，构造还省 16.85% GPT token（1,025,732 vs 1,233,641）——增益来自结构化组织，而非堆更多上下文。
- **Ablation 说明**（ALFWorld）：去转移证据最致命（87.31%→70.15%，塔从 39 程序/118 策略塌到 19/76）；去结果证据或去对比变换均 73.88%，后者塔仅剩 10 程序/44 策略。证明转移编码了必要执行顺序，结果/对比阻止"成功歧义关系"主导图。
- **跨模型迁移**：GPT-5.4 建的塔迁给 Flash 用户 65.67%→88.06%（34 胜 4 负 96 平，McNemar p=6.04×10⁻⁷）；塔结构不绑定作者模型，但作者质量与用户能力决定实际增益。

## 6. 亮点与贡献（Why it matters）

1. 补上技能学习里缺失的"结构归纳"一环——在技能工件存在之前就显式回答归组/转移/结果/组合四个问题，全流程参数无关、无人工配权。
2. 对比谱分解是干净可复用的新算子：把成败证据织进亲和度再谱聚类，稳定性有 Lemma 1 + Davis–Kahan 定理双重背书。
3. 三层塔契合 Agent 分层规划的认知结构（可执行动作 + 可复用程序 + 可迁移策略），而非扁平摘要。
4. 验证器驱动的四类图编辑让技能库"建完可改"，失败后低成本修订，摆脱"建完即死"。
5. 实验纪律好：同轨迹池、同预算、同 Skill User 对比，并做作者/用户解耦的跨模型验证，排除了"好结果来自作者模型"的混淆。

## 7. 局限与可改进点（个人点评）

1. **环境窄**：只在文本观测的 ALFWorld/WebShop 上验证，动作空间小、状态结构化。真实 GUI（像素截图、视觉+DOM 混合、超长 horizon）里"事件抽象"难度陡增，嵌入归一对视觉同义动作是否成立完全无证据。
2. **离线批处理**：全部轨迹一次性喂入建塔，虽可小修小补，但没有流式增量归纳的复杂度与稳定性分析，"技能随经验从零长出"的终身学习愿景打了折扣。
3. **启发式脆弱**：最大特征间隙定簇数、零度节点单例化在数据稀薄时易裂出碎片程序，对超低频成功轨迹伪计数平滑未必兜得住。
4. **底座依赖被轻描淡写**：GPT-5.4 建的塔增益显著，但 Flash 自建塔仅 65.67%——弱作者模型建的塔价值有限，这个"作者质量决定塔质量"的隐含前提需要更多证据。
5. **嵌入模型不可复现**：4,096 维表征的具体模型 identifier 论文自认无法从记录恢复，直接影响可复现性。

## 8. 对我们的启示 / 可借鉴点

（本篇属 Agent 方法论域，对 GUI Agent 的可借鉴点如下）

1. **失败轨迹是金矿**：GUI 交互日志里失败轨迹占绝大多数，正是"对比式失败抑制"最发力的场景——可把"前置状态→动作→后置状态"的转移证据 + 任务成败引入构图，自动剔除"看似正常却通向死胡同"的动作链，比手写 SOP 或文本相似度检索可靠。
2. **事件层参数化归一**：把 GUI 步骤映射成规范事件（OpenApp/Click/Type/Scroll/Recovery），用元素角色与类型做归一，抹平"同一操作在不同截图里的表面差异"——这正是 GUI 动作泛化的老难题。
3. **冻塔可改机制**：四种图编辑（Split/Merge/Promote/Downweight）比每次失败后重训整套策略便宜得多，契合 GUI 智能体"边用边改"的工程现实。
4. **落地注意**：GUI 事件嵌入必须融合视觉模态，纯文本嵌入会把两张截图上的同义控件切成两个节点；动作长尾极重的日志需先去噪再谱聚类。
