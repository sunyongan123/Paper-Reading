# ElderBench: Benchmarking Autonomous Mobile Agents for Older Adults

> 一句话 TL;DR：首个用真实老年自然指令（249 条）构建的移动 GUI Agent 基准，量化了主流模型在"欠指定/间接表达"上的系统性失败，并证明措辞不匹配是显著失败源。

## 2. 论文要解决的核心问题

- **要解决什么问题**：如何可靠地评测移动 GUI Agent 服务老年用户的能力——场景属于 Mobile 端 GUI Agent 评测，核心对象不是"能否操作屏幕"，而是"能否听懂老人怎么说需求"。
- **为什么重要**：GUI Agent 被寄望于帮老人跨越数字鸿沟（调字体、设铃声、拉黑号码这类老人高频但难上手的系统操作）。但若考题与老人真实表达脱节，评测结论就无法回答"Agent 能不能服务好老年用户"这一落地前提——不解决会导致高估部署可行性、把资金投错方向。
- **现有方法有什么不足**：AndroidWorld、AndroidLab、MobileWorld、A3、ProBench 等现有基准几乎都用"精心撰写的显式目标指令"（如"找到 Download 文件夹里上月下载的简历，发送到 HR_chen@gmail.com，主题 candidates_cv"）。这类指令目标、对象、动作全都显式给出；而老人真实表达多为间接、欠指定、依赖屏幕上下文（"声音太小，听不见""把这个号码拉黑"）。Mobile-Bench-v2 虽有模糊指令设定，但仍是"从完整指令删槽"构造，非真实采集。
- **Research Gap**（作者视角）：现有基准**从未把"目标人群真实采集 + 人群特定设计 + 自然语言现象 + 系统语言学分析"四者结合**。ElderBench 的 claim 是补上这一缺口——第一个用真实采得的老年指令做成的移动 GUI 基准，且 249 任务/20 应用在同类中规模最大。

## 3. 方法核心思想（三层拆解）

### 3.1 一句话概括方法

不是训一个模型，而是**采真实老年指令 → 做三维语言学刻画 → 建"在线+离线"双模式评测协议**，再用"受控改写 + 失败归因 + 特征归因"三重分析把失败拆到语言层 vs 执行层。

### 3.2 方法总览（Pipeline）

- **输入**：老年自然语言指令 + 初始设备状态（截图/XML）；**输出**：任务成功率 SR、每回合推理延迟 AIL、每任务 token 消耗 MCM 及失败归因。
- **模块**：
  1. **数据采集**：对 28 名 59–84 岁老人做半结构化访谈（两阶段：日常用法→期望协助），不预设任务模板/语言示例，仅请其自然描述需求；251 条经三人合议剔除 2 条不可执行，得 249 条，覆盖 20 个 Android 应用。
  2. **语言学刻画**：以 MobileWorld 201 条指令为基线，从句法/语义/语用三维对比（理论框架引自 Silverstein 1972；LLM 预标注用 DeepSeek-V4-Pro，与人工一致性 93.10%）。
  3. **双模式评测**：在线 130 任务/15 应用（ADB 闭环执行）；离线 119 任务/5 应用（支付宝、微信、高德、淘宝、携程——涉支付/隐私），用真人多条轨迹合并成"任务图"判分。
- **连接**：指令 →（在线）Agent 循环执行动作经 ADB 改变状态，最终截图+采样帧+Activity 交 Qwen3-VL-Flash 判分；（离线）Agent 每步预测动作须命中任务图中某条合法边（点击 50px 容差、文本模糊匹配），显式 finish() 到达 DONE 才算成功。成功判定 = Agent_Finished ∩ Judge_Passed。

### 3.3 真正的创新点（去伪存真）

- **真·方法创新**：几乎没有"新损失/新结构"——这是 benchmark 论文。真正的硬贡献在于**数据范式**（半结构化访谈真采，非模板生成/改写）与**实验设计**（受控改写配对 + McNemar 检验，把"语言难"与"任务难"解耦）。
- **工程组合**：双模式评测（在线闭环复用 AndroidWorld 范式、离线轨迹复用 AitW/AMEX 范式）、语言学三维框架、VLM-as-Judge（引自 Shih 2026）、FM 特征归因（标准工具）——均非原创，但组合有效。
- **对结论最关键的设计**：**受控指令改写**（同一任务/环境只换措辞，AutoGLM 37→61、Qwen3-VL-Flash 23→46，McNemar p<0.001）是全文最有说服力、可复用的证据，直接证明了"措辞不匹配是显著失败源"。
- **证据不足 / 仅声称有效**：① 三条设计洞察（状态感知意图理解/主动澄清/上下文解析）**只提建议、未做任何验证**；② 特征归因是 Pearson/FM 相关性，非因果；③ VLM-Judge 主要看最终截图，对"渐进式状态错误"可能漏判；④ 评测禁止追问，却建议 Agent 应主动澄清，方法与其结论自相矛盾。

## 4. 具体技术细节

### 4.1 模型结构

本文**不训练、不改模型**。评测对象是现成模型：5 个 VLM（Qwen3-VL-Flash/Plus、GLM-4.6V、Gemini-3-Flash、Kimi K2.5）+ 4 个 GUI Agent（AutoGLM Phone-9B、Doubao-1.5-UI-TARS 7B、GUI-Owl-1.5 8B-Think、UI-Venus-1.5 8B）。Agent 按各自官方开源仓库原生配置评测，未做任何微调/冻结改动。

### 4.2 训练流程（若需要训练）

**无训练阶段**。全部模型零样本评测。

### 4.3 推理流程（评测协议，非训练）

- **单轮设定**：每个实例一条指令 + 初始状态，不允许多轮追问（作者自述三条动机：建立基线、老人常以独立请求表达、当前 Agent 多为单轮）。
- **多步执行循环**：Agent 感知截图+上下文 → 生成结构化动作 → 经 ADB 执行 → 接收更新状态，闭环迭代。动作空间 = Tap / Long Press / Swipe / Type / Home / Back；坐标归一化到 [0,1000] 再映射到设备像素。
- **终止条件**：每任务最多 25 步、硬性 120 秒超时；成功需显式 finish() 且判分通过。环境：Google Pixel 6a、Android 17、1080×2400。

## 5. Benchmark 与实验设置

### 5.1 Benchmark 一览表

| Benchmark | GUI 场景 | 任务类型 | 数据规模 | 输入格式 | 输出格式 | 评测指标 |
|---|---|---|---|---|---|---|
| **ElderBench（总体）** | Mobile（Android，20 App） | 端到端任务执行（老年自然指令） | 249 任务 | 截图 + 老年自然指令 | 结构化动作序列 | SR / AIL / MCM |
| ├ 在线子集 | Mobile（15 App，含系统设置/浏览器/天气等） | ADB 闭环执行 | 130 任务 | 截图+上下文，动作实时改状态 | Tap/Swipe/Type/Home/Back | SR/AIL/MCM + VLM-Judge（Qwen3-VL-Flash，与人工一致性 93.08%） |
| └ 离线子集 | Mobile（5 App：支付宝/微信/高德/淘宝/携程） | 任务图轨迹匹配 | 119 任务 | 截图+XML+指令 | 预测动作匹配图边（50px 容差/文本模糊） | SR/AIL/MCM（finish ∩ DONE） |

> 对照基线：MobileWorld（201 条显式指令）仅用于语言学对比，不参与打分。

### 5.2 实验结果分析

**主结果**（Table 2，总体/在线/离线 SR）：没有任何模型总体成功率过半。
- VLM：Gemini-3-Flash 49.80%（最高）、Qwen3-VL-Plus 47.39%、Kimi K2.5 29.72%、GLM-4.6V 23.29%、Qwen3-VL-Flash 22.89%。
- GUI Agent：GUI-Owl-1.5 45.38%、UI-Venus-1.5 41.37%、AutoGLM 36.55%、Doubao-1.5-UI-TARS 32.53%。
- **分模式**：在线显著高于离线——Qwen3-VL-Plus 76.15%、GUI-Owl-1.5 68.46%（在线）；离线普遍个位数到 30% 出头（最好 UI-Venus-1.5 31.09%、Gemini-3-Flash 27.73%）。注意两子集任务/应用构成不同，作者明确警示**不宜做受控对比**。
- 效率权衡：Qwen3-VL-Flash AIL 最低 3.57s 但 SR 仅 22.89% 且 token 高；Gemini-3-Flash SR 最高且 VLM 中 token 最低（21,660）；无模型同时最优三项。

**Ablation / 归因分析**（本文以三类实验替代传统消融）：
1. **受控指令改写**（100 条按五类语义分层抽样，同一任务只改措辞）：AutoGLM 37→61（+24）、Qwen3-VL-Flash 23→46（+23），McNemar p<0.001，bootstrap 95% CI 分别为 [14,34]、[12,34] 个百分点——证明**措辞不匹配是显著失败源**，但改写后仍有约四成失败，说明规划/执行能力本身也不足。
2. **失败归因**（AutoGLM 在线 63 条失败，在线 SR 51.54%）：意图/能力边界错误 57.1%、规划与状态跟踪 33.3%、环境感知 6.4%、视觉定位/动作执行仅 3.2%——**前两类合计 90.4%**，说明瓶颈在"听懂人话/维持多步执行"，而非低层视觉接地。
3. **特征归因**：单特征相关——指令长度 −0.16、省略句 −0.15、间接表达 −0.12（均拖累），信息查询 +0.26（有利）；交叉特征（FM）——冗长×信息查询 +0.70（长描述反而有利）、冗长×系统设置 −0.42（复杂度冲突）、canonical×间接表达 −0.34（语言矛盾）。

## 6. 亮点与贡献（Why it matters）

- **填补真实缺口**：第一个"真老年指令"移动 GUI 基准，249 任务/20 应用同类最大，且为访谈真采而非模板生成/改写，直接回应"评测语言与真实需求脱节"这一被长期忽视的问题。
- **可复用的量化证据**：短句（平均 15.89 vs 基线 88.09 字符）、低动词密度（1.26 vs 2.82）、近半省略/叙述结构（47.80%）、约八成非显式语义类型——这组数字可直接指导 SFT 语料与评测难度梯度的建设。
- **双协议兼顾保真与可控**：在线闭环保交互保真，离线任务图多路径判分规避"单黄金路径"偏见并绕过支付/隐私约束。
- **解耦实验设计**：受控改写 + 失败归因把失败拆到"语言层 vs 执行层"，并量化出意图理解（57.1%）远比视觉定位（3.2%）更关键——这是投入优先级上的强信号。
- **判分可靠性基线**：VLM-Judge 与人工一致性 93.08%，为自动化评测提供可引用的可信度参照。

## 7. 局限与可改进点（个人点评）

- **单语言单文化**：样本全部来自中国老人与中文 App（支付宝/微信等），跨语言/跨文化迁移性存疑；28 人 249 条样本量也偏小。
- **方法自相矛盾**：文末建议 Agent 应"主动澄清"，评测却禁追问、只测一次性完成，等于**没测它最推崇的那类行为**——建议增设"允许澄清"赛道或分级计分。
- **offline 分数被协议压低**：任务图要求每步都命中人工演示的合法边，Agent 的合法替代路径会被判负；且 offline 与 online 任务构成不同，文中对离线低分的解读偏保守，可能低估 Agent 真实能力。
- **证据层级有限**：特征归因是相关性而非因果；VLM-Judge 只看最终截图+采样帧，对渐进式状态错误可能漏判；三条设计洞察纯属建议、零验证。

## 8. 对我们的启示 / 可借鉴点

- **语料侧**：真实用户指令（欠指定 38.15% + 间接 19.28% ≈ 六成为非显式）应进入 SFT 与评测管线；"把自然话语改写为显式指令"可同时用作训练增强与难度梯度构造。
- **投入优先级**：失败分布（意图理解 57% ≫ 视觉定位 3%）提示——先解决"听懂人话、判断能力边界、必要时澄清"，再追求接地精度，避免在视觉定位上过度内卷。
- **交互设计落点**：状态感知意图理解（把"听不见"翻译成调音量）、欠指定先问再动、按场景自适应解析，三条可直接转为我们 Agent 的策略模块需求。
- **方法论借鉴**：受控改写配对 + McNemar 显著性检验，适合做我们自己的消融，在固定环境里分离"措辞、任务难度、模型能力"三者贡献；FM 交叉特征分析可用于定位语言属性间的非线性交互。
