## 1. 研究背景与要解决的问题

GUI Agent 能"看懂"屏幕、代替用户点击/滑动/输入，被视为帮老年人跨越数字鸿沟的可行路线——很多老人会用微信、支付宝，但调字体、设铃声这类系统操作常无从下手。然而要判断 Agent 能否帮上老人，先得有靠谱的"考卷"。现有移动 GUI 基准（AndroidWorld、AndroidLab、MobileWorld、A3、ProBench 等）的考题几乎都是精心撰写的显式指令，目标、对象、动作写得清清楚楚。这与老人真实的表达方式严重脱节：他们常说出"声音太小，听不见""把这个号码拉黑""截个图给我"这类间接、依赖屏幕上下文、信息不完整的句子。考题语言与真实需求不匹配，评测结果自然无法回答"Agent 能不能服务好老年用户"。

本文要补的正是这个缺口：构建**第一个用真实采得的老年指令**做成的移动 GUI 基准，并回答三个问题：指令语言差在哪、当前 Agent/VLM 能完成多少、失败根源在哪。

## 2. 核心方法 / 思路

整体分三步：**采数据 → 刻画语言 → 建评测**。

**(1) 数据采集**。作者对 28 位 59–84 岁的老人做半结构化访谈，不预设任务模板、不给语言示例，只请他们自然描述"希望 Agent 帮忙做的手机操作"。受访者来自上海、安徽、江苏、河北等多地，手机使用年限与日使用时长差异很大（1–8 年至 10 年以上、1–2 小时至 5–6 小时）。共收集 251 条指令，三人合议剔除 2 条不可执行的，得到 **249 条有效指令、覆盖 20 个 Android 应用**——不是命题人出题，而是把老人的原话当考题。

**(2) 语言学刻画**（以 MobileWorld 的 201 条指令为基线对照，从句法/语义/语用三维比较）。句法上，老年指令平均仅 15.89 字符（基线 88.09）、平均动词 1.26 个（基线 2.82），78.31% 短于 20 字符；省略句和叙述句合计占 47.80%。语义上归为五类：显式清晰 17.67%、欠指定 38.15%、间接表达 19.28%、指代歧义 12.85%、口误/自我纠正 12.05%；其中间接表达里 22.92% 不含任何显式动词，而这三类非显式现象在基线指令中全部为 0%。语用上集中在生活服务、社交沟通、系统设置三大场景。

**(3) 评测框架（双模式，任务级分流）**。在线模式 130 个任务、15 个交互流较稳定的应用，在真实 Android 环境闭环执行（经 ADB 操作，动作含点击、长按、滑动、输入、Home/Back）；离线模式 119 个任务、5 个涉及支付与隐私的应用（支付宝、微信、高德地图、淘宝、携程）——先由真人录制多条合法轨迹合并成"任务图"，Agent 每步预测动作必须命中图中某条合法边（点击容差 50 像素、文本模糊匹配），并显式 finish() 到达 DONE 才算成功。指标为成功率 SR、每回合平均推理延迟 AIL、每任务平均 token 消耗 MCM；成功判定采用 VLM-as-Judge（Qwen3-VL-Flash 零样本评分），与人工判定一致性达 93.08%。

## 3. 关键实验结果

评测对象是 5 个主流 VLM（Qwen3-VL-Flash/Plus、GLM-4.6V、Gemini-3-Flash、Kimi K2.5）与 4 个专攻 GUI 的 Agent（AutoGLM、Doubao-1.5-UI-TARS、GUI-Owl-1.5、UI-Venus-1.5），每任务上限 25 步、120 秒。核心结论：**没有任何模型总体成功率过半**——VLM 最好 Gemini-3-Flash 49.80%、Qwen3-VL-Plus 47.39%；Agent 最好 GUI-Owl-1.5 45.38%、UI-Venus-1.5 41.37%，AutoGLM 只有 36.55%。分模式看，在线子集分数明显更高（Qwen3-VL-Plus 76.15%、GUI-Owl-1.5 68.46%），离线子集普遍落在个位数到 30% 出头（最好 UI-Venus-1.5 的 31.09%）。

为了把"老年语言难"与"任务本身难"分开，作者抽取 100 条按五类语义分层的指令，改写为简洁显式指令（同一任务、同一环境，只换措辞）。改写后 AutoGLM 成功数 37→61，Qwen3-VL-Flash 23→46，McNemar 检验 p<0.001——证明**措辞不匹配是显著失败源**，但并非全部（仍有约四成任务失败，说明规划和执行能力本身也不足）。失败轨迹分析（AutoGLM 在线 63 条失败，其在线成功率 51.54%）：意图/能力边界错误占 57.1%（如把"声音太小"当知识问答而非调音量）、规划与状态跟踪占 33.3%、环境感知 6.4%、视觉定位/动作执行仅 3.2%。细粒度归因显示：指令长度（−0.16）与省略句（−0.15）普遍拖累成功率，但信息查询类的较长描述反而有利（+0.70），长文本配系统设置则显著不利（−0.42）。

## 4. 亮点与贡献（Why it matters）

- 填补真实缺口：第一个"真老年指令"移动 GUI 基准，249 任务/20 应用在同类对照中任务量最大，且是访谈采得而非模板生成/改写。
- 给出三维语言差异的量化证据（短句、低动词密度、近半数省略/叙述结构、约八成指令属欠指定/间接/指代/口误等非显式语义类型），可直接引用指导语料建设。
- 在线+离线双协议兼顾交互保真与可复现/隐私约束，任务图多路径判分规避"单黄金路径"偏见。
- 用"受控改写 + 失败归因 + 特征归因"三重分析，把失败拆到"语言层 vs 执行层"，并量化出意图理解是比视觉定位更关键的瓶颈。
- 附带 VLM-Judge 与人工判定的一致性验证（93.08%），为基准的自动化判分提供可靠性基线。

## 5. 局限与可改进点（个人点评）

- **单语言单文化**：指令全部来自中国老人与中文常用 App，能否迁移到其他语言/文化需谨慎。
- **单轮设定与自己的建议矛盾**：文末建议 Agent 应"主动澄清"，评测却禁止追问、只测一次性完成，等于没测它最想要的那类行为——建议增加"允许澄清"赛道或分级计分。
- **offline 分数被协议压低**：任务图要求每步都命中人工演示的合法边，Agent 的合法替代路径可能被判负；offline 与 online 任务构成不同、不宜直接对比，文中对离线普遍低分的解读偏保守。
- 28 人 249 条样本量有限；支付/通讯录等敏感操作只能在离线演示；VLM-Judge 主要看最终截图，对"渐进式状态错误"可能漏判；特征归因是相关性而非因果结论。

## 6. 对我们的启示 / 可借鉴点

- **语料侧**：真实用户指令（欠指定+间接表达约占六成）应进入 SFT 与评测管线；"把自然话语改写为显式指令"可同时用作训练增强和难度梯度。
- **投入优先级**：失败分布（意图理解 57% ≫ 视觉定位 3%）提示先解决"听懂人话、知道能力边界、适时澄清"，再追求接地精度。
- **交互设计落点**：状态感知意图理解（把"听不见"翻译成调音量）、欠指定时先问再动、按场景自适应解析——三条可直接作为我们 Agent 的策略模块需求。
- **方法论借鉴**：指令改写配对实验（paired + McNemar 显著性）适合做我们自己的消融，在固定环境里分离"措辞、任务难度、模型能力"的贡献。
