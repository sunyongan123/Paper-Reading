## 1. 研究背景与要解决的问题

现代智能体靠编排推理、生成、验证与工具调用等多步解复杂任务。步骤能力固然重要，但"何时调用、以什么顺序调用"往往更关键——一旦某步已产出正确结果，排队中的验证就变得多余。然而现有工作几乎都在决定性结果可见前把流程定死：AFlow 搜索一条数据集级工作流原样执行；MaAS 在每条 query 执行前就采样好架构；LAS 只能在预定义 DAG 内调度。作者称之为**续段失效**：执行中出现的中间证据让尚未执行的后续步骤不再适用——review 发现草稿缺证据，排队的 Format 步骤却照跑。

两个极端都不好：整条换工作流重跑丢前缀丢工件；每节点 LLM 重规划则延迟、token 与方差高且覆盖仍有效部分。HotpotQA 例最直观：review 发现缺俱乐部别名证据后，AFlow 仍执行固定 Format 后缀只得 0 分；TROVE 先 Insert 一个 revise、再把过期后缀 Replace 成 stop，保留前缀，得分升到 1。本文要补的正是这个**中间地带：只修订被运行时证据作废的那一小段未来**。

## 2. 核心方法 / 思路

总览：TROVE 把"规划"与"承诺"解耦——规划视野可横跨多个技能，承诺视野却始终只有一个动作：每次只执行路线头部一个技能，观察边界结果后再决定下一步，全程分离线、在线两段。

**离线经验抽取。** 把 AFlow 算子封装成带标准接口的**原子技能**；关键创新是复用 AFlow 在训练集搜索时留下的**整条评估轨迹**——相邻候选改动 (W_i→W_{i+1}) 成对评估的 Δscore/Δtime 与中间结果，而非只留最终选中的工作流。稳定的高频片段若满足"内部顺序与数据依赖稳定、构成连贯子目标、IO 契约一致、执行时无需参考外层路线"，就封装为**组合技能**（对外返回一个聚合边界结果）；凡中间结果可能改变后续顶层决策的边界一律保留不折叠。结果依赖型续接则显式存入**技能转移图**，边 τ=(s,e,c,g)：完成技能 s、观察到事件 e/特征 c 时，trace 支撑的下一步是 g，每条边来自被评估过的局部修改而非单纯邻接。最终注册表含 10 个原子技能、41 个组合技能，转移图含 244 条边。

**在线执行与路线修订。** 规划器提出不超过 4 步的临时路线，但只 commit 头部技能并观察边界结果，之后三选一：**(1) Retain**——排队后继在新结果下仍可执行，原样保留，不额外花路由调用；**(2) Insert**——后继失效但下游意图仍成立，用转移图查一个 trace 支撑的局部反应（修复/测试/验证类）插到后缀前，跑完再重新检查原后继；**(3) Replace**——图弃权、证据冲突或需更大改动时，才让 LLM 以最新结果、执行历史、待执行后缀（图候选可作先验）重新生成"仅未执行部分"的新后缀。任务完成即提前终止并丢弃后缀。已执行前缀与工件始终保留，改动永远落在最小充分范围。

## 3. 关键实验结果

评测覆盖 6 基准 × 3 主干共 18 组：代码 HumanEval/MBPP（pass@1）、数学 MATH/GSM8K（准确率）、问答 DROP/HotpotQA（token F1），训练:测试约 1:4；主干为 DeepSeek-V4-Flash、GPT-4o-mini、Qwen3-8B；基线覆盖数据集级（AFlow）、query 级执行前自适应（MaAS）、节点级在线调度（LAS）三个层级。TROVE 在 **15 组拿最佳/并列最佳分数、16 组线上耗时最短**；相对 AFlow 16 组提分（最高 **+31.37**）、16 组省时（最高 **−86.7%**）；相对 MaAS 18 组全部省时（−6.1%~−94.6%）、17 组不降分（提升 0.48–46.27）；相对 LAS 六个代码设置 5 组提分 1.47–7.03、6 组全部省时 37.3–63.9%。DeepSeek 主干下在线 token 从 AFlow 的 21.11M 降到 **13.45M（−36.3%）**。

收益形态因任务而异：难任务赢质量——MATH **+6.79** 分且耗时 −62.1%，多步推理给了中间结果作废后续的更多机会；近饱和任务赢效率——GSM8K 大量提前终止，路线编辑率 100%（多为剪枝而非纠错）；HumanEval 54.20% 的路线运行中被真改（纠错型适应），而 MBPP（5.87%）、DROP（7.75%）、HotpotQA（2.88%）大多稳定。消融（HumanEval + Qwen3-8B）定位贡献：去全部离线结构，准确率 92.37→77.86 且多用 9.26 分钟；只去组合技能损失接近（78.63），说明离线收益主要来自组合技能封装；去 Insert 降 9.93 分、多用 14.74 分钟；去 Replace 只降 1.53 分却多用 15.79 分钟——Replace 的核心价值是剪枝与逃离死路，而非提正确率。

## 4. 亮点与贡献（Why it matters）

- 把"续段失效"提炼成独立编排问题，并给出"校验 + 最小范围编辑"的测试期需求，问题刻画清晰、易迁移到其他 Agent 系统。
- 把工作流搜索的**轨迹**当经验来源，蒸馏成"组合技能（封装稳定片段）+ 转移图（暴露结果依赖分支）"双形态，比只留最终工作流信息量大得多。
- "规划多步、承诺一步"配合 Retain/Insert/Replace，在全盘重跑与逐节点重规划之间找到成本—响应折中，且保留已完成进度。
- 质量与效率双指标同时领先，收益模式可解释（质量在难任务、效率在饱和任务），说明不是靠堆预算换分数。
- 在 3 个能力差异明显的主干上结论一致，说明"选择性路线编辑"是具有泛化性的编排原则。

## 5. 局限与可改进点（个人点评）

- **评测范围偏窄。** 全是纯文本代码/问答/数学基准，无真实工具副作用、无长程交互界面；作者也承认 DROP/HotpotQA 的难点在证据抽取而非路线不稳定——对交互型/视觉型任务的适用性未被证明。
- **离线依赖被轻描淡写。** 组合技能与转移图全部来自 AFlow 训练分区的可执行搜索轨迹，需固定算子集与可回滚环境；对图中没出现过的失效类型只能降级到 Replace，泛化上限受 trace 覆盖度约束。GUI 场景没有 AFlow 这类成熟搜索流程，轨迹多来自人工标注或在线数据，离线管线无法照搬。
- **在线控制偏启发式。** Insert/Replace 的划分是"图是否命中"的离散规则，没有学习"何时信局部反应、何时该重规划"；预算用尽只标记 incomplete，缺优雅恢复出口。
- **实验细节单薄。** 消融只在 HumanEval+Qwen3-8B 单设置上做；未见多次 seed；全文未开源，控制器判定阈值等实现细节缺失。

## 6. 对我们的启示：对 GUI Agent 的可借鉴点

TROVE 的语言几乎可逐条翻译成 GUI Agent 的编排语言，是本库"跨域参考"价值最高的一类论文。

- **"计划想远、执行看近"应成为 GUI 多步任务的默认架构。** 计划器可输出长路线（search→open product→add to cart→checkout），控制器却只 commit 一步，每步用界面语义状态（DOM/无障碍树/OCR/grounding 输出）当"边界证据"，失效才动手。截图与长 DOM 使 GUI 单步成本远高于文本，能少重规划一次都是净赚。
- **技能蒸馏二分法可直接落地。** GUI 领域"从交互轨迹提炼可复用技能"的工作（CoSkill、Trace2Tower、"From Interaction Traces to Persistent Skills"等）可套用其判据：登录、搜索筛选、表单填写等稳定子流程→组合技能；"界面状态决定下一步选谁"→GUI 版转移图，条件从文本事件换成"界面前置条件 + 动作可达性"。
- **Insert/Replace 对应两类 GUI 恢复策略。** Insert 实例化为"从技能库取局部恢复动作"（关弹窗、刷新、重新登录、缺元素重试）；Replace 才推翻重来。多数 GUI Agent 论文把二者混为一谈，TROVE 给出按失效严重程度分级的最低成本修法。
- **剪枝价值被 GUI 严重低估。** GSM8K 100% 编辑率且多为提前终止提示：GUI 里"目标已达成却继续空点"既浪费又危险（易触发副作用），廉价的终止判定可能比更强的规划器更划算。当然落地难点也在 GUI 侧暴露：把像素/DOM 变成可靠的"作废信号"本身需 grounding 或状态差分模型，这是 TROVE 思想工程化的前置模块。

## 7. 延伸阅读

- **AFlow**（Zhang et al., ICLR 2025）：可执行代码工作流自动生成，TROVE 的算子与搜索轨迹来源。
- **MaAS**（Zhang et al., ICML 2025）与 **LAS / LLM-as-Scheduler**（Xiang et al., ACL 2026）：执行前架构搜索与 DAG 内在线调度两条基线。
- **GPTSwarm**（Zhuge et al., ICML 2024）：把 Agent 系统当可优化计算图。
- **Voyager / ExpeL**：可执行技能库与经验抽取早期代表；**AdaPlanner / DoReMi**：按执行反馈修复高层计划的路线适应。
- **GraSP / Agent Skills at Scale**（Xia et al. 2026 / Li et al. 2026）：大规模技能组织与图结构组合。
