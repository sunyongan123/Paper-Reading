# TROVE: Adaptive Agent Skill Orchestration via Trace-Grounded Route Validation and Editing

> TL;DR：把工作流搜索的轨迹蒸馏成"组合技能 + 转移图"，在线执行时只 commit 一步、按边界证据对失效后缀做 Retain/Insert/Replace 最小范围修订。

## 2. 论文要解决的核心问题

- **要解决什么问题**：多步 Agent 编排中，一旦中间结果使尚未执行的"待续后缀"不再适用（如 review 发现草稿缺证据、或答案已生成使验证步骤冗余），系统要么硬跑过期步骤、要么整体重规划。本文把这一现象命名为 **续段失效（continuation invalidation）**，并把它作为独立问题解决。

- **为什么重要**：编排的核心不在"每步多强"，而在"何时调用、以何顺序调用"。中间证据能否被转成有效计算，还是被过期执行路径白白浪费，直接决定质量与算力开销。不解决会导致：错误级联、算力浪费、已完成的进度与工件被丢弃。

- **现有方法有什么不足**：论文明确点名三个层级的基线——**AFlow**（数据集级工作流搜索后原样重放，执行中不感知结果）；**MaAS**（query 级执行前采样架构，但一旦开跑不按中间结果调整）；**LAS**（节点级在线调度，但只能在一个预定义 DAG 内择路）。三者共同缺陷是"结构性决策发生在决定性结果可见之前"。

- **Research Gap**：作者认为前人缺一个"中间地带"——全盘重跑丢前缀丢工件，逐节点重规划则延迟/token/方差高且覆盖仍有效的部分。TROVE 主张补上的是**只修订被运行时证据作废的那一小段未来**：保留已执行前缀与工件、保留仍有效的后继、局部修复、仅对失效后缀重规划。

## 3. 方法核心思想（三层拆解）

### 3.1 一句话概括方法

把"规划"与"承诺"解耦——规划视野横跨多步，承诺视野只有一个动作；每次执行路线头部一个技能、观察边界结果后再决定下一步，离线与在线两段协作。

### 3.2 方法总览（Pipeline）

- **输入/输出**：输入为任务 `x` + 离线构建的技能注册表 `S` + 转移图 `G`；输出为最终结果（或预算耗尽标记 incomplete）。
- **离线经验抽取**：复用 AFlow 在训练集搜索时留下的**整条评估轨迹**（相邻候选 `W_i→W_{i+1}` 的 Δscore/Δtime 与中间结果），而非只留最终工作流。稳定高频片段封装为**组合技能**（对外只返回一个聚合边界结果）；结果依赖型续接显式存为**技能转移图**边 `τ=(s,e,c,g)`。最终注册表含 **10 原子技能 + 41 组合技能**，转移图 **244 条边**。
- **在线执行与修订**：规划器提出 ≤4 步临时路线，但只 commit 头部技能；观察边界结果后三选一——**Retain**（后继仍有效，原样保留不花路由调用）、**Insert**（后继失效但下游意图成立，从图查一个 trace 支撑的局部反应插到后缀前）、**Replace**（图弃权/证据冲突/需大改时，LLM 只重新生成未执行部分）。任务完成即提前终止并丢弃后缀。
- **连接**：数据流是"技能→边界结果→控制器判定→更新后缀→再 commit 头部"的循环，控制流以离散规则（图是否命中）为主、LLM 为辅。

### 3.3 真正的创新点（去伪存真）

- **真·方法创新**：① 将"续段失效"提炼为独立问题并给出"校验 + 最小范围编辑"的测试期需求；② 用**评估轨迹的成对 Δscore/Δtime** 而非最终工作流作为经验来源；③ "规划多步、承诺一步"的 Retain/Insert/Replace 修订原语。
- **工程组合**：原子技能标准化接口、AFlow 算子封装、LLM 重规划器均为既有组件的拼装，本身不新。
- **对性能提升最关键的设计**：ablation 显示**组合技能封装**贡献了离线收益的主体（去掉它 −13.74 分，几乎等于去掉全部离线结构的 −14.51 分）；**Insert** 贡献主要质量（−9.93 分），**Replace** 主要贡献效率（仅 −1.53 分却多花 15.79 分钟）。
- **证据不足 / 仅声称有效**：离线结构对"图中未出现过的失效类型"的泛化能力仅有定性表述，无覆盖度/召回率的定量评估；控制器阈值、图命中判定的实现细节因未开源而无法复核。

## 4. 具体技术细节

### 4.1 模型结构

- **Base model**：非单一模型，用三套主干评测——**DeepSeek-V4-Flash**、**GPT-4o-mini**、**Qwen3-8B**（后者为开源 8B）。三者均作为 LLM（无视觉编码器，纯文本任务）。
- **无参数训练/微调**：所有模型只做在线调用（规划/技能/重规划/组合内部调用），离线阶段产出的技能与转移图是**符号化结构**而非模型权重。

### 4.2 离线阶段（经验抽取，"训练"）

| 阶段 | 目标 | 训练什么能力 | 数据来源 | 数据形态 | 目标 / 机制 |
|---|---|---|---|---|---|
| Stage 1 原子技能标准化 | 定义动作空间 | 统一 IO 契约 | AFlow 算子 | 带输入/产物/状态/重复约束的接口 | 规则封装，无 Loss |
| Stage 2 组合技能提炼 | 隐藏稳定局部决策 | 稳定子目标封装 | AFlow 训练集搜索轨迹的局部修改 | 相邻候选 Δscore/Δtime + 中间结果 | 判据：顺序与数据依赖稳定、子目标连贯、IO 契约一致、执行不依赖外层路线 |
| Stage 3 转移图构建 | 暴露结果依赖分支 | 结果→下一步映射 | 同上（被评估过的局部修改） | 边 `τ=(s,e,c,g)` | 每条边来自被评估的局部改动，非单纯邻接 |

> 数据划分约 1:4（训练:测试），如 HumanEval 33/131、MBPP 86/341、MATH 119/486、GSM8K 264/1055、DROP 与 HotpotQA 各 200/800；所有测试期结构在评测前冻结。

### 4.3 在线推理流程

- **多步、规划-执行-反思式循环**：规划器先出临时路线 `R0`，控制器只执行头部技能 `st` → 观察边界结果 `ot` → 更新历史 → 判定终态/Retain/Insert/Replace → 更新后缀 → 循环。
- **终止条件**：产出最终结果即提前终止并丢弃后缀；或触达步数上限（**在线最多 6 次 top-level 技能调用**）、重复/无进展约束后标记 incomplete 按评测器打分。
- **Insert 后不自动执行原后继**，而是重新检查；Replace 的 LLM 重规划器接收任务、最新结果、执行历史、待执行后缀、可用技能，并可选把图命中 `gt` 作为路由先验。

## 5. Benchmark 与实验设置

### 5.1 Benchmark 一览表

| Benchmark | GUI 场景 | 任务类型 | 数据规模（训练/测试） | 输入格式 | 输出格式 | 评测指标 |
|---|---|---|---|---|---|---|
| HumanEval | General（纯文本） | 代码生成 | 33 / 131 | 函数签名+文档串 | 代码 | pass@1 |
| MBPP | General | 代码生成 | 86 / 341 | 题目描述 | 代码 | pass@1 |
| MATH | General | 数学推理 | 119 / 486 | 数学题 | 答案 | accuracy |
| GSM8K | General | 数学推理 | 264 / 1055 | 应用题 | 答案 | accuracy |
| DROP | General | 问答（离散推理） | 200 / 800 | 段落+问题 | 答案 | token F1 |
| HotpotQA | General | 多跳问答 | 200 / 800 | 问题 | 答案 | token F1 |

> 并发 10，单样本超时 300 秒；耗时含在线规划/执行/验证/重规划，排除一次性离线搜索与蒸馏。

### 5.2 实验结果分析

- **主结果**：6 基准 × 3 主干共 **18 组**，对比 AFlow（数据集级）、MaAS（query 级执行前）、LAS（节点级 DAG 内）。TROVE **15 组最佳/并列最佳分数、16 组线上耗时最短**。相对 AFlow：**16 组提分 0.12–31.37 分、16 组省时 2.9–86.7%**；相对 MaAS：**17 组不降分（0.48–46.27）、18 组全部省时 6.1–94.6%**；相对 LAS 六个代码设置：**5 组提分 1.47–7.03、6 组全部省时 37.3–63.9%**。DeepSeek 主干在线 token 由 AFlow 的 21.11M 降至 **13.45M（−36.3%）**。
- **收益形态可解释**：难任务赢质量（MATH **+6.79 分**且耗时 **−62.1%**，多步推理给足"结果作废后续"的机会）；近饱和任务赢效率（GSM8K 大量提前终止，**编辑率 100%**，多为剪枝非纠错）。路线编辑率（DeepSeek）：HumanEval **54.20%**（纠错型适应）、MBPP 5.87%、DROP 7.75%、HotpotQA 2.88%、MATH 98.97%。
- **Ablation（HumanEval + Qwen3-8B，全量 92.37 分 / 24.36 分钟）**：去全部离线结构 → 77.86（−14.51，+9.26min）；去组合技能 → 78.63（−13.74，+8.94min），说明离线收益主要来自组合技能；去 Insert → 82.44（−9.93，+14.74min），是质量的命门；去 Replace → 90.84（−1.53，+15.79min），核心价值是剪枝/逃离死路而非提正确率。

## 6. 亮点与贡献（Why it matters）

1. 把"续段失效"提炼为独立编排问题，给出"校验 + 最小范围编辑"的测试期需求，问题刻画干净、可迁移到其他 Agent 系统。
2. 用**搜索轨迹而非最终工作流**当经验来源，蒸馏成"组合技能 + 转移图"双形态，信息量远超只留一个最优 DAG。
3. "规划多步、承诺一步"配合 Retain/Insert/Replace，在全盘重跑与逐节点重规划之间找到成本—响应折中，且保留已完成进度。
4. 质量与效率双指标同时领先，且收益模式可解释（难任务赚质量、饱和任务赚效率），说明不是堆预算换分数。
5. 三个能力差异明显的主干结论一致，"选择性路线编辑"具备跨模型泛化性。

## 7. 局限与可改进点（个人点评）

- **评测范围偏窄**：全是纯文本代码/问答/数学，无真实工具副作用、无长程交互界面；作者也承认 DROP/HotpotQA 难点在证据抽取而非路线不稳定——对交互型/视觉型任务的适用性未被证明。
- **离线依赖被轻描淡写**：组合技能与转移图完全来自 AFlow 训练分区的可执行搜索轨迹，需固定算子集 + 可回滚环境；图中未见过的失效只能降级到 Replace，泛化上限受 trace 覆盖度约束。GUI 场景没有 AFlow 这类成熟搜索流程，离线管线无法照搬。
- **在线控制偏启发式**：Insert/Replace 的划分是"图是否命中"的离散规则，没有学习"何时信局部反应、何时该重规划"；预算耗尽只标 incomplete，缺优雅恢复出口。
- **实验细节单薄**：ablation 仅 HumanEval + Qwen3-8B 单设置，未见多 seed；未开源致控制器阈值、图命中判定不可复核。

## 8. 对我们的启示 / 可借鉴点

> 本篇属【Agent 方法论域】，其对 GUI Agent 的可借鉴点如下。

- **"计划想远、执行看近"应是 GUI 多步任务的默认架构**：计划器输出长路线（search→open product→add to cart→checkout），控制器只 commit 一步，用界面语义状态（DOM/无障碍树/OCR/grounding 输出）当"边界证据"，失效才动手。GUI 单步成本（截图+长 DOM）远高于文本，少重规划一次就是净赚。
- **技能蒸馏二分法可直接落地**：把"稳定子流程（登录/搜索筛选/表单填写）→组合技能"、"界面状态决定下一步→GUI 版转移图"判据迁移到 GUI 交互轨迹蒸馏（CoSkill、Trace2Tower 等），条件从文本事件换成"界面前置条件 + 动作可达性"。
- **Insert/Replace 对应两类 GUI 恢复策略**：Insert = 从技能库取局部恢复动作（关弹窗、刷新、重登录、缺元素重试）；Replace 才推翻重来。多数 GUI Agent 论文把二者混为一谈，TROVE 给出按失效严重程度分级的最低成本修法。
- **剪枝价值被 GUI 严重低估**：GSM8K 100% 编辑率且多为提前终止，提示 GUI 里"目标已达成却继续空点"既浪费又危险（易触发副作用），廉价的终止判定可能比更强的规划器更划算。落地难点在把像素/DOM 变成可靠的"作废信号"，这需要 grounding 或状态差分模型作为前置。

## 9. 延伸阅读

- **AFlow**（Zhang et al., ICLR 2025）：可执行工作流自动生成，TROVE 的算子与搜索轨迹来源。
- **MaAS**（Zhang et al., ICML 2025）／**LAS / LLM-as-Scheduler**（Xiang et al., ACL 2026）：执行前架构搜索与 DAG 内在线调度两条基线。
- **GPTSwarm**（Zhuge et al., ICML 2024）：把 Agent 系统当可优化计算图。
- **Voyager / ExpeL**：可执行技能库与经验抽取早期代表；**AdaPlanner / DoReMi**：按执行反馈修复高层计划。
- **GraSP / Agent Skills at Scale / SkillGraph**（Xia et al. 2026 / Li et al. 2026a / Li et al. 2026b）：大规模技能组织与图结构组合。
