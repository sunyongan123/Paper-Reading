# CUA-Universe: A Scalable and Dynamic Environment for Hybrid GUI+CLI Agents

> 一句话 TL;DR：把真实桌面软件改造成"共享应用状态"的 GUI+CLI 混合环境，端到端批量产出混合任务与高质量轨迹，让 9B 开源模型学会"何时点鼠标、何时敲命令"。

## 2. 论文要解决的核心问题

- **要解决什么问题**：让 computer-use agent 摆脱"只能走 GUI"或"只能跑终端"的单模态困境，学会在**同一应用状态**上动态编排 GUI（视觉定位）与 CLI（批量/精确执行）。
- **为什么重要**：真实人类的电脑使用是混合的——先用眼睛在界面里定位目标，再用一条命令完成高吞吐操作。当前主流 agent 要么 GUI-only，轨迹冗长脆弱（OSWorld 上几步的活被拆成几十次点击）；要么 CLI-only，看不见布局、只会写脆弱脚本。这个缺口卡住的是"跨模态编排"这一项下游核心能力。
- **现有方法有什么不足**（论文明确批评的基线/范式）：
  - 环境合成系（InfiniteWeb、GUI-Genesis、AutoWebWorld、CUA-Gym、Gym-Anything）：只产出 GUI 单模态轨迹，**结构上无法产生"何时离开 GUI"的信号**，且多为人工网页/模拟器，存在 sim-to-real 差距。
  - 混合 agent 系（CoAct-1、UltraCUA）：用**固定任务集 + 固定工具集**训练，工具从通用文档/代码库挖掘，未锚定每个真实应用的状态；无法规模化造新环境、新数据。
  - CLI 系（Terminal-Bench、TerminalWorld、CLI-Universe）：纯终端，缺视觉感知。
- **Research Gap**（作者 claim，忠实转述）：缺一条"把任意桌面软件批量改造成共享状态混合环境、并持续产出任务与轨迹"的可扩展流水线；缺"何时切接口"这种编排能力的显式训练数据。

## 3. 方法核心思想（三层拆解）

### 3.1 一句话概括方法

"环境→数据"闭环：用编码智能体把 16 个真实桌面应用改造成 GUI+CLI 共享状态的混合环境（App-Forge），从中组合合成混合任务（Task-Weave），再引导 rollout 走高效混合路径并收割高分轨迹（Path-Steer），最后 LoRA 蒸馏到一个 9B 开源模型。

### 3.2 方法总览（Pipeline）

- **输入**：真实桌面软件 + 真实种子文件（.blend、.odp、.aup3 等真实工程状态）。
- **输出**：可复现混合环境 + 可控难度的混合任务 + ≥0.75 分的高质量混合轨迹 + 一个 9B 混合编排模型。
- **三大模块**（数据流：环境→任务→轨迹→训练）：
  1. **App-Forge（造环境）**：安装器智能体在持久 VM 里装好、调好、验活软件，配置蒸馏成可复现镜像；再构建与 GUI 对齐的 CLI 工具面——**发现**原生命令（blender --python-expr、cvlc）、**包装**脚本 API（bpy、UNO、Script-Fu）、现有接口不够时**生成**智能体原生 CLI（受 CLI-Anything 启发）。GUI/CLI 操作同一工程状态，外部 CLI 改动后用轻量适配层刷新过期 GUI 视图。规模 16 应用、约 404 条 agent 可见命令。
  2. **Task-Weave（造任务）**：三段式——①探索智能体轨迹抽象成"可复用操作"（如"导出为 glTF"而非"点这个按钮"）沉淀到操作池；②以真实种子文件为初始态，组合操作链实例化任务，难度用链长控制；③ReAct 式评审智能体在真实应用里跑一遍，过滤不可行/有歧义/种子已满足的任务。
  3. **Path-Steer（造轨迹）**：给 rollout 智能体统一 GUI+CLI 动作接口；从操作链推导"混合执行先验"（批量/精确/高吞吐→CLI，依赖视觉布局→GUI，只给模态级引导不给低层动作）；VLM 评审（GPT-5.4）打分，保留 ≥0.75 的高分轨迹作后训练数据。

### 3.3 真正的创新点（去伪存真）

- **真·方法创新**：**"环境即数据源"这一可扩展范式**是核心贡献——把"手工造单条数据"升级为"用智能体把整个软件变成持续产任务/产轨迹的机器"。App-Forge 的三层工具面（发现/包装/生成）与 Task-Weave 的"操作池 + 种子条件化 + 执行验证"组合是本文最原创的部分。
- **工程组合**：Path-Steer 本质是"rollout 提示里加一句模态引导 + 阈值过滤"，无新损失、无新结构；LoRA 蒸馏是标准 STaR/ReST 式"学教师高分上尾"。
- **对性能提升最关键的设计**：**Path-Steer 消融**（Table 3）证明"模态级引导"这一轻量设计同时提升质量与效率——Kimi K2.5 把关通过率 0.44→0.51、Mean Score 0.63→0.71、单任务成本 $0.31→$0.26，且跨骨干（Seed2.1 Pro 0.45→0.54）复现；w/o 组同样有 CLI 访问权，说明增益来自"引导"而非"CLI 本身"。
- **证据不足 / 仅声称有效**：作者强调"学的是可迁移的 CLI 选用能力而非死记命令"，但 CUA-Verse 是**域内**评测（8 应用与训练同域），3× 提升里多少来自应用内命令记忆、多少来自编排泛化，无法拆清；唯一硬证据是 OSWorld 8-app OOD-only LoRA 的 +3.2 点零样本提升，幅度与域内 +16.8 点差距悬殊，迁移性 claim 偏乐观。

## 4. 具体技术细节

### 4.1 模型结构

**不训练新结构。** 评测与数据生成涉及多个现成模型：App-Forge 用 Codex 编码智能体（GPT-5.6）驱动；Task-Weave 操作抽象/任务合成用 Kimi K2.5；任务评分用 VLM judge（GPT-5.4）。最终产物模型为 **Qwen3.5-9B（MLLM，含视觉塔）**，未改结构。

### 4.2 训练流程（本篇不训练模型，只做一次后训练微调）

本篇是**环境/benchmark 工作**，核心机制在环境侧而非训练侧。仅有的"训练"是最后的 LoRA 微调，作为"环境有用性"的验证手段，而非方法论主体：

| 阶段 | 目标 | 训练能力 | 数据来源 | 数据形态 | Loss |
|---|---|---|---|---|---|
| LoRA SFT | 验证混合环境产出的轨迹可蒸馏出混合编排能力 | 何时用 CLI / 何时用 GUI | Path-Steer 收割的 ≥0.75 分轨迹（Kimi K2.5 rollout） | Qwen XML 格式 step 级样本，3 帧历史；4,923 episodes / ~235K steps | 标准 SFT（next-token），非 RL |

关键设定：base 权重、视觉塔、多模态对齐层**全部冻结**，仅训 LM 线性层（LoRA rank 8 / α 32 / dropout 0.05 / all-linear）；lr 1e-4、warmup 0.05、3 epoch、8×A100 约 2 天（ms-swift，ZeRO-2）。

### 4.3 环境与数据生成机制（本篇重点）

- **VM/硬件**：每任务跑在隔离 OSWorld VM（4 vCPU / 4GB RAM，copy-on-write 覆盖盘），动作后 3s settle；所有 agent 共享 **60-step 预算**，Qwen 系用 3 帧历史、每步最多 4 图。
- **数据生成成本**：单次 rollout 平均约 5 分钟，全流水线 CPU-bound 且天然可并行——单台 **128 核 CPU 主机**并行 32 个 VM，约 **1.3~1.5 天**产完全部训练数据，**无需 GPU 集群**，这是其"可复现"卖点的关键。
- **评审器可靠性**（支撑数据可信度）：VLM judge 接受集精度 **99.0%**（475/480，0 例硬失败）、假阴性率 5.2%、与人标 Cohen's κ=**0.94**（"几乎完美"），说明阈值 0.75 是"刻意筛掉部分完成"的保守训练过滤。

## 5. Benchmark 与实验设置

### 5.1 Benchmark / 环境一览表

| Benchmark / 环境 | GUI 场景 | 任务类型 | 数据规模 | 输入格式 | 输出格式 | 评测指标 |
|---|---|---|---|---|---|---|
| **CUA-Universe 环境**（16 应用，8 OSWorld + 8 自建） | Desktop | 端到端混合任务合成 + 轨迹生成 | ~404 条 agent 可见命令；4,923 训练 episodes | 截图 + 指令 + CLI 工具注册表 | GUI（pyautogui）/ CLI 交错动作 | 任务 verifier（VLM judge 0~1） |
| **CUA-Verse 基准**（留出） | Desktop（8 扩展应用） | 端到端混合（每任务均需双模态） | 160 条（8×20），与训练不相交；平均 5.7 个抽象工具/任务，59% CLI | 截图 + 指令 + CLI 注册表 | GUI/CLI 动作 | VLM-judge Score + Steps + Token |
| **OSWorld**（迁移评测） | Desktop（8 OSWorld 应用） | 端到端，GUI vs GUI+CLI 对照 | 244 条受控（排除 os/multi-app） | 截图（GUI）/ +execute_cli（GUI+CLI） | 坐标动作 / CLI 调用 | SR（官方 verifier）+ Steps + Token |
| **OSWorld-MCP**（泛化评测） | Desktop | 端到端 + MCP 工具调用 | 244 条（158 MCP 工具，训练中从未见过） | 截图 + MCP 工具集 | GUI / 工具调用 | Score、Strict SR、TIR、ACS、Token |

### 5.2 实验结果分析

**主结果（对照 Kimi K2.5、Seed2.1 Pro、GPT-5.5、Qwen3.5-9B、EvoCUA-8B）：**

- **CUA-Verse**：Ours **Score 0.582**，开源最佳——超教师 Kimi K2.5（0.522），仅次闭源 Seed2.1 Pro（0.599）与 GPT-5.5（0.768）；相对未微调 Qwen3.5-9B（0.189）约 **3×**，步数 −37%、token −60%（每集 255K vs 643K）。能力分层明显：音视频最强（Audacity 0.815、OBS 0.605），3D 最弱（Blender 0.398、Godot 0.460）。
- **OSWorld 迁移**：GUI+CLI 模式 **SR 40.2%**，较纯 GUI 23.4% **+16.8 pts**；加 CLI 把此前失败的 **+41 个任务**变成功，而其余模型仅 +2~+8。步数（28.6）与 token（286.5K）全场最省，同类成功任务 **2.35× 步数节省**。
- **OSWorld-MCP 泛化**：SR 20.90%→**28.69%**（+7.79），TIR 10.66%→**23.36%**，Score（29.51%）反超 Seed2.1 Pro（27.03%），证明编排能力可迁移到未见工具接口。

**Ablation 说明了什么：**

1. **Path-Steer 消融**（Table 3，320 任务）：Kimi K2.5 把关通过率 0.44→0.51、Mean Score 0.63→0.71、成本 $0.31→$0.26；Seed2.1 Pro 同向（0.45→0.54）。**验证的结论：模态级引导（而非 CLI 访问权本身）是增益来源**，且跨骨干成立。
2. **OOD-only 训练**（Table 5）：仅用与 OSWorld 不相交的 8 应用训练，零样本 SR 24.2%→27.4%（+3.2），在 7/8 应用上提升，最大 Thunderbird +13.4——证明学到部分应用无关的编排能力，但也暴露幅度远小于域内，迁移性有限。
3. **动作模态分布**（Table 4）：未微调 Qwen3.5-9B 的 CLI 使用率 0%（纯 GUI 撞满预算）；Ours 25.3%；GPT-5.5 100% CLI 仍未满分（0.768）——**结论是"会编排"而非"多用 CLI"才是关键**，这是本文最干净的一条机理发现。

## 6. 亮点与贡献（Why it matters）

1. **环境即数据源**：把"手工造数据"升级为"把软件改造成持续产任务/轨迹的机器"，给出端到端可复现配方，为 GUI agent 后训练开辟了一条新的规模化轴。
2. **跨模态编排被证明可学习、可迁移**：不仅"会用 CLI"，而是学会"何时离开 GUI"，且能零样本泛化到训练中从未见过的 MCP 工具接口。
3. **效率被提到一等公民**：全程以步数/token 的成对增益（如 2.35× 步数节省）与成功率并重，正面回应 GUI agent"轨迹冗长"的批评。
4. **极低复现门槛**：单台 128 核 CPU 一天出头产完全部数据 + 8×A100 两天微调，无需 GPU 集群造数据。
5. **评审器可靠性公开验证据实**（κ=0.94、接受集 0 硬失败），为"用 VLM judge 过滤训练数据"提供了可信度背书。

## 7. 局限与可改进点（个人点评）

- **任务仍困在单应用内**：作者自承每条任务只锚定一个应用的共享状态，跨应用长流程（真实工作常态）未涉及；而 OSWorld 的跨应用任务恰好被排除在受控 244 条之外，等于绕开了最难的部分。
- **域内泛化无法拆清**：CUA-Verse 8 应用与训练同域，3× 提升里"命令记忆"与"编排泛化"贡献占比不明；唯一 OOD 证据仅 +3.2 点，迁移性 claim 偏强。
- **策略上限受教师约束**：只做 SFT，模型被 Kimi K2.5 上尾封顶；作者把"用 verifier 做 RL 超越教师"列为 next step，等于承认当前未榨干流水线产出的 verifier 价值。
- **对比公平性存疑**：OSWorld 仅测 244 条子集，各家历史帧/图像数不同（自家 3 帧/4 图，闭源各自默认）；OSWorld-MCP 也在子集报告；本质是"微调过的 9B vs 未调的大模型"，归因需谨慎。
- **适用范围受限**：App-Forge 假设软件开源或可脚本化、环境固定在桌面 Linux；Chrome、VS Code 等命令面偏浅（10~15 条），生态复杂软件的覆盖有限。
- **代码与数据未落地**：全文只承诺开源却无 URL，环境/基准的复现性目前无法独立验证，是本工作当前最大的可信度缺口。

## 8. 对我们的启示 / 可借鉴点

- **"造不了环境就造不了数据"**：最有价值的是这套**按应用划分的原子模块**——每个应用 = 种子文件 + CLI 工具面 + 验证器 + 适配器。挑任意一个桌面工具照此配方搭建，就能持续合成带客观验收标准的任务，摆脱手工写用例。
- **模态级先验可以白拿效率**：Path-Steer 只加一句"这条操作走 CLI 更划算"的引导，把关通过率就从 0.44 提到 0.51、成本降 16%。我们自建数据管线可直接借鉴"低成本引导 + 阈值过滤"的轨迹筛选策略。
- **把效率指标写进评测与数据过滤**：同时报告步数/token 成对增益，能逼 agent 少做无谓点击；数据收集时把"是否多余点击"作为过滤维度。
- **VLM judge 可用但必须验**：本文给出对齐度验证的具体做法（分层抽样 + 人类盲评 + 混淆矩阵重加权），建议给我们自家自动评估器建立同样的校准流程。
- **"编排能力 ≠ 多用 CLI"的机理洞见**：GPT-5.5 100% CLI 仍未满分——训练目标应指向"按任务选模态"，而非"最大化某种模态"，这对我们设计 reward 有直接指导意义。
