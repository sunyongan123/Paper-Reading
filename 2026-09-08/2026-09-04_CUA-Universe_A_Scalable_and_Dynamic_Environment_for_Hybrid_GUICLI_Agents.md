## 1. 研究背景与要解决的问题

现在的"会用电脑的智能体"（Computer-Use Agent）大多只走 GUI 路线：给模型一张屏幕截图，让它用鼠标键盘一步步点。这在 OSWorld、AndroidWorld 上虽能跑通，但轨迹往往又长又脆，几步就能干完的批量操作被拆成几十次点击。反过来，纯命令行（CLI）智能体在终端任务上很强，却"看不见"界面——遇到依赖布局、状态的任务只会写脆弱的脚本。真实人类用电脑是混合的：先用眼睛在 GUI 里定位目标，再用一条命令完成大批量操作。要训练这样的 agent，卡在两个耦合瓶颈：一是同时支持 GUI+CLI、共享应用状态的真实环境很难规模化搭建，几乎每个应用都要人工工程；二是现有智能体没学会"何时切换界面"这种编排能力。本文要补的缺口，就是把真实桌面软件批量改造成混合环境的"环境→数据"流水线，用产出的数据教会模型跨模态编排。

## 2. 核心方法 / 思路

CUA-Universe 提出"环境到数据"的闭环流水线，分三件套，把"造环境、造任务、造轨迹"全部交给智能体自动完成。

**App-Forge（自动造环境）**：解决两个应用专属瓶颈——安装适配与工具构建。一个"安装器智能体"操作持久 VM，把目标软件装好、调好、验活，配置蒸馏成可复现镜像；随后构建与 GUI 对齐的 CLI 工具面，工具来源分三层：直接**发现**原生命令行（如 cvlc、blender --python-expr）、**包装**脚本 API（如 bpy、UNO、Script-Fu）、现有接口不够时**生成**智能体原生 CLI（灵感来自 CLI-Anything）。GUI 与 CLI 操作同一份工程状态，外部 CLI 改动后用轻量适配层刷新过期的 GUI 视图。最终规模达 16 个真实桌面应用、约 404 条对智能体可见命令。

**Task-Weave（自动造任务）**：三段式组合合成。先把探索智能体的轨迹抽象成"可复用操作"（如"导出场景为 glTF"而非"点这个按钮"）沉淀到操作池；再以真实种子文件（.blend 场景、.odp 演示稿等）为初始状态，组合操作链实例化任务，任务难度用链长控制；最后由 ReAct 式评审智能体在真实应用里跑一遍，过滤掉不可行/有歧义/种子已满足的任务，把"幻觉任务"挡在上线前。

**Path-Steer（高效路径收集轨迹）**：给 rollout 智能体统一 GUI+CLI 动作接口；再从任务的操作链推导"混合执行先验"——批量、精确、高吞吐操作提示走 CLI，依赖视觉布局的操作提示走 GUI，只给模态级引导、不给低层动作；最后用 VLM 评审（GPT-5.4）对轨迹打分，保留 ≥0.75 的高分混合轨迹作后训练数据。

**训练配方**：把收获的 4,923 条验证轨迹（约 23.5 万步记录）转成 Qwen XML 格式，用 LoRA 微调 Qwen3.5-9B 3 个 epoch，8×A100 约 2 天。视觉塔与对齐层冻结，本质是把教师（Kimi K2.5）的成功轨迹做**蒸馏式 SFT**。值得强调的是，整个数据生成只需一台 128 核 CPU 机器并行跑 32 个 VM，约 1.3~1.5 天即可产完，完全不需要 GPU 集群。

与已有工作（CoAct-1、UltraCUA 等"固定任务集+固定工具集"）相比，关键差异是：它提供了一条**可扩展地构造环境并持续产出数据**的路子，把工具层锚定在每个真实应用的共享状态上，而不是挖掘通用工具库。

## 3. 关键实验结果

评测横跨三个互补维度：

**① 域内基准 CUA-Verse**（160 条留出混合任务，8 应用×20 条，与训练数据不相交）：训练后的模型 Score 0.582，是开源最佳——超过教师 Kimi K2.5（0.522），仅次于闭源 Seed2.1 Pro（0.599）与 GPT-5.5（0.768）；相对未微调的 Qwen3.5-9B（0.189）提升约 3 倍，且步数 −37%、token −60%（每集 255K vs 643K）。能力分布上音视频应用最强（Audacity 0.815、OBS 0.605），3D/空间类偏弱（Blender 0.398、Godot 0.460），3D 数据覆盖仍有缺口。

**② 跨域迁移 OSWorld**（244 条受控任务，排除 os 与 multi-app 分片）：GUI+CLI 模式下 SR 40.2%，较纯 GUI 的 23.4% 提升 +16.8 个百分点；加 CLI 把此前失败的 **+41 个任务**变成成功，而其余所有模型仅 +2~+8。该模型也是全场步数（28.6）与 token（286.5K）最省的一个。8 应用仅 OOD 训练（不含 OSWorld 的 8 个域）也能零样本提升 +3.2 个百分点，说明学到的是"可迁移的 CLI 选用与编排能力"而非死记应用命令。

**③ 未见工具接口泛化 OSWorld-MCP**（模型训练中从未见过 MCP 动作空间）：SR 从 20.90% 提到 28.69%（+7.79），TIR（工具调用决策准确率）从 10.66% 翻倍到 23.36%，Score 反超 Seed2.1 Pro。**Path-Steer 消融**：对 Kimi K2.5 把关通过率从 0.44→0.51，单任务成本从 $0.31→$0.26，且该收益在 Seed2.1 Pro 上跨骨干复现。评审器可靠性：接受集精度 99.0%、与人类标注 Cohen's κ=0.94。

## 4. 亮点与贡献（Why it matters）

1. **环境即数据源**：把"手工打造单条数据"升级为"用智能体把整个软件变成持续产任务/产轨迹的机器"，并给出端到端可复现配方。
2. **混合编排被证明可学习、可迁移**：不仅是"会用 CLI"，而是学会"何时离 GUI"，该技能还能零样本泛化到从未见过的 MCP 工具接口。
3. **把效率纳入一等公民**：全文以步数/token 增益（如同类成功任务上 2.35× 步数节省）与成功率并重评测，回应了 GUI agent"轨迹冗长"的批评。
4. **极低成本即可复现**：单台 CPU 服务器一天出头产完全部训练数据 + 8×A100 两天微调，对学术复现非常友好。
5. **评审器与人为标注对齐度公开验证**（κ=0.94、接受集 0 例硬失败），为"VLM judge 过滤训练数据"这一做法提供了可信度证据。

## 5. 局限与可改进点（个人点评）

- **任务仍是单应用内**：作者自承每条任务只锚定一个应用的共享状态，跨应用长流程（真实工作最常发生）未涉及；且评估用的 8 个新应用与训练同域，CUA-Verse 上 3× 提升有多少来自应用内命令记忆、多少来自编排泛化，难以拆清——OOD 那 +3.2 点的零样本结果反而更说明问题，但幅度与域内差距悬殊。
- **数据质量的天花板来自教师与评审器**：只做 SFT，策略被 Kimi K2.5 上限约束；VLM 评审虽做了人标验证，仍是软标签，且阈值 0.75 的"部分完成即拒收"会把渐进式改进的学习信号丢掉。作者把"用评审分数做 RL"列为 next step，等于承认现方案未榨干数据价值。
- **对比公平性存疑**：OSWorld 只测 244 条子集，各家历史帧数、图像数设置不同（自家模型 3 帧/最多 4 图，闭源模型用各自默认）；OSWorld-MCP 也仅在子集上报告。闭源模型未做同样 LoRA，本质是"微调过的 9B vs 未调的大模型"，归因需谨慎。
- **适用范围受限**：App-Forge 假设软件开源或可脚本化、环境固定在桌面 Linux；16 个应用里 Chrome、VS Code 等命令面偏浅（约 10~15 条），对生态复杂软件的覆盖仍有限。

## 6. 对我们的启示 / 可借鉴点

1. **"造不了环境就造不了数据"**：对我们做 GUI Agent 评测/训练最有价值的是这套按应用划分的原子模块——每个应用 = 种子文件 + CLI 工具面 + 验证器 + 适配器。挑任意一个桌面工具照此配方搭建，就能持续合成带客观验收标准的任务，而不是每次手工写用例。
2. **模态级先验可以白拿效率**：Path-Steer 只在 rollout 提示里给"这条操作走 CLI 更划算"的一句话引导，把关通过率就从 0.44 提到 0.51、单任务成本降 16%——我们在自建数据管线里完全可以直接借鉴这种"低成本引导 + 阈值过滤"的轨迹筛选策略。
3. **把效率指标写进评测**：成功率之外同时报告步数与 token 的成对增益，能逼着 agent 少做无谓点击。做数据收集时也建议把"是否多余点击"作为过滤维度。
4. **VLM judge 可用但要验**：本文给出了 judge 对齐度验证的具体做法（分层抽样 + 人类盲评 + 混淆矩阵重加权），建议我们给自家自动评估器也建立类似的校准流程。
