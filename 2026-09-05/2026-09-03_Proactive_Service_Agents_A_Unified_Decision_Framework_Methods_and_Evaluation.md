# Proactive Service Agents: A Unified Decision Framework, Methods, and Evaluation

> 一句话 TL;DR：把"Agent 何时该主动出手帮人"从对话/推荐/健康/具身等零散研究，统一成一个受授权与风险约束的"沉默-询问-协助-执行"四模式序贯决策框架，并配一套可落地的评测协议与三轴证据描述符——核心主张：主动 ≠ 话多，而是在不确定下判断"出手比继续等更值"。

## 2. 论文要解决的核心问题

- **要解决什么问题**：这是一篇跨域综述（survey），要梳理的研究对象是"**主动服务决策**"——即 LLM Agent 在**没有明确完整指令**的前提下，如何自主决定"何时、以何种方式、介入什么内容"来帮助用户，横跨数字工作区（GUI/文档/代码）、情境与具身（可穿戴/机器人/AR）、高利害人类服务（教育/医疗/心理支持）三大 regime。
- **为什么重要**：现有 Agent 能力（规划、调工具、改外部状态）已经很强，但几乎所有评测都把"一条完整指令 → 把活干完"当作固定起点。真实持续使用中，需求往往以屏幕事件、传感器流、卡壳进度、未说出口的偏好形式出现，用户自己未必及时察觉或表达。让系统主动介入能缩短"从需求到服务"的距离，但代价是误报、打断、操纵、隐私暴露、不可逆操作。这个"谁先决定该做什么"的问题，卡住的是 Agent 从"接单工具"走向"可信助手"的下游能力。
- **现有方法有什么不足**：作者明确批评了四类既有综述的局限（Table 对照）：① **决策单元是对话轮**（Deng et al. IJCAI 2023 / ACM TOIS 2025），系统默认已持有发言权，而主动服务必须在"大部分时刻没有服务事件"的开放流里决定是否从沉默转向介入；② **按对话类型/设计维度组织**（Deng et al. SIGIR 2024 position、Jannach et al. CSUR 2021），把机制、任务、应用糊在同一层级，掩盖了真正可比的东西——每个决策时刻的信念、可行动作与后果；③ **把主动当成一种能力而非"受真沉默门控的选择"**，因而"何时不介入""等待与提问的价值""授权是硬约束还是软罚项"全都欠定义；④ **只把评测与伦理列为开放问题**，却给不出可操作协议（没有统一决策单元 schema、校准/时序/覆盖-风险指标、off-policy/反事实估计、活在动作空间里的安全模型）。
- **Research Gap**：作者认为自己补上的缺口是——**把"组织对象"从"应用清单"换成"模态无关的决策对象"**。即用一个**受限 POMDP** 作为统一分析语言，将"信念状态 + 可行动作 + 后果"作为可比单元，重排全领域；并首次（作者 claim）在数字工作区、具身、高利害人类服务三大设定下用同一组决策变量组织主动服务。其落点不是"再来一张清单"，而是"给未来的主动类 benchmark 与方法立一套可执行的共同协议"。

## 3. 方法核心思想（三层拆解）

### 3.1 一句话概括方法

把"主动服务"形式化为一个**受授权与风险硬约束的部分可观测序贯决策（constrained POMDP）**，用统一的动作元组 `(模式, 内容, 呈现)` 同时刻画"何时/做什么/怎么做"，并据此给出等待的期权价值、提问的信息价值与干预优势三个可计算量。

### 3.2 方法总览（Pipeline）

- **输入**：历史 `h_t`（观察流 `o_t`、当前指令规格 `ι_t`、权限账本 `κ̄_t`、过去的动作与反馈）。**输出**：结构化的主动动作 `a_t = (m_t, z_t, ℓ_t)`，其中模式 `m_t ∈ {silent, ask, assist, act}`，`z_t` 为具体问题/建议/计划/工具动作，`ℓ_t` 为渠道、模态与解释。
- **核心模块（决策管线，Fig.2）**，四个串联：
  1. **状态与需求估计（state & need estimation）**：从流式观测切分出决策机会（机会检测 + 时序切分），估计需求 `n_t`、可打断性 `w_t`，并要求**校准过的不确定性**（因为式 9/12 吃的是尾风险概率和期望价值，不是单点标签）；长时记忆只改变信念 `b_t` 的构造，是可选组件而非主动的必要条件。
  2. **干预门控（intervention gating）**：在可行动作集 `A_adm` 内，比较"最优非沉默动作"与"沉默的期权价值"，用**保守平局规则**决定是否出手。
  3. **动作构造（action construction）**：门控选"模式与时机"，内容策略选具体 `z_t`，呈现策略选 `ℓ_t`。
  4. **反馈适应（feedback adaptation）**：在三重时间尺度（即时答案/拒绝/undo、任务结局、跨会话的接受/信任/负担）上更新信念与策略。
- **正交的第二轴**：策略"如何被构造"用四个**可叠加**标签刻画——Prescribed（规则/阈值/提示词/SOP）、Predictive（监督模型预测需求/门控/动作标签）、Model-based（显式 `T/Z/r` 或搜索树/BDI）、Return-optimized（bandit/RL/离线策略学习直接优化累积回报）。机制、训练范式、任务、应用不再是并列的类。

### 3.3 真正的创新点（去伪存真）

- **真·方法创新**：① **操作性的主动定义**（Definition 1）——相对当前指令 `ι_t`、且协议允许真沉默才叫"主动决策"，把"系统先开口"与"系统做了主动决策"干净切开（定时提醒不算主动）；② **动作元组化**：把 timing/content/delivery 装进同一个动作，四模式共享一个动作空间；③ **权限账本 `κ̄_t` 与信念严格分离**——授权是"可验证的协议状态"，只能被 `K` 算子对 `f_t^perm` 验证事件更新，普通点头/接受/行为暗示一律只算信念猜测；④ **干预优势 `Δη` + 保守平局**（式 12）与**提问的纯信息价值判据**（式 14）——"答案若不改变信念/授权/后续动作值，纯信息价值不可能为正"，直击盲目反问。
- **工程组合**：受限 POMDP、Lagrangian 松弛、IPS/PDIS 离线策略估计、mixed-initiative 期望效用分析都非原创，作者明说是"分析语言"而非要系统真去解；把 Horvitz 的经典效用原则（UAI 1999 / CACM 2003）**扩展到 LLM Agent 的结构化动作**是组合式贡献。
- **对性能提升最关键的设计**：无实验可判 ablation，但就框架说服力而言，**授权/风险做成硬约束（式 9）而非软罚项**、以及**沉默被显式赋予期权价值**是最关键的两点——前者划清"能被效用买通"与"绝不能无授权执行"的界限，后者解释"为什么预测到需求存在 ≠ 应该现在出手"。
- **证据不足 / 仅声称有效**：命题 1（上包络阈值切换）仅证到"一步预排序候选"的特殊情形，作者自己也承认一般情形下"只按需求概率定阈值并非最优，除非增量价值单调且其它动作属性被正确边缘化"；四机制标签（Table II）的"优势/劣势/典型失败"是机制签名而非实证覆盖率，标注主观。

## 4. 具体技术细节

### 4.1 模型结构

本文是综述，无模型无训练。所谓"模型"是一套形式化语言（式 1–21）：

- **决策模型**：受限 POMDP `M = ⟨S,O,A,T,Z,r,c,γ,b_0⟩`，`c = (c_1,...,c_J)` 为 J 维单步成本向量。隐状态分解 `s_t = (x_t 环境与任务进度, g_t 目标与偏好, n_t 潜在需求与紧迫度, w_t 注意力/负载/可打断性, e_t 用户认可的长期结果)`。
- **权限账本**：`κ̄_{t+1} = K(κ̄_t, a_t, f_t^perm)`，只被验证过的同意/改范围/撤销事件更新；"语言说愿意"只是 `g_t` 里的信念，不是授权。
- **单步效用（式 8）**：`r_t = B^task_t + β·B^user,long_t − λ_I C^int_t − λ_Q C^ask_t − λ_E C^exec_t − λ_P C^priv_t`，四类成本（打断/提问/误执行回滚/隐私）与预算分账管理。
- **可行动作集（式 9）**：`A_adm = {a ∈ A_perm(κ̄_t) ∧ Pr_{s∼b_t}[L_R(s,a) > H] ≤ ϵ}`，授权未知时外部执行不可行，但"请求授权的 ask"仍可保持可行。
- **约束优化（式 10）**：`π* = argmax_π E_π[Σ γ^t r_t]`，s.t. 逐类成本预算 `≤ B_j` 且 `a_t ∈ A_adm` a.s.；用固定乘子 `η` 做 Lagrangian 松弛得 `r_{η,t} = r_t − η^T c_t`。

### 4.2 训练流程（若需要训练）

**—（综述，无训练）**。全文没有任何模型训练/微调，也没有自家评测实验。

### 4.3 推理流程（本文是框架，重点在"决策/门控"）

- **干预优势（式 12）**：`Δη(b_t, κ̄_t) = max_{a∈A^+_t} Q*_η(b_t, κ̄_t, a) − Q*_η(b_t, κ̄_t, silent)`；**保守平局**：`Δη ≤ 0` 就沉默，否则选价值最高的可行非沉默动作。`Q*(silent)` 内含"再观察、以后介入"的期权，故沉默 ≠ 放弃。
- **首介入时刻（式 13）**：`T^π_int = inf{t : m(a_t) ≠ silent}`，是随机停时而非预设触发器——这解释了为什么"预测现在有没有需求"一般不够，同样需求概率下，内容质量差或执行风险高会产生不同的 `Δη`。
- **提问价值（式 14）**：`Q*_η(ask(q)|b,κ̄) = E_{y}[r_η + γ V*_η(b_{q,y}, κ̄_{q,y})]`；一步近似下纯信息价值 `= E_y[V_0(b_{q,y})] − V_0(b,κ̄) − C_Q(q)`，若答案不改变任何后续决策则为非正。
- **命题 1（式 15）**：给定按风险/干扰预排序的候选，最优动作是仿射效用函数 `U_i(p)=u_{i0}+p·d_i` 的上包络，切换点在 `p_ij = (u_{i0}−u_{j0})/(d_j−d_i)`；在 `d_i` 随序非降时最优动作指标随需求概率 `p` 单调不降。**结论：固定阈值门控一般不是最优的**。

### 5.2 评测协议与"结果"分析

- **评测指标体系（本文的真正"产物"）**：① 触发层——先报 prevalence `ρ`，再报 precision/recall/F1/PR-AUC/balanced accuracy，以及 **FAH（每小时假干预，式 16）**；输出需求概率时须配 Brier score、校准曲线、ECE（强调 ECE 对分箱敏感，不能单独作证据）。② 时序层——事件级匹配时序 `Prec_T/Rec_T/F1,T`（式 17，二分图最大基数+最小绝对时序误差匹配），并分报早/晚误差与"到首次有效干预的延迟"。③ 内容分解层——**"参考门控下的条件质量"与"系统自带门控的端到端质量"必须分开报**，否则上游假触发被强内容遮住。④ 策略价值层——`ΔV(π,π_0)`（式 18）、IPS（式 19）、PDIS（式 20）、覆盖-风险曲线 `Cov(τ)/Risk(τ)`（式 21）。
- **证据清点（关键结论，无数字实验）**：13 个资源绝大多数停在 **R0–R1 / C0 / H-NA**（静态能力诊断或离线回放），最好的也只到"短程真实用户"（ProMemAssist R3/C1/H-S、SCALA R4/C0/H-S）；**没有一个达到能识别长期因果增量价值的对比设计（R4 + H-L）**。这个"空"本身即结论：领域缺的不是新模型，而是能证明"干预相对沉默真的净赚"的证据基础设施。
- **核心反例（intervention paradox）**：作者引用 [84] 指出**高故障预测 AUROC 可以与更低的端到端成功率并存**——因为干预既能救活一条将失败的轨迹，也能毁掉一条本会成功的轨迹。这直接支撑"离线分类分数 ≠ 部署收益"的全文主张。

## 6. 亮点与贡献（Why it matters）

1. **跨域统一到一个决策对象**：首次把对话、GUI、视频、可穿戴、软件工程、具身、高利害人类服务放进同一组变量（信念/动作/后果）下组织，而非再来一张应用清单。
2. **可操作的主动定义**："相对当前指令 + 存在真沉默选项"的判据，能干净区分"系统先开口"与"系统做了主动决策"（预设自动化不算），这一定义对后续 benchmark 有直接约束力。
3. **把"等待/提问"写进价值函数**：沉默的期权价值、提问的纯信息价值判据，把"该不该等/该不该问"从口头原则变成可计算量，给"盲目反问"类系统提供了形式化反驳工具。
4. **授权与安全是硬约束、活在动作空间里**：可验证权限账本 + 严重风险阈值（式 9）给"不能靠效用买通"一个形式位置；tiered permission、渐进式自主（act→assist→ask 降级）、可回滚执行被明确为**改变最优策略的可测变量**而非论文末尾的伦理声明。
5. **评测协议具体到能抄**：统一决策单元 schema、事件级时序匹配、FAH、条件质量 vs 端到端质量分解、IPS/PDIS、覆盖-风险曲线、R/C/H 三轴证据描述符，给未来所有主动类 benchmark 立了模板。

## 7. 局限与可改进点（个人点评）

- **纯框架文，零自证**：全文没有一个用该协议标注、用该门控跑通的实验，连"13 个资源重述是否忠实、标注者间一致性"都无从检验；框架对真实 LLM 门控的性价比完全未验证。
- **落地路径缺失**：作者自己承认受限 POMDP 只是"分析语言"，但没给近似解法或工程近似；Lagrangian 乘子 `η` 如何标定、`Q*` 谁来估、`γ` 与真实步长如何对应，全部推给"未来工作"（Q1–Q4 只提方向，不给方法）。
- **评测协议理想化程度高**：IPS/PDIS 需要日志策略概率、支持重叠、无未记录顺序混淆等硬前提；而主动服务最根本的难处——**沉默时观测不到"是否需要帮助"的选择性反馈**——文中只点到方向（Q3），没有折中方案。
- **证据等级存在自循环风险**：团队"UniCone Team"公开信息极少，所倚重的多篇关键资源（ProAgentBench 2602.04482 等）是自引且未经同行评审的预印本；"现有证据弱"的判断部分建立在自家未审基准上。
- **广度牺牲深度**：横跨 5–6 个 regime，任一领域（尤其 GUI）的机制细节都只能点到为止；Table I–IV 的取舍依赖作者主观筛选，有漏 2026 同期工作的风险。

## 8. 对我们的启示 / 可借鉴点

### 对 GUI Agent 的可借鉴点（本篇为 Agent 方法论域，单列）

- **把"不操作"显式建模成带期权价值的合法动作**：多数 GUI 系统拿到指令就跑，silent 只是引擎没派活的空转。本文主张 silent 是四模式之一，且 `Δη ≤ 0` 时应保持沉默并保留"再观察后干预"的期权——这正对应"用户在改文档时，Agent 该不该弹建议"的判断：频繁弹窗是打断成本，静默观察本身有价值。
- **提问判据可直接治"盲目确认"**：GUI Agent 常见病是遇到歧义就无脑弹窗。按式(14)，一个问题若答案不会改变后续任何一步的决策（不改变信念/授权/动作值），就不该问；反之当动作不可逆（下单/删除/付款/发送），ask 往往是唯一 admissible 的动作——先拿到可验证授权再动手。
- **权限账本对应 GUI 高危操作授权**：用户一次普通"继续"点击不能当长期授权；act 前应绑定对象+目的+过期，低置信/高风险时从 act 降级为 assist（预览/草稿/干跑），失败要可 undo——"渐进式自主权"是现成设计原则。
- **相对当前指令判主动 + 带负样本流评测**：AppAgent-Pro 式"跨应用扩展字面请求"只能算状态构建，不算开放流的沉默门控。GUI 评测若只给"该帮忙的片段"会系统性高估——须像 PIRA-Bench 那样带完整负样本流，并分报"参考门控下建议质量"与"自带门控端到端成功率"，否则差的门控会被强触发器遮住。

### 对项目的通用启示

- 建主动 GUI 数据/评测时，**以"决策机会单元"为标注与采样基本单位**，把"用户可接受干预窗口 [l_j,u_j]" + 完整负样本流 + 日志策略概率写进 schema，为日后 IPS/PDIS 反事实估计留后路。
- 需求估计层输出要**校准概率**而非单点标签（式 9/12 吃尾风险和期望价值），直接对标 Brier/ECE 而非只报 F1。
- 若用 RL 训门控，训练环境必须含 silence、rejection、授权越界样本，否则学出来只是内容策略而非门控；采纳"条件质量 vs 端到端"双层报告与 R/C/H 三轴，能对自家 bench 的证据等级说实话。

## 9. 延伸阅读

- **Horvitz, "Principles of Mixed-Initiative User Interfaces"（CHI 1999）/ CACM 2003**：期望效用 + 注意力/打断成本的源头，本文式(8)的直接前身。
- **Deng et al., IJCAI 2023 / ACM TOIS 2025**：proactive dialogue 两篇奠基综述（本文的"对照物"）。
- **Proactive Agent (ICLR 2025)**：早期"从响应式转向主动协助"的代表原型。
- **ProAgentBench（arXiv:2602.04482，作者团队）**：基于真实计算机日志的主动协助评测。
- **PIRA-Bench（arXiv:2603.08013）**：GUI 主动意图推荐的流式负样本基准（GUI 域最贴近本文协议）。
- **Ambig-SWE（ICLR 2026）**：软件工程欠定任务三条件评测，演示"检测-提问-利用答案"是三个独立瓶颈。
- **When Not to Help（arXiv:2508.01837）**：在简化 POMDP 用户模型里直接对比"帮 vs 不帮"三种策略。
- **Accurate Failure Prediction...（arXiv:2602.03338）**：intervention paradox 的实证来源——高 AUROC 故障预测 ≠ 有效故障预防。
