# Proactive Service Agents: A Unified Decision Framework, Methods, and Evaluation

> TL;DR：把"Agent 何时该主动出手帮人"从一堆对话/推荐/健康领域的零散研究，统一成一个受授权与风险约束的"沉默-询问-协助-执行"四模式序贯决策框架，并配上一套可落地的评测协议与三轴证据描述符——核心主张：主动 ≠ 话多，而是在不确定下判断"出手比继续等更值"。

## 1. 研究背景与要解决的问题

现在的 LLM Agent 能规划、能调工具、能改外部状态，但几乎所有评测还是同一个套路：**给一条完整指令 → 让系统把活干完**。真实世界不是这样运转的：需求往往长在屏幕事件里、卡壳的任务进度里、一段没被说出口的偏好里，用户自己都没察觉。于是作者把镜头往前推一格——**谁先决定"该做什么"？** 让系统主动开口能缩短"从需求到服务"的距离，但代价是误报、打断、越权、隐私泄露、不可逆操作。作者反复强调：**主动服务不等于更频繁地行动**，而是"在不确定下，判断系统何时应揽过主动权，并且有证据表明这么做比干等着更值钱"。

类比：传统 Agent 像个只会"接单"的客服；主动 Agent 要更像一个懂分寸的私人管家——他得判断此刻是该闭嘴、该问一句、该递上草稿，还是该直接把事办妥。

这个问题的研究积累不少但极其零散：对话领域研究澄清与目标引导，推荐领域研究"要不要问偏好"，健康领域 JITAI 研究触发时机，HRI 研究"预测下一步 vs 据此夺权"，各说各话，时间粒度、负样本定义、反馈来源、风险假设全不一样。作者认为按应用列清单的做法掩盖了真正可比的东西——**每个决策时刻的信念状态（belief）、可行动作与后果**。本篇综述就围绕这个对象重排全领域。

## 2. 核心方法 / 思路

**第一步：给出操作性定义。** 系统某个"非沉默动作"要算主动服务干预，须同时满足四条：① 系统自主引入了指令未规定的服务机会/时机/子目标/提问/外部动作承诺；② 协议确实允许"沉默"或"按指令办"等其它选项（有真沉默，才是真主动）；③ 选择基于对用户目标、环境、后果的信念；④ 目标是用户认可或共享的收益。关键在"相对指令"和"门控"：用户事先设好的定时提醒不算——它的触发器被规则定死了，系统没做在线决策。而一个 Agent 自主比较"把模糊请求直接干 vs 先问清楚"就算主动。

**第二步：形式化成一个受约束的部分可观测序贯决策模型。** 用一个受限 POMDP 当"分析语言"（作者明说不是要求每个系统真的去解它）。隐状态拆成 `st = (xt环境进度, gt目标偏好, nt潜在需求与紧迫度, wt可打断性, et用户认可的长期结果)`。两个设计很关键：

- **权限账本 κ̄t 与信念严格分离**：授权是"可验证的协议状态"，只能被验证过的同意/改范围/撤销事件更新（K 算子），普通点头、接受、行为暗示一律不算数。语言说"我愿意"也只是信念层面的猜测，不是授权。
- **动作是一个元组而非单个标签**：`at=(mt, zt, ℓt)`，模式 `mt∈{silent, ask, assist, act}`，加上具体内容 zt 和呈现方式 ℓt。于是"何时/做什么/怎么做"装进同一个动作，四模式共享一个动作空间。
- **效用 vs 硬约束分家**：单步效用 = 任务收益 + β×长期收益 − λ×(打断+提问+误执行+隐私成本)；但授权与"严重风险超阈值"是硬约束，构成可行动集 Aadm，不能被足够大的效用抵消——这跟把授权当"软罚项"的主流做法划清界限。

**第三步：抽出三个可计算的量。** ① **干预优势** Δη(b,κ̄) = 最优非沉默动作值 − 沉默值，保守平局规则：Δ≤0 就沉默；② **等待的期权价值**：沉默动作里含着"再观察、以后再说"的选项，所以沉默不是放弃；③ **提问的价值**：一个问句的价值是"答案引发的信念/授权/后续决策变化"的期望，再扣掉提问负担——若答案什么都不改变，纯信息价值不可能为正。这是一把非常好用的尺子。Proposition 1 进一步证明：给定按风险预排序的候选动作，最优动作随"需求概率"在上包络上单调切换，阈值由两条仿射线交点给出——因此**"需求概率过固定阈值就出手"这种门控一般不是最优的**，你还需要内容质量与执行风险的信息。

**第四步：方法综合轴。** 用一条决策流水线组织全部方法：状态与需求估计（机会检测/时序切分、需求+可打断性+校准不确定性、"记忆只改信念构造"的条件角色）→ 干预门控 → 动作构造 → 反馈适应；再用正交维度"策略怎么构造"打标签：规则式（Prescribed）、预测式（Predictive）、显式模型式（Model-based）、回报优化式（Return-optimized），四种可叠加。这样避免把机制、训练范式、任务、应用糊在同一层。

**第五步：评测协议。** 主张以"预定义的完整决策机会流"为基本单元（必须带负样本和时间戳），指标分四层：触发层（报 prevalence、PR-AUC、校准、**每小时假干预 FAH**）、时序层（事件级匹配时序 F1、早/晚误差）、内容分解层（**参考门控下的条件质量 + 系统自带门控的端到端质量分报**）、策略价值层（离线策略估计 IPS/PDIS、反事实）。外加 R0-R4（交互真实度）/ C0-C1（对比设计）/ H-NA/H-S/H-L（人类结局时长）三轴证据描述符。这篇综述想终结的顽疾是：**离线分类分数 ≠ 部署收益**——"干预悖论"文献表明 AUROC 很高的故障预测可以与更低的端到端成功率并存，因为干预能救活一条将失败的轨迹，也能毁掉一条本会成功的轨迹。

## 3. 关键实验结果

本文是综述+框架文，**没有自设实验**。它的"证据面"是表 III 里 13 个代表性资源用统一决策协议重述后的清点，关键规模数字如下：

- ProactiveBench（ICLR 2025 主动 Agent 原型）：6,790 条合成训练 / 233 条真实测试，模式仅 silent/assist；
- ESTP-Bench：890 段 Ego4D 视频、2,264 条人工核验的带时问答；
- PIRA-Bench：100 条人工整理的 GUI 截图轨迹（含注入噪声负样本流）；
- LatentNeedsBench：100 段真实转录会话、3,936 轮；
- Ambig-SWE：软件工程欠定任务三条件（Full/Hidden/Interaction）；
- SCALA：1,508 名学生、整学期课堂真实部署、2,608 个会话，但**匿名化设计无法做个体级纵向关联**；ProMemAssist 是唯一带受试者（12 人）短程对照（R3/C1/H-S）。

作者用三轴矩阵算总账：这批资源绝大多数停在 R0-R1 / C0 / H-NA（静态能力诊断或离线回放），最好的也只到"短程真实用户"，**没有一个达到"能识别长期因果增量价值"的对比设计（R4+H-L）**。这个"空"本身就是结论：领域缺的不是新模型，而是能证明"干预相对沉默真的净赚"的证据基础设施。

## 4. 亮点与贡献（Why it matters）

1. **跨域统一**：第一次把对话、GUI、视频、软件工程、具身、高价值人类服务放在同一组决策变量（信念/动作/后果）下组织，而不是再来一张应用清单。
2. **可操作的主动性定义**："相对当前指令 + 存在真沉默选项"的判据，能干净地区分"系统先开口"和"系统做了主动决策"（预设自动化不算）。
3. **沉默的期权价值被写进式子**：Δη 与保守平局把"等一等更值"变成可计算的量；提问的信息价值判据直击"盲目反问"类系统的要害。
4. **授权是硬约束不是软罚项**：可验证权限账本 + 严重风险阈值（式 9）给"不能靠效用买通"的安全底线一个形式化位置，且成本（打断/提问/回滚/隐私）与预算分开管。
5. **评测协议具体到能抄作业**：统一决策单元 schema、事件级时序匹配、FAH、条件质量 vs 端到端质量分解、IPS/PDIS 反事实估计、R/C/H 三轴证据描述符，给未来所有主动类 benchmark 立了模板。

## 5. 局限与可改进点（个人点评）

- **纯框架文，零自证**：全文没有一个用该协议标注、用该门控跑通的实验，连"13 个资源重述是否忠实、标注者一致性"都无从检验。框架的可用性（尤其对 LLM 门控的性价比）存疑。
- **落地路径缺失**：作者自己承认受限 POMDP 只是"分析语言"，但没给出近似解法或工程近似；Lagrangian 乘子怎么标定、Q* 谁来估、γ 与真实步长怎么对应，都推给"未来工作"。
- **评测协议理想化程度高**：离线策略估计需要日志策略概率、支持重叠、无未记录混淆等硬前提；而主动服务最根本的难处——**沉默时观测不到"是否需要帮助"的选择性反馈**——文中只点到方向，没有折中方案。
- **证据等级有点自循环**：作者单位"UniCone Team"公开信息极少，所倚重的多篇关键资源（ProAgentBench 2602.04482 等）是自引且未经同行评审的预印本；"现有证据弱"的判断部分建立在自家未审基准上。
- **广度牺牲深度**：横跨 5-6 个 regime，任何一个（比如 GUI）的机制细节都只能点到为止；Table I-IV 的取舍也依赖作者主观筛选，存在漏 2026 同期工作的风险。

## 6. 对 GUI Agent 的可借鉴点

这篇是 Agent 方法论域论文，但对 GUI Agent（尤其"GUI Agent 何时该主动"）几乎是直给：

- **把"不操作"显式建模成带期权价值的合法动作**。多数 GUI 系统拿到指令就跑，silent 只是引擎没派活的空转。该文主张 silent 是四模式之一，且 Δη≤0 时应保持沉默并保留"再观察后干预"的期权——这正好对应 GUI 场景里"用户在改文档时，Agent 该不该弹建议"的判断：频繁弹窗是打断成本，静默观察本身有价值。
- **提问判据可直接用来治"盲目确认"**。GUI Agent 常见病是遇到歧义就无脑弹窗问用户。按式(14)的逻辑，一个问题若答案不会改变后续任何一步的决策（不改变信念、不改变授权、不改变动作值），就不该问。反过来，当动作不可逆（下单/删除/付款/发送），ask 常常是唯一 admissible 的动作——先拿到可验证授权再动手。
- **权限账本思想对应 GUI 高危操作的授权设计**：用户一次普通的"继续"点击不能当长期授权；执行前应绑定对象+目的+过期。act 前可先降级为 assist（预览/草稿/干跑），失败了要可 undo——"渐进式自主权"（低置信/高风险时从 act 降到 assist/ask）是现成的设计原则。
- **相对当前指令判主动**：AppAgent-Pro 式"跨应用扩展字面请求"只能算状态构建，不算开放流的沉默门控。GUI 评测若只给"该帮忙的片段"，会系统性高估——必须像 PIRA-Bench 那样带完整负样本流，并分报"参考门控下的建议质量"和"自带门控的端到端成功率"，否则差的 gate 会被强 trigger 遮住。

## 7. 对我们的启示

- 如果我们要建主动 GUI 数据/评测：**以"决策机会单元"为标注与采样的基本单位**，把"用户可接受干预窗口 [lj,uj]"+ 完整负样本流 + 日志策略概率写进 schema，为日后离线/反事实估计留后路。
- 状态估计层：需求输出要**校准过的概率**而非单点标签（式 9/12 吃的是尾风险和期望价值），直接对标 Brier/ECE 而非只报 F1。
- 若用 RL 训门控，训练环境必须包含 silence、rejection、授权越界样本，否则学出来只是内容策略而非门控——这是很容易踩的坑。
- 采纳"条件质量 vs 端到端"双层报告与 R/C/H 三轴，能让我们对自家 bench 的证据等级说实话；intervention paradox 提醒：与其信故障预测 AUROC，不如盯端到端成功率。
