# MEMO: Multimodal Evidence Memory Organization for Long-Horizon LLM Agents（面向长程 LLM Agent 的多模态证据记忆组织）

> TL;DR 提出多模态记忆组织方法 MEMO：把历史记忆切成带出处与关键跨度的"证据单元"，由训练过的记忆管理器在统一 token 预算下为每个单元分配文本/图像/双通道载体并排版，构造成查询定制的工作记忆。128-token 预算下 2Wiki 上 F1 达 73.91，远超纯文本 56.26 与纯图像 35.89。

## 1. 研究背景与要解决的问题

长程 agent 需要外置记忆来保存单窗口放不下的历史，但轨迹不断累积，全量塞入既贵又让真正有用的证据与冗余内容抢有限上下文。作者指出，核心难题不仅是"存什么、取什么"，更是**读出来（memory readout）**：给定查询与预算，系统要选出本次必需的证据并组织成模型能高效读懂的"工作记忆"。

现有读接口分两派。文本记忆（MemRL、Agentic Memory、Mem-α 等）擅长压缩检索，但最终都是线性 token 序列，重要度不同的内容以近等成本挤占上下文；图像记忆（MemOCR、AgentOCR）把文本渲染成带版式的"文档页"，用二维布局凸显重点、省 token，但渲染/压缩会丢细粒度语义。作者的判断是：文本与图像适配不同类型的证据，锁死单一模态就无法同时兼顾保真、结构表现力与资源效率。MEMO 补的正是这个缺口——按证据粒度按需混合模态。

## 2. 核心方法 / 思路

MEMO 把一次"读记忆"拆成四步（图 2）：证据抽取 → 单元物化 → 记忆规划 → 工作记忆构建。

1. **查询条件化证据抽取**。检索命中的段落/对话轮往往只有一句有用，整块塞入是浪费。抽取器读入查询、候选记录与预算，输出相关源块 S 与各源内"字符级关键跨度"H，再从原始记录逐字复制关键内容及邻近窗口，形成可溯源的最小操作对象——**证据单元** uᵢ=(id, 内容, 关键跨度, 出处, 保留优先级)。优先级规则注明"哪句必须精确保留、哪段可改图、哪段可丢弃"，相当于给后续模块留了红线。抽取器用全参数 SFT 训练：HotpotQA/2Wiki 用官方 supporting facts，LoCoMo 用官方证据轮，ALFWorld 无标注则对专家轨迹做状态差分生成弱标签。

2. **证据选择与呈现联合规划（记忆管理器）**。对每个单元输出动作 `{text, image, dual, drop}`：text 在文本包保留精确语义锚；image 进视觉页，用时间线/表格/清单/卡片/列等模板承载结构；dual 双通道，文本锚保精度、图像补结构，成本同时计入；drop 省略。所有单元共享总预算 C_text+C_vis≤B，把"选内容、选模态、排版式"三个互相竞争的决定合成一个单元级计划。

3. **用冻结 reader 反馈造训练标签**（最有意思的设计）。对同一查询与证据，把每个单元分别做成"只留文本/只放图/双通道/丢弃"四种反事实候选，其余单元不动，逐一送冻结 reader 答题；答案质量优先、平手取 token 少者，为每单元"赢"出一个行动标签，置信度取该动作与次优动作的差距，image/drop 还要过 reader 结果的额外校验。模板标签同理按反事实答案质量排序，推理时取首个满足预算者。训练目标由此**对齐下游 reader 的真实效用**，而非单纯省 token。

4. **确定性工作记忆构建**。builder 不做学习：把 text/dual 单元连成带单元与源标识的文本包 T；把 image/dual 单元按模板排成视觉页 V，先定文本成本、用剩余预算定页面大小，保证不超预算；最终把 (T,V) 与查询交给冻结的多模态 reader 作答。

与既有方法的关键差异：Mem-α/MemAgent 学习"怎么改写记忆"，出口仍是线性文本；MemOCR/AgentOCR 整体走图像单模态。MEMO 把决策下放到证据单元级，既能留文本锚、又吃视觉结构红利。

## 3. 关键实验结果

评测覆盖 HotpotQA、2WikiMultiHopQA（多跳问答）、LoCoMo（长对话记忆）、ALFWorld（具身轨迹下一动作预测），reader 冻结为 InternVL3.5-8B、Qwen3-VL-32B、gpt-5.4-mini 三个后端，基线含 Text-only、BM25、Mem-α、MemAgent、AgentOCR、MemOCR。

- **128-token 严格预算下全面第一**：三个 reader 的 Overall EM/F1 均最优。相对最强基线：InternVL3.5-8B +7.30 EM/+7.22 F1，Qwen3-VL-32B +2.35/+1.84，gpt-5.4-mini +2.47/+2.81，增益不依赖单一后端。多跳 QA 上优势最明显：Qwen3-VL-32B 时 2Wiki F1 达 73.91，纯文本 56.26、纯图像 35.89；gpt-5.4-mini 时达 80.06。
- **无预算设定下"省 token 不减质"**：4096 窗口内不截断源记忆时，MEMO 平均只用 83.93 tokens，比 MemAgent 少约 50.5–50.7%、比 Text-only 少 66.9%，而 Overall 在每个 reader 上排第一或第二，最大落后 0.43 点。
- **组件消融（gpt-5.4-mini，128-token）**：两组件全关 47.49 EM/57.24 F1、耗 126.22 tokens；只开抽取器升至 53.56/66.09、token 降到 70.12（EM+6.07、F1+8.85、−44.4%），说明"先筛相关证据"是压缩与提分主力；加管理器到 57.78/68.62（再 +4.22/+2.53）。全系统相对全关 EM+10.29、F1+11.38 且省 35.8% token。

## 4. 亮点与贡献（Why it matters）

第一，把读记忆重新表述为"共享预算下的查询条件化工作记忆构建"，证据选择、模态分配、排版收进同一可优化框架，问题边界清晰。第二，可溯源证据单元天然兼容 EverMemOS/MemoryOS 等结构化记忆系统的输出，本方法可作其"上层读方案层"。第三，"冻结 reader 反事实造标签"使留什么、怎么呈现对齐下游效用，是压缩任务里少见的效用导向而非成本导向。第四，跨文档问答、长对话、具身轨迹三类异构源与多 reader 验证，展示了对源类型和后端的鲁棒性；对多模态 reader 时代"上下文放什么"给出了系统化方案。

## 5. 局限与可改进点（个人点评）

- **监督成本不低**：反事实标签要求逐单元构造 4 种候选并逐一送冻结 reader 前向，而消融里管理器只带来 +4.22 EM 的质量增量，收益比值得掂量；抽取器又依赖各 benchmark 原生证据标注或手工差分，冷启动到新领域不轻松。
- **"通用"言过其实**：ALFWorld 上 MEMO 与 Text-only 几乎打平（EM 约 1.68 vs 1.37–1.90），LoCoMo 也非单项第一——当内容本是紧凑文本、无强结构关系可借用时，视觉编排没有红利。结论宜限定在"信息密度高、含时序/表格结构"的记忆源。
- **组件是小模型 SFT 上限受限**：两模块仅 1.5B 基座；评测 reader 与训练 reader 同属 InternVL 家族；"无预算"仍有 4096 上限。渲染依赖 reader 的视觉-OCR 能力，未报告渲染质量敏感性；未开源也使复现门槛偏高。

## 6. 对我们的启示 / 可借鉴点

通用启示：上下文管理不该是启发式截断，而应作为可学习、且以"下游 reader 真实效用"为目标的一层组件；一切压缩决策都应显式记账在统一预算下。

**对 GUI Agent 的可借鉴点：**

GUI agent（计算机/手机操作）正是"多模态证据+长程轨迹"最典型的重灾区——每轮有截图、无障碍树/DOM、坐标与文本，历史动辄数百步，现成做法要么截断、要么整屏贴图烧 token。MEMO 给出四条可迁移思路：其一，把"截图/树/日志"切成**带出处的证据单元**：一次"点击下载→弹窗→保存"就是单元，出错可按源回查，支持过程级诊断与反思；其二，对每单元做**载体分配**而非全量文本/全量截图——文件名、URL、金额等需高保真的走文本锚，页面布局、弹窗层级等空间关系走图像，长任务中"哪些步骤值得留图、哪些留文字"从此成为可学习决策；其三，把**上下文预算当第一公民**：截图 token 昂贵，用下游效用（而非 token 数）训练"是否贴这张截图"的策略，比启发式截屏节流更贴近目标；其四，**模板化排版**（时间线=操作历史、清单=状态、表格=表单值）可直接复用于 GUI 轨迹摘要页。对 RL 训练的 GUI agent，这套方法还可作观测预处理层，把原始截图史压成预算内证据包再喂给策略，缓解观测过长导致的 RL 不稳定。

## 7. 延伸阅读

- **视觉记忆**：MemOCR（版式感知视觉记忆）、AgentOCR（光学自压缩轨迹图像）——最直接参照。
- **文本记忆**：Mem-α、MemRL、Agentic Memory、SimpleMem/LightMem。
- **结构化记忆**：MemoryOS、EverMemOS、A-MEM、ES-Mem——MEMO 定位在其上的读方案层。
- **评测侧**：ALFWorld、LoCoMo 提供轨迹记忆评测范式；verl（Sheng et al., 2024）为微调框架。
