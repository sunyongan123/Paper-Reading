# MEMO: Multimodal Evidence Memory Organization for Long-Horizon LLM Agents

> TL;DR：把"读记忆"重新定义为"共享 token 预算下的查询条件化工作记忆构建"——按证据单元混合分配文本/图像/双通道载体，用冻结 reader 的反事实反馈训练记忆管理器，实现省 token 且不减质。

## 2. 论文要解决的核心问题

- **要解决什么问题**：长程 LLM agent 需要外置记忆承接单窗口放不下的交互轨迹，但轨迹持续累积，全量回放既贵又让真正有用的证据与大量冗余内容抢有限上下文。作者把核心难题从"存什么、取什么"进一步收窄到 **memory readout（读出）**：给定查询、候选记录与上下文预算，系统要选出本次必需证据并组织成模型能高效读懂的"工作记忆"。
- **为什么重要**：读出不解决，再好的存储与检索都会在"喂给 reader 的最后一步"前功尽弃——重要度不同的内容以近乎统一的 token 成本挤占上下文，下游多跳推理、长对话问答、具身轨迹恢复的能力天花板被硬性压低。
- **现有方法有什么不足**：读接口分两派。**文本记忆**（MemRL、Agentic Memory、Mem-α、SimpleMem/LightMem 等）擅长压缩检索，但出口仍是线性 token 序列，重要性差异无法体现在成本上；**图像记忆**（MemOCR、AgentOCR）把文本渲染成版式化"文档页"，能用二维布局凸显重点、省 token，但渲染/压缩会丢细粒度语义（字符级事实难以精确恢复）。作者论据：文本与图像适配不同类型的证据，锁死单一模态无法同时兼顾保真、结构表现力与资源效率。
- **Research Gap**：作者声称补上的缺口是——**在证据单元粒度上按需混合模态**，把"选哪些证据、用什么载体呈现、如何排版"三个互相竞争的决定放进一个统一预算下的联合优化框架，而非把检索结果整体转成单模态。

## 3. 方法核心思想（三层拆解）

### 3.1 一句话概括方法

用训练过的证据抽取器把原始记忆切成带出处与保留优先级的"证据单元"，再由训练过的记忆管理器为每个单元分配 `{text, image, dual, drop}` 载体并选排版模板，最后确定性拼装成预算内的 (文本包 T, 视觉页 V) 交给冻结的多模态 reader 作答。

### 3.2 方法总览（Pipeline）

**输入**：当前查询 q、候选记忆记录 R、总预算 B；**输出**：工作记忆 a=(T, V) 供一次 reader 调用。

四步数据流（图 2）：

1. **查询条件化证据抽取**：抽取器 `(S,H)=E_ϕ(q,R,B)` 定位相关源块 S 与各源内字符级关键跨度 H；从原记录逐字复制关键内容及邻近窗口，形成可溯源的最小操作对象——证据单元 `uᵢ=(id, xᵢ, hᵢ, sᵢ, cᵢ)`，其中 cᵢ 是保留优先级规则（哪些必须文本精确保留 / 可改图 / 可丢弃）。
2. **单元物化**：确定性步骤，把抽取结果固化为带出处、高亮、优先级的证据单元集合 U。
3. **记忆规划（联合选择与呈现）**：管理器对每个单元输出动作 `{text, image, dual, drop}` 并选模板偏好（cards/timelines/tables/checklists/columns），所有呈现决策共享一个资源上限 `C_text + C_vis ≤ B`。
4. **确定性工作记忆构建**：builder 不学习——text/dual 单元连成带标识的文本包 T，image/dual 单元按模板排成视觉页 V；先定文本成本，用剩余预算定页面大小，保证不超预算；最终 (T, V) + 查询交给冻结 reader。

### 3.3 真正的创新点（去伪存真）

- **真·方法创新**：把读记忆表述为"共享预算下证据级模态分配+排版联合规划"，并首次用**冻结 reader 的反事实反馈**造训练标签——逐单元构造"只文本/只图/双通道/丢弃"四种候选、其余单元不动，以答案质量优先、平手取 token 少者定行动标签，置信度取最优与次优动作差距，image/drop 还要过 reader 结果额外校验。这使训练目标对齐下游真实效用而非单纯省 token。
- **工程组合**：证据抽取（query 条件化 + 字符级跨度）、文本-图像渲染、模板排版均为已有组件；其"本身不新，组合有效"。
- **对性能提升最关键的设计**：ablation 证明**证据抽取器是主力**（EM+6.07、F1+8.85、token −44.4%），管理器是次要增益（EM+4.22、F1+2.53）。
- **证据不足 / 仅声称有效**："证据单元兼容 EverMemOS/MemoryOS 等结构化记忆输出"这一可移植性 claim 无定量实验支撑；视觉排版的红利仅在含时序/表格结构的源上体现，泛化边界未严格刻画。

## 4. 具体技术细节

### 4.1 模型结构

- **base model**：证据抽取器与记忆管理器均用 **Qwen2.5-1.5B-Instruct**（1.5B 纯 LLM，无视觉编码器），**全参数 SFT**，框架 verl（Sheng et al., 2024），A100 GPU。
- **reader（冻结的多模态后端）**：训练管理器标签用 **InternVL3.5-4B-Instruct**；评测用 **InternVL3.5-8B、Qwen3-VL-32B、gpt-5.4-mini** 三个后端（不同规模/家族，检验方法是否绑定特定 reader）。
- 方法本身无视觉编码器，视觉页由 text-to-image 渲染器生成，依赖 reader 的视觉-OCR 能力读取。

### 4.2 训练流程

| 阶段 | 目标 | 训练什么能力 | 数据来源 | 数据形态 | 训练目标 / Loss |
|---|---|---|---|---|---|
| 证据抽取器 | 从原始记录中定位查询相关源块与关键跨度 | 查询条件化证据定位 | 四 benchmark 训练集：HotpotQA/2Wiki 用官方 supporting facts；LoCoMo 用官方证据轮（对话级切分）；ALFWorld 对专家轨迹做状态差分生成弱标签 | 查询+候选记录+预算 → 结构化抽取目标 e⋆ | 全参数 SFT 负对数似然 `L_ext(ϕ)=−Σ log p_ϕ(e⋆_t|e⋆_<t, q, R, B)` |
| 记忆管理器 | 为每个证据单元选载体+模板 | 证据选择与呈现联合规划 | 同上四 benchmark；逐单元构造 4 种反事实候选送冻结 reader 打分 | 查询+证据单元 U+预算 → 完整记忆计划 y⋆ | SFT `L_sft(θ)=−Σ log p_θ(y⋆_t|y⋆_<t, q, U, B)` |

> 标签来源写实：管理器标签不是人工标注，而是**冻结 reader 对反事实候选记忆的答案质量反馈**——答案质量优先、平手取 token 少者胜出；模板标签同理按反事实答案质量排序成有序列表，推理时取首个满足预算者。

### 4.3 推理流程

- 冻结 reader 收到（查询 q，文本包 T，视觉页 V 图）作答。**单步推理**：MEMO 本身一次前向构建工作记忆、一次 reader 前向出答案，无 ReAct/反思循环；终止即产出答案。
- 两种预算设定：**严格 128-token**（text+visual tokens ≤ 128）与**无预算**（4096 执行窗口内不截断源记忆，无方法级上限）。

## 5. Benchmark 与实验设置

### 5.1 Benchmark 一览表

| Benchmark | GUI 场景 | 任务类型 | 数据规模 | 输入格式 | 输出格式 | 评测指标 |
|---|---|---|---|---|---|---|
| HotpotQA | General | 多跳文档问答 | 官方 dev set 预切分（非重叠验证/测试） | 文本段落 | 答案 | 归一化 EM / token 级 F1 |
| 2WikiMultiHopQA | General | 多跳文档问答 | 官方 dev set 预切分 | 文本段落 | 答案 | EM / F1 |
| LoCoMo | General | 长对话记忆问答 | 测试集含 2 个完全 held-out 对话 | 对话轮（说话人+时间戳） | 答案 | EM / F1 |
| ALFWorld | General | 具身轨迹下一动作预测 | 官方 valid_unseen 专家轨迹派生 | 任务+已保存轨迹状态 | 下一动作 | EM / F1 |

> 四任务统一 reader 输出格式与指标，可计算跨任务 Overall EM/F1。

### 5.2 实验结果分析

**主结果（128-token 严格预算）**：MEMO 在三个 reader 上 Overall EM/F1 全部第一。相对最强基线：InternVL3.5-8B 47.83 EM/59.82 F1（对 AgentOCR 40.53/52.60，**+7.30/+7.22**）；Qwen3-VL-32B 50.23/63.84（对 MemAgent 47.88/62.00，**+2.35/+1.84**）；gpt-5.4-mini 57.78/68.62（对 MemAgent 55.31/65.81，**+2.47/+2.81**），增益不依赖单一后端。多跳 QA 优势最明显：Qwen3-VL-32B 时 2Wiki F1 **73.91**（纯文本 56.26、纯图像 35.89）；gpt-5.4-mini 时 2Wiki F1 **80.06**。

**无预算设定（"省 token 不减质"）**：MEMO 平均只用 **83.93 tokens**，比 MemAgent 少 **50.5–50.7%**、比 Text-only 少 **66.9%**；Overall 在每个 reader 上第一或第二，最大落后仅 **0.43** 点。

**Ablation（gpt-5.4-mini，128-token）**：两组件全关 47.49 EM/57.24 F1、耗 126.22 tokens；只开抽取器升至 53.56/66.09、token 降到 70.12（**EM+6.07、F1+8.85、−44.4%**），说明"先筛相关证据"是压缩与提分主力；加管理器到 57.78/68.62、token 微升至 81.07（**再 +4.22/+2.53**），证明管理器不单纯省 token，而是花少量额外 token 换质量。全系统相对全关 **EM+10.29、F1+11.38 且省 35.8% token**，两模块贡献互补。

## 6. 亮点与贡献（Why it matters）

1. **问题边界重定义**：把记忆读出统一为"共享预算下查询条件化工作记忆构建"，选证据、分模态、排版收进同一可优化框架，为"多模态 reader 时代上下文放什么"给出系统化答案。
2. **效用导向的训练范式**：冻结 reader 反事实造标签，让"留什么、怎么呈现"对齐下游真实效用，是压缩任务里少见的 utility-driven 而非 cost-driven。
3. **可溯源证据单元**：保留出处/高亮/优先级，天然兼容 EverMemOS/MemoryOS 等结构化记忆系统的输出，可作为其上层"读方案层"。
4. **跨源与跨后端鲁棒性**：多跳文档、长对话、具身轨迹三类异构源 + 三个不同规模/家族的 reader 验证，结论不绑定特定后端。

## 7. 局限与可改进点（个人点评）

- **监督成本不低**：反事实标签需逐单元构造 4 种候选并逐一送冻结 reader 前向，而管理器仅贡献 +4.22 EM，收益比值得掂量；抽取器又依赖各 benchmark 原生证据标注或手工状态差分，冷启动到新领域不轻松。
- **"General"标签言过其实**：ALFWorld 上 MEMO 与 Text-only 几乎打平（EM 约 1.68 vs 1.37–1.90），LoCoMo 也非单项第一——当内容本就是紧凑文本、无强结构可借用时，视觉编排没有红利。结论宜限定在"信息密度高、含时序/表格结构"的记忆源。
- **组件与评测范围受限**：两模块仅 1.5B 基座，且训练 reader 与评测 reader 同属 InternVL 家族，跨家族泛化证据偏弱；"无预算"仍设 4096 窗口；渲染质量敏感性未报告；未开源使复现门槛偏高。

## 8. 对我们的启示 / 可借鉴点

通用启示：上下文管理不应是启发式截断，而应是一层**可学习、以"下游 reader 真实效用"为目标**的组件；一切压缩决策都应在统一预算下显式记账。

**对 GUI Agent 的可借鉴点**（Agent 方法论域，单列）：

GUI agent（计算机/手机操作）正是"多模态证据 + 长程轨迹"最典型的重灾区——每轮有截图、无障碍树/DOM、坐标与文本，历史动辄数百步。MEMO 给出四条可迁移思路：其一，把"截图/树/日志"切成**带出处的证据单元**（如一次"点击下载→弹窗→保存"即一单元），出错可按源回查，支持过程级诊断与反思；其二，对每单元做**载体分配**而非全量文本/全量截图——文件名、URL、金额等高保真项走文本锚，页面布局、弹窗层级等空间关系走图像，"哪些步骤留图、哪些留字"成为可学习决策；其三，把**上下文预算当第一公民**：截图 token 昂贵，用下游效用（而非 token 数）训练"是否贴这张截图"的策略，比启发式截屏节流更贴近目标；其四，**模板化排版**（时间线=操作历史、清单=状态、表格=表单值）可直接复用于 GUI 轨迹摘要页。对 RL 训练的 GUI agent，这套方法还可作观测预处理层，把原始截图史压成预算内证据包再喂策略，缓解观测过长导致的 RL 不稳定。

## 9. 延伸阅读

- **视觉记忆**：MemOCR（版式感知视觉记忆）、AgentOCR（光学自压缩轨迹图像）——最直接参照。
- **文本记忆**：Mem-α、MemRL、Agentic Memory、SimpleMem/LightMem。
- **结构化/生命周期记忆**：MemoryOS、EverMemOS、A-MEM、ES-Mem、MAGMA、SYNAPSE——MEMO 定位在其上的读方案层。
- **评测侧**：ALFWorld、LoCoMo 提供轨迹记忆评测范式；verl（Sheng et al., 2024）为微调框架。
