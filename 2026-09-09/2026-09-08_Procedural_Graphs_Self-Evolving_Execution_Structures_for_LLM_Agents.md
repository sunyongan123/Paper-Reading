# Procedural Graphs: Self-Evolving Execution Structures for LLM Agents

> 把任务的"该做什么"程序性知识组织成(流程, 关系, 流程)三元组的有向属性图，在线按进度取局部子图生成情境化引导，离线用"验证门控 + 拒绝记忆"自演化图的拓扑与属性——全程不改模型权重。

## 1. 研究背景与要解决的问题

长程任务的 LLM Agent 大多沿用 ReAct 式的自由生成：在一条不断变长的"动作—观测"历史之上直接决定下一步。这意味着"什么该做、按什么顺序、什么条件下能做"这套**程序性知识**完全压在自由文本生成上。轨迹一长，agent 就会跑题、乱序调用工具、反复做无用动作。现有改进大致分三类：文本记忆/反思（Reflexion、ExpeL）只存经验描述，仍要模型自己重建用法与前后约束；状态条件规则（AutoGuide）给出针对性提示，但没有把相邻步骤串起来；流程图/工作流/状态机（FlowBench、KnowAgent、AWM）把步骤显式化，却大多依赖人工设计，且不随经验自动修订。作者想补的缺口是：一种**既能显式编辑、又能按当前进度取用、还能从执行反馈中自我改进**的程序知识表示——于是提出 Procedural Graph（PG，程序图）。

## 2. 核心方法 / 思路

**总体类比**：知识图谱用 (实体, 关系, 实体) 三元组组织事实知识、回答"是什么"；PG 用 (流程, 关系, 流程) 三元组组织程序知识、回答"下一步做什么"。一个 PG 是有向带属性图 G=(V,R,E,Φ)：节点抽象工具动作、技能、推理步骤或任务状态；边 (u,r,v) 声明"u 之后在关系 r 下允许走到 v"，每条边挂三个文本属性——condition（何时可用）、guidance（怎么做）、pitfalls（要避免什么），关系词表仅四种：LEADS_TO、TRIGGERS、PROVIDES_INPUT_FOR、CONVERGES_TO。这样程序知识留在**模型权重之外**，可检查、可检索、可编辑而无需重训。

**在线推理（图冻结）三步走**：
1. **locate**：用"最近一次动作（如某次工具调用）"在图中匹配出当前活动节点 uₜ，匹配失败则退回整图；
2. **extract**：取出以 uₜ 为中心、向外扩展 ℎ=2 跳的局部子图（连带邻接条件与属性，而不是单独检索某条边——避免"光看到'提交'提示、看不到前置'检查'步骤"这种上下文割裂）；
3. **generate**：由引导模型 Ψ（与求解器同源 LLM）把该子图 + 最近 w=3 步轨迹翻译成一段"情境化引导"文本，追加进求解器 prompt。引导只"指明方向"不"代做决定"，求解器仍自由选动作——这是软的约束而非硬的状态机。

**离线自演化（每批训练任务后，图被修改，权重不动）**，四步闭环：
1. **诊断 rollout**：用当前图跑一批训练任务，记录轨迹与分数；
2. **反馈驱动变异**：LLM refiner 对比成功/失败轨迹，产出结构化编辑集 ΔG（add/delete 节点与边；改属性 = 删边再加边），输出严格 JSON；
3. **验证门控**：结构合法（端点存在、节点可达终止点、遵循环策略）的候选图在**独立验证集**上重跑打分，只有 S_val(candidate) ≥ S_val(当前图) 才提交，否则回滚——用泛化性能挡住"只在训练批上有效"的过拟合编辑；
4. **拒绝记忆**：被拒候选连同其轨迹与原因写入 H_rejected，下一轮喂给 refiner 作为负例，防止反复提同样的馊主意。

作者在附录还对比了 24 个方法 × 8 个设计维度，把 PG 定位在"结构化先行（结构化偏置）但推理仍自由、且支持拓扑与属性双重编辑"的空档。

## 3. 关键实验结果

**主实验（6 个基准 × 4 个 LLM：Claude Sonnet 4.6 / Gemini 3.1 Pro / Gemini 3.5 Flash / Grok 4.1 Fast，统一 ReAct 求解器）**：HotpotQA、MultiChallenge、GDPval、ALFWorld、τ-bench、BFCL v3。PG 在 24 个 模型×基准 设置中 21 个第一或并列第一；对最强基线 19 胜 2 平 3 负（符号检验 p=4.3×10⁻⁴）。最大领先出现在 BFCL v3 × Gemini 3.5 Flash（67.00% vs 58.00%，+9.00 点）、GDPval × Gemini 3.1 Pro（78.78 vs 71.37，+7.41）、τ-bench × Gemini 3.1 Pro（80.00% vs 73.04%，+6.96）。HotpotQA 上优势很小（相对最强基线 −0.90 ~ +1.30 点）。

**长程韧性（EnterpriseArena，最多 132 个月、含 3 次不公开的宏观危机）**：PG 把全程存活率从 44.0% 提到 58.0%（Claude Sonnet 4.6）、6.0%→34.0%（Gemini 3.1 Pro）、26.0%→40.0%（Grok 4.1 Fast，且平均企业分最优 $39.62M）；Flash 虽 0% 存活，但平均寿命 33.58→40.62 个月、平均融资 $0→$9.39M。关键行为是"提前融资"：引导下 agent 在平稳月就发起 1~6 个月后才到账的融资申请。

**构造策略（HotpotQA/MultiChallenge，Gemini 3.5 Flash）**：从零骨架 + 在线演化（Mode 5）在 HotpotQA 达 78.79% Ans F1 / 66.30 EM，较无图基线 +7.58/+7.50 点；MultiChallenge 上专家图初始化反而从 87.50% 掉到 58.93%，静态更新后更差（53.57%），而"专家图 + 在线演化"（Mode 3）回收到 92.86%（较专家初始 +33.93 点），证明循环能**修复劣质先验**。

**10 轮自演化（EnterpriseArena，Gemini 3.5 Flash）**：验证集存活率 0%→45%（Round 1，发现"先查现金/预测 runway 再融资"主链）→80%（Round 2 加 recall_notes）→90%（Round 8），期间多轮被拒并回滚；最终返回图测试存活率 85% vs 基线 0%（Fisher 精确检验 p=2.6×10⁻⁸）。工具调用从基线 17.23 次/月降到 3.08 次/月（−81.8%）。

**效率消融（Gemini 3.5 Flash）**：相比整图生成式引导，"局部子图 + 生成式引导"在 MultiChallenge/GDPval/ALFWorld 全部最优（89.31 / 63.99 / 81.53），比各自次优 +2.0/+6.8/+9.0 点；token 总量相对整图引导降 14.8%/18.1%/70.9%，求解步数在 GDPval 从 28.20 降到 18.57。代价是比"无图基线"总 token 仍高 33.4%~55.4%（引导本身是额外一次 LLM 调用）。

## 4. 亮点与贡献（Why it matters）

- **显式、可编辑、可改进的程序知识表示**：把"何时做什么、怎么做、别踩什么坑"结构化地放在模型外，天然支持审计与迭代，比把过程知识固化在权重里更可控。
- **按进度取局部子图再生成引导**：解决了"零散规则检索丢上下文"问题，兼顾结构化约束与推理自由度（"引导但不独裁"），还显著省 token。
- **带安全阀的自演化闭环**：验证门控 + 拒绝记忆 + 结构校验构成一套防过拟合、防退化、防重复提案的机制，这在同类"自改进 agent"工作里相当完整。
- **适用范围宽**：7 个基准覆盖搜索问答、多轮对话记忆、专业长文档、具身、策略合规工具用、函数调用与金融长程决策，且 4 个不同模型族一致受益。
- **"经验不落权重、外置可移植"的示范**：同一套图可在不同 solver/tool 间复用与迁移，训练成本为零（无梯度）。

## 5. 局限与可改进点（个人点评）

- **引导有恒定的 token/延迟税**：每步多一次 LLM 调用，即使局部化后总 token 仍比无图高 33%+；作者自己承认未来应跨步复用引导或选择性生成，这在在线产品里是现实瓶颈。
- **验证门控的成本与小样本噪声**：每个候选都要在独立验证集上重新 rollout；EnterpriseArena 每折仅 20 集，作者也承认单轮接受/拒绝往往取决于一两集，应视为搜索轨迹而非显著性结论。
- **编辑质量依赖 refiner 与结构校验器的天花板**：自演化是全提示驱动，refiner 幻觉会直接产生错误 JSON/错误边；拒绝记忆无限增长后，喂给 refiner 的负例可能稀释有效信号，未见压缩/剪枝策略。
- **迁移性未验证**：同一图跨 solver/工具接口复用的能力只在结论里作为 future work；引导文本可能隐性过拟合到训练所用的特定 LLM 的措辞习惯。
- **评测与 GUI 场景有距离**：全部为文本式工具/指令环境，无视觉 GUI、无截图；若搬到 GUI，还需要与 grounding（元素识别）结合，本文没有涉及观测噪声问题。
- **对部分场景收益不稳定**：HotpotQA 上增益接近噪声水平，ALFWorld/Grok 等个别格子 PG 并非最优，"稳定增益"更多体现在结构性强的长程任务上。

## 6. 对我们的启示 / 可借鉴点

- **"外置、可编辑的结构先验"非常契合 GUI 长任务**：GUI agent 失败模式（乱序操作、重复点击、跳过前置校验）正是 PG 想治的病。把"打开应用→登录→检索→填写→提交→等待结果"建成带 condition/guidance/pitfalls 的有向图，可以把大量流程常识从每轮 prompt 的隐式遵守中解放出来。
- **引导式而非硬约束**：GUI 页面状态千变万化，硬状态机易碎；PG 的"软引导 + 求解器自由决策"路线对我们做通用 GUI 策略是更稳的形态，可作为与 RL 并存的轻量模块先落地。
- **自演化 + 验证门控 = 可复现的经验沉淀机制**：我们项目若让 agent 从历史轨迹自举技能，最怕"越改越差"。借鉴其三步保险：只在独立验证集上不降分才提交、结构合法性校验、把被拒方案当负例喂回——是一套可直接抄的防回归设计。
- **局部检索优于整库注入**：对应我们 GUI 场景的观察压缩与记忆课题——按"当前进度节点"取 2 跳子图而非全量注入，既降 token 又保住步骤间依赖，值得在 GUI 观测序列上复刻。
- **成本结构要有心理预期**：引导的额外 LLM 调用与 token 增长是实打实的，设计时要评估"每步引导"还是"仅在易错状态引导"，或用更小的引导模型。

**对 GUI Agent 的可借鉴点：**

GUI Agent 的每一步本质上都可以表示成图节点——open_app、login、navigate、fill_form、click、submit、verify、wait_for_element——而页面级前置条件（某按钮可点前必须先有登录态、表单校验通过前不该提交）正好编码成带 condition/pitfalls 的边。若照搬 PG：先把某类 GUI 任务（如订票、企业软件操作）归纳成程序图，在线执行时用"上一步已完成的 UI 操作"定位当前节点，只把其后 1~2 跳的子图及其注意事项翻译成一句引导塞进 prompt，就能在不改模型权重、不动策略的情况下显著压低乱序/漏步/重复点击；这对我们项目里"少而准地注入上下文"和长程任务可靠性是低风险高回报的第一步。更进一层，GUI 环境天然适合做自演化：失败轨迹（报错弹窗、元素超时、提交被拒）与成功轨迹对比后，refiner 可自动增删/改写图与引导文本——例如发现"提交前必须等待 loading 消失"就自动加一条 verification 节点——再用小规模验证集门控防止技能漂移。由于图与权重解耦，同一张"任务程序图"可复用于不同底模（如我们评测中换用不同 GUI 基座模型），无需重新训练。若要升级为长期方案，还可把 PG 作为先验/动作约束与 Online RL 结合：先由图保证流程合法性，再用 RL 优化具体交互细节（点击目标选择、输入内容），并让 RL 学到的成功模式反向驱动图更新——这与我们项目关注的 Grounding 与在线自改进方向都能咬合。注意点：GUI 引入的观测误差（截图解析、元素定位偏差）会使"活动节点匹配"失败率上升，落地时需给匹配失败提供可靠的全图回退与重定位策略。

## 7. 延伸阅读

- KnowAgent（Zhu et al., 2025）：文本式动作转移规则的先验约束，同方向最早一批。
- AutoGuide（Fu et al., 2024）：状态条件规则生成与选择，与 PG 最接近的基线。
- AWM（Wang et al., 2025b）与 FlowBench：线性工作流 / 流程图式过程先验。
- ExpeL、Reflexion、MemoryBank：对比式经验提炼与文本记忆家族。
- AFlow（Zhang et al., 2025）：用 MCTS 自动搜索工作流图。
- SE-Agent、SkillWeaver、WebXSkill、Voyager：计算机/网页/沙盒场景的技能自改进代表，可对照"经验外置"路线在 GUI 的可行性。
- MemP、ToolNet、SkillGraph：程序记忆生命周期、工具转移图、多智能体技能图。
