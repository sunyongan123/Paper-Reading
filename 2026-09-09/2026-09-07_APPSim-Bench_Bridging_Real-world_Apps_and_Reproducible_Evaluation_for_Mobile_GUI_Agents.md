## 1. 研究背景与要解决的问题

移动 GUI 智能体能听懂自然语言指令并像人一样"看屏幕、点按钮、滑输入"地操作手机，是 VLM 落地的重要方向。要评判这类"手机管家"，评测既要贴近真实生活又要环境稳定，两者天然冲突。早期基准以"动作轨迹是否匹配人工标注"判成败，但真实 App 常"条条大路通罗马"，路径比对会误杀合法操作；动态基准（AndroidWorld）改为看最终状态、解决了多路径问题，却只覆盖系统或开源 App，与日常第三方服务差距大；真机跑商业 App 的方案（SPA-BENCH、LlamaTouch）够真实，却因推荐、广告、账号与动态内容，令同一任务在不同时间/设备上呈现不同状态（Fig.1a），破坏可复现与公平比较。既有工作一直要在"真实"和"可复现"间二选一，这正是本文要补的缺口。

## 2. 核心方法 / 思路

整体是"把真实高频交互搬进可控沙盒"的三件套框架：任务层 + 模拟 App 层 + 自动化评测层。

- **任务层**：先由 15 名志愿者产出真实交互，经人工整理成 557 个自然语言任务，分布在 17 个模拟 App（中文生态 283 个：微信、京东、小红书、腾讯会议、高德、携程、B 站、饿了么、网易云音乐；英文生态 274 个：Amazon、Instagram、Spotify、Uber Eats、YouTube、Booking.com、WhatsApp、Zoom）。按参考步数划分：≤5 步 282 个、6–10 步 140 个、≥11 步 135 个；另含 183 个数值推理任务，细分计数/算术/比较/阈值过滤四类。
- **模拟 App 层**："人主导、编码 Agent 辅助"流水线——人给出任务需求、后端 schema、页面层级与代表截图，Agent 生成候选实现，人再检查、执行、迭代纠错。只保留任务相关页面与数据、用可控后端替换真实服务，每次从确定初始状态开始、可重置，剔除个性化、广告、网络波动等随机源，运行于原生 Android。
- **评测层**：沿用 AndroidWorld 的"结果验证"而非路径比对——任务结束后检查**可见或后端状态是否达成目标**，分 State（消息已发/订单已下）、Answer（返回数量、价格等结构化答案）、Hybrid 三类；并把基准规格、参考执行、官方打分分离以支持确定性判分。类比：不比"解题步骤"，只查"账目结果"。

与 AppWorld 的区别在于范式：后者靠 agent 写代码调 457 个 API（测程序综合）；AppSim-Bench 坚持 GUI agent 在像素上 tap/swipe/type 的视觉 grounding 与界面导航范式，两者探针能力正交。

## 3. 关键实验结果

共 19 个 agent（15 通用：GPT/Claude/Gemini/Qwen/Doubao 家族，商用模型用单模型版 M3A 适配；4 个 GUI 特化：MobileAgent-v3.5、UI-TARS-1.5-7B、AgentCPM-GUI、V-Droid）。协议：Android 13、1080×1920、温度 0、50 步上限、二元 ACC。

- **天花板低**：最强 Claude-Opus-4.7 仅 **50.27%**，Gemini-3-Pro 49.91%、GPT-5.5 49.73%。GUI 特化未能补差——最强 MobileAgent-v3.5 只有 31.42%，其余 <23%（V-Droid 仅 9.87%），说明瓶颈在任务本身。**28.55% 任务（159/557）无任何模型解出**，仅 0.36%（2 个）被 19 家全解出——失败是系统性盲区。
- **生态差异大**：头部模型中文 App 约 59–60%，英文 App 掉到 39–41%。
- **越长越差**：所有模型精度随参考步数单调降（GPT-5：43.62→31.43→14.07%）；≥11 步档最佳仅 33.33%，特化模型在该档近乎归零（0.00%/0.74%）。
- **数值推理败在"推理"**：算术 GPT-5.5 最高 57.78%；阈值过滤最难，Opus-4.7 的 42.86% 已居首，多数模型 <15%。人工审计 1,287 步仅 1 处感知/抽取错。
- **低分伴随原地打转**：准确率与平均动作数（Pearson −0.669）、Action Overhead（−0.458）、预算耗尽数（−0.705）负相关；2,036 条预算耗尽轨迹成功率仅 0.44%，其中 83% 含 ≥3 次连续重复动作。
- **视觉保真受控**：静态截图 46.3% 判"无法区分"、19.0% 认假为真；动态序列 35.7% 无法区分、15.2% 认假为真。

## 4. 亮点与贡献（Why it matters）

- 首次系统弥合"真实 vs 可复现"：可控可重置模拟环境 + 确定性结果验证，把商业 App 级任务变成可复现评测。
- 双语生态：同时覆盖中英文 17 个高频 App、557 任务，并含专门数值推理子集。
- 构造流程可复制：spec → 编码 Agent 生成 → 人工校验 → 仪器化，摊薄人工、易扩展新 App。
- 大规模同协议横评：19 个通用/特化模型的可比数据，把共同短板定位到长程工作流、数值约束、低效轨迹三类能力。
- 质量证据链较完整：视觉盲评、剪枝残余上界（≤4.28%）、错误分解审计，增强基准可信度。

## 5. 局限与可改进点（个人点评）

- 仿真是有损"温室"：只留任务相关页面、剥掉广告/个性化/网络等，测的是理想界面下的确定性执行，不代表真实部署的抗扰能力。
- 后端数据人工/合成，缺真实账户历史与长尾分布，相关任务可能被系统性低估难度。
- 协议较单一：温度 0 + 单次运行 + 50 步上限 + 二元结果，未报告运行方差；把"预算耗尽"当失败代理，对状态变化下的合法重复动作偏保守。
- 质控深度有限：错误分解只审单个 App，跨生态未确认；动态序列"认假为真"仅 15.2%，模拟仍可辨。
- 规模相对长尾仍小：每 App 平均约 33 任务，跨 App 长流程、实时交互、无障碍与安全敏感场景未覆盖。

## 6. 对我们的启示 / 可借鉴点

- 评测工程范本：高频真实场景搬进可控环境 + 结果验证 + 三层分离，可复用；其对随机源（推荐/广告/账号/动态内容）的清单化管理尤其值得抄。
- 给 Online RL 廉价信号：准确率与动作开销、预算耗尽、连续重复强负相关，这些免标注的轨迹统计可作 reward shaping 或"死循环终止/恢复"检测特征。
- 造环境流水线可迁移："人给规格、编码 Agent 生成、人校验"可低成本扩展新 App/生态，产出沙盒可直接当 SFT/RL 环境。
- 能力短板即方向：长程状态追踪、界面上的阈值过滤式数值约束、卡壳恢复，是 19 家共同盲点，正对应 RL/长程建模的落点。
- 评测须分层：中英 60% vs 40% 提示按语言/平台分组报告，避免混合均值误导。
